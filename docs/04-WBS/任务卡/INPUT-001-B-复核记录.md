| 审查要求 | v2 是否满足 | 证据 |

| 精确触发条件 | ✅ | §R4-3.3：`containsInputNode(n.For.Children)`，**不论是否有 Key**；覆盖间接子树与嵌套 For |
| 诊断消息 | ✅ | §R4-3.4 英文消息 + 中文文档附注 |
| 测试位置与正负例 | ✅ | §R4-3.5 表：Parser 正/负例、diagdoc 一致性、CLI 端到端 |
| Codegen 兜底定位 | ✅ | §R4-3.6：保留为防御层，正常不可达（与缺 Key 的既有实践一致） |

**重要实证（复核中补做）**：
```
有 Key + Input 的 For: 诊断数 = 0        ← v1 规则下放行，必须新增拒绝
无 Key + Input 的 For: GXML-SCOPE-003    ← 已有规则先命中
```
这确认了两条规则**不重叠**：SCOPE-003 管缺 Key，SCOPE-005 管 v1 不支持。
两者同时满足时（无 Key + Input），按"先命中者报"——SCOPE-003 优先，
不叠加两条诊断（v2 §R4-3.5 已写明）。

**结论：通过。**
