        break

        t.Fatalf("确定处于到达前的第 %d 帧发生了替换：替换不是由状态驱动的", before)

#### 6.3.1 原 N2 为什么自锁（静态推演，逐步）

原变异＝删除 `:721` 的 `if lz.State() == theme.LoadReady { break }`。

1. 删除后循环不再在 Ready 时退出；
2. 到达后的第一次迭代（或在一次 `straddle` 之后的第一次迭代）中，`pre == post == Ready`；
3. 该次迭代执行 `a.frame` ⇒ `swapPending` ⇒ `lz.Take()` 完成替换 ⇒ `MarkFrameSubmitted`
   （`app.go:413-417`）⇒ `FrameSubmittedAt` 非零；
4. 于是 `:731` 的 `else if !lz.Report().FrameSubmittedAt.IsZero()` **成立**
   ⇒ `t.Fatalf("确定处于到达前的第 %d 帧发生了替换…")` 在约 **1–2 ms** 触发。

⇒ 实际结果是：耗时 **< 1 s**（不在 `[14s,20s]`）、失败原文出自 `:731-733`（**不是**「墙钟预算…耗尽」）
⇒ 与判据②③直接冲突 ⇒ 按 A6「任一项缺失即 N 不成立」判 **N2 不成立**。
**这不是"证据不足"，而是"判据不可达"**：循环之所以不会在到达后继续断言，恰恰**依赖循环顶部的 break**。
因此"删 break"这一变异**不可能**产生"跑满 15 s 后墙钟耗尽"的观测。

#### 6.3.4 为什么首选 B1；以及选 A 时必须写明的限定

- **B1 的理由**：① **输入替换不改断言**——被测的等待/归因逻辑**原样运行**，N2 检验的正是这段逻辑；
  ② 只引入 **1 个**变化因素（到达与否），符合"一次只变一件事"；
  ③ 与 N3a/N3b 职责**不重叠**（后者检验 `:731-733`，本条只检验循环退出条件）；
  ④ 恢复只需还原一行，残留风险最低；
  ⑤ 其失败路径 `LoadFailed` 由 `lazy.go:373-378` 保证 `pending=nil`、**不写** `LoadedAt`
     ⇒ `FrameSubmittedAt` 不可能非零 ⇒ 不会污染 `:731` 的判定。
- **若改用 A 必须写明**（不得默认省略）：A 的变异**临时禁用了 `:731-733`**，
  因此它**不是**"对完整修复后代码的验证"，而是**在隔离该断言的前提下**验证"循环退出条件只剩墙钟"。
  其证明范围必须**收窄表述**为「循环不再因帧数提前退出」；
  `:731-733` 的有效性**仍由 N3a/N3b 独立证明**，**不得**用 A 的结果冒充对该断言的覆盖。
  若 A 与 B1/B2 都不可行 ⇒ **N2 记为"未验证"**，按 A6 判 N2 不成立，并在验收报告中写明原因，
