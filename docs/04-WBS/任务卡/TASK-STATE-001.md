# TASK-STATE-001：状态更新与 UI 自动刷新

## 元信息

- 状态：**S0 核查进行中** | 优先级：P0
- 依赖：绑定链路已闭环（`76dfedf` 为稳定基线）
- 历史说明：本任务卡旧版把「AOT 浅对比 Diff + MacroOp 局部失效」当作既定目标。
  现按当前路线**重定义**：AOT Diff 降级为 S5 的**评估项**，
  由 S0–S4 的测量结果决定是否需要——**不预设**。

## 最终目标（限定）

> ViewModel 状态变化后，UI 能在**正确的生命周期内**获得更新机会，
> 并在后续布局中显示最新值；现有静态缓存、绑定显示缓存与错误处理规则**均不退化**。

## 1. 子阶段拆分

| 子阶段 | 目标 | 关键验收 |
|---|---|---|
| **S0** 现状与依赖核查 | 查清事件循环、Invalidate 使用点、App/Runtime 辐界 | 证据清单，**不改代码** |
| S1 状态更新契约 | 定义状态修改、失效通知、布局读取、错误边界 | 通知与重绘不混为一谈 |
| S2 最小通知机制 | 状态修改后能通知 UI | 更新请求触发后续布局 |
| S3 端到端自动刷新 | **真实 App 生命周期**中自动显示新值 | 不再依赖测试显式调用 `Layout` |
| S4 缓存与回归 | 静态缓存、绑定缓存、状态更新协同 | 值变化正确失效；稳定值零分配不退化 |
| S5 架构评估 | 是否需要 AOT Diff / Deps / 细粒度失效 | **以测量结果决定** |

**S2 ≠ S3**：能发出失效通知 ≠ 生产 UI 自动刷新。
最终必须在**实际 App 事件循环**中验证完整链路。

## 2. S0 必须回答的四个问题

| # | 问题 | 核查点 |
