## 3. 冻结的状态维度

**不使用单一「完成/未完成」字段。**每个 TASK 分别记录：

| 维度 | 取值 | 要回答的问题 |
|---|---|---|
| 生命周期 | 待办 / 进行中 / 阻塞 / 关闭 | 任务管理状态（**不能代替下面几项**） |
| 实现状态 | 未开始 / 进行中 / 已实现 / 部分实现 / 不适用 | 代码或文档交付物实际做到哪一步 |
| 验收状态 | 未执行 / 通过 / 部分通过 / 失败 / 受阻 | 规定的验收条件是否真正验证 |
| 证据状态 | 完整 / 不足 / 过期 / 无法获取 | 结论能否被别人独立复核 |
| 文档状态 | 一致 / 滞后 / 冲突 / 缺失 | WBS、任务卡、契约和实现是否一致 |
| 平台状态 | 未测 / Windows / Linux / macOS / CI（分别记录） | 实际在哪些环境验证过 |

## 4. 冻结的判定矩阵

| 证据情况 | 实现状态 | 验收状态 | 总账处理 |
|---|---|---|---|
| 没有对应实现，且未开始 | 未开始 | 未执行 | 保留待办 |
| 有部分代码，仍缺关键功能 | 部分实现 | 部分通过或未执行 | 拆出剩余任务 |
| 代码已实现，规定测试未运行 | 已实现 | 未执行 | **不允许关闭** |
| 自动化测试通过，人工验收未做 | 已实现 | 部分通过 | 明确保留人工验收项 |
| 测试只有结构断言，未验证真实行为 | 依证据填写 | 未充分验证 | 不得用结构测试代替行为验收 |
| 退出码 0，但测试全被跳过或没有匹配测试 | 不据此判定 | 未执行 | 标记**测试空转**或证据不足 |
| 测试失败且能复现 | 依证据填写 | 失败 | 建立 BUG 或整改任务 |
| 环境缺失、访问被拒、平台不可用 | 依证据填写 | **受阻** | 写明阻塞原因与解除条件 |
| 代码与验收都通过，证据完整，文档一致 | 已实现 | 通过 | 满足关闭条件后才可关闭 |
| 旧提交通过，当前基线尚未复验 | 依**当前**代码证据填写 | 证据过期或待复验 | **不得**把旧证据当当前通过 |

> **「已实现」≠「可关闭」**。编译器框架的一个任务往往同时包含实现、错误语义、边界行为、
> 测试、文档同步与集成验收；缺任何一项明确要求，都不得通过改标题或缩小解释范围来消掉。

## 5. 核心纪律（审计期间一律适用）

1. 契约已冻结 ≠ 实现完成。
2. 单元测试通过 ≠ 端到端或真实窗口验收通过。
3. `go test` 退出码 0 ≠ 所有测试 PASS；必须确认实际命中的测试、PASS、SKIP 与未执行项。
4. 无运行环境 / 无权限 / 无法复现 → 记「受阻 / 无法验证」，**不得计为通过**。
5. 部分子任务通过 ≠ 父任务整体通过。
6. 提交存在 ≠ 功能已验收；代码存在 ≠ 代码被生产路径调用。
7. 状态必须绑定**证据与基线提交**，不能只留「已测」「已完成」这类文字。

## 7. 统计口径（防止虚高）

同时输出三个率，并**分别**统计阻塞、部分实现、未执行验收、未登记任务：

- 任务关闭率 = 满足约定关闭条件的任务数 / 纳入统计的任务总数
- 验收通过率 = 已完成规定验收且通过的任务数 / 纳入统计的任务总数
- 证据完整率 = 证据完整、可定位、与当前基线匹配的任务数 / 纳入统计的任务总数

**父子不重复计数**：主统计以**最底层可验收交付项**为单位；父任务状态由子任务 +
父级独立验收条件推导；确有独立父级验收要求的再单独统计。
