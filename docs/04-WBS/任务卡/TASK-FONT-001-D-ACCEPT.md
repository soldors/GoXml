## 2. 四个指标必须分四行报（R3）

验收报告里**必须**是这样一张表，四行缺一不可，**不得**出现"总耗时"：

| 指标 | 定义 | 实测 | 判定口径 |
|---|---|---|---|
| M1 首帧预算 | 进程启动 → 首帧处理开始（含 `TempElapsed` 这段**有界同步成本**） | 待实测 | 实测后定阈值 |
| M2 探测段 | `Report.ProbeElapsed`（仅 `probe()` 候选循环） | 待实测 | **只记录，不设通过阈值** |
| M3 后台总量 | `Report.LoadElapsed`（`RequestedAt→CompletedAt` 墙钟，成功/失败都记） | 待实测 | 只记录；与 M2 的差即补链/兜底/主题构造余量 |
| M4 切换后首次排版 | `Report.FirstLayoutAfterSwap` | 待实测 | 实测后定阈值 |

> **填表前置**：M2（`ProbeElapsed`）与 M3（`LoadElapsed`）的**语义**须先由
> `D-ACCEPT-07` 确立。在确立之前，M2 的"实测"格只能标注「**未验证**」并注明
> 「Provider 状态未定」，**不得**填数后直接判定；
> 「`LoadElapsed - ProbeElapsed` = 补链/兜底/主题构造余量」这一推论同样依赖
> 两者同源，缓存命中时不成立。

**M2 为什么没有通过阈值（评审阻塞点 3 的结论，不要再改回去）**：

- 规范 §3.2 的 20 ms 是**冷启动内加载耗时的预算**，原文括号写明
  「懒加载时应 ≤ 首帧 budget」——D 的职责是**移出首帧**，不是压到 20 ms；
- 实测 `ResolveWithReport` 冷启 **97–109 ms**，是 **A/B/C 阶段就存在的既有缺口**，
  不是 D 引入的；把 20 ms 当本卡通过条件，等于让 D 去还 A/B/C 的债。
  **但 97–109 ms 不是 M2 的实测值**——它测的是 `ResolveWithReport` 整段，
  不能填进 §2 的"M2 实测"格，也不能拿来跟 20 ms 直接比；
- `ResolveWithReport` 区间还含 `supplement`（C 卡补链）与嵌入兜底，
  与"探测"不是一回事；而 `probe()` 内部把读文件/解析/覆盖判定混在同一循环，
  **现有 API 无法分离解析耗时**（详见 IMPL-1 §6）。
- 真要 ≤20 ms，需要候选优化（Provider 层缓存/并行探测/预解析缓存），
  **独立待办**，本轮不承诺。报告里必须写清这一点，不得用"异步已达标"含糊过去。

**M1 阈值的定法（D 卡 §9-1 强制）**：先测"完全不加载字体的最小窗口"首帧耗时作基线，
再测懒加载路径首帧耗时，两者同量级即可接受；**不得**先写一个数字再去找数据。
首帧预算必须在**同一个探针**里用同一种计时方式取，不得跨探针拼数。

#### 语义裁决（**已冻结**，负责人 2026-10-23）

> **选择「本轮探测耗时」语义。缓存命中时必须明确表示本轮没有执行探测，
> 不得把历史耗时伪装成本轮耗时。**
>
> 理由：`ProbeElapsed` 在 `LoadReport` 里是**单次加载的诊断指标**；
> 若它可能来自另一次加载，上层诊断、耗时比较与后续性能验收都要额外
> 了解 Provider 的历史缓存状态才能解释。优先让指标忠实表达**本轮事实**。

**冻结的语义契约**：

| 场景 | `ProbeElapsed` 语义 | 验收要求 |
|---|---|---|
| 本轮执行了探测 | 本轮**实际**探测耗时 | 由注入时钟验证 |
| 成功缓存命中，未执行探测 | 本轮无探测耗时，返回 **`0`** | **不得**沿用历史耗时 |
| 探测失败并再次尝试 | 每次记录**本轮**实际探测耗时 | 不得复用上一次失败的耗时 |
| 嵌入兜底成功并写入缓存 | 按**实际执行路径**判断 | 首次执行与后续缓存命中**分别**验证 |

**三条明确限制（不得含混）**：

1. **`ProbeElapsed == 0` 不代表加载耗时为零，也不代表加载失败**——
   它只表示**本轮没有记录到探测耗时**。消费方不得据 0 反推任何结论。
2. 若将来需要区分「缓存命中」「没有探测」「计时不可用」，**必须**通过
   **明确的状态字段或报告结构**表达，**不得**靠耗时数字猜测。
3. `LoadElapsed >= ProbeElapsed` **不是无条件契约**：只能在两者**计时口径相同**
   且**本轮确实执行了探测**的前提下使用；即使满足，也要确认二者的**计时区间关系**，
   不能把不等式当公理。

#### A 阶段取证结果（2026-10-23，确定性注入时钟，**已实证**）

方法要点：`ProviderOptions.Now` 可注入 → 虚拟时钟每次调用前进固定步长，

##### （16）验收条款变更治理规则（负责人 2026-10-24 下达，**自本卡起生效**）

4. **结论强度必须与证据匹配**：

> **这个"批次间差异"本身是证据**：若根因是机器负载或环境波动，失败率应相对稳定；

**根因四分类判定**

| 类别 | 判定 | 依据 |
|---|---|---|
| 生产逻辑错误 | **否** | 三个时刻均正确写入；`LoadElapsed = CompletedAt - RequestedAt` 计算正确；命中缓存后加载本就应该快 |
