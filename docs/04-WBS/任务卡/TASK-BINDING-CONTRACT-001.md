## 1. 为什么拆成两步

绑定系统涉及**三个相互关联但不能混为一谈的问题**：

| 问题 | 不等价于 |
|---|---|
| 绑定值能正确更新 | 文本 shaping 已避免重复计算 |
| 用 `op.InvalidateOp` 触发重绘 | 需要 AOT Diff |
| 静态子树可以固化 | 动态节点可以套用同一套缓存策略 |

先核查、后契约，避免：
- 把已有的 `BindingVal` / `Facts` / Analyzer 能力重新设计一遍；
- 在更新机制尚未明确时过早引入 AOT Diff。

## 2. 核查规则

1. **以当前代码与已冻结文档为据**，不从旧任务名推断实现状态。
2. 区分四态：**已实现** / **有接口但未接通** / **只有文档定义** / **尚未实现**。
3. `BIND-*` 诊断码逐一核对**实际触发位置**，不仅检查常量是否存在。
4. 对并发提交或其他会话的修改，只记录核查结果，不擅自覆盖。
5. **核查结束前不改生产代码，不提前创建公共接口。**

## 3. 六项核查清单

| # | 核查项 | 需要查明的事实 |
|---|---|---|
| 1 | `BindingVal` | 定义位置、字段、类型信息、当前用途、谁负责构造 |

| 6 | 性能契约 | `INV-PERF-4`、ADR-0001、契约 §16 各约束了什么 |

## 3.1 第二阶段决策（已冻结）

### 决策 1：绑定契约是否定义状态机制

**定义与绑定直接相关的最小语义，不定义完整状态机制。**

| 能力 | 本契约 | `TASK-STATE-001` |
|---|---|---|
| 读取当前绑定值 | 定义 | 遵守 |
| 类型/安全性/失败行为 | 定义 | 遵守 |
| 值变化判定 | 定义语义与责任边界 | 可提供实现机制 |
| 变化后更新显示 | 定义可观察行为 | 实现更新流程 |
| 通知失效/触发重绘 | **不冻结接口** | 定义与实现 |
| 是否 AOT Diff | **不作决定** | 评估与验证 |
| 细粒度依赖失效 | **不默认要求** | 按性能需求决定 |
| shaping 缓存规则 | 定义结果要求与边界 | 配合实现 |

**关键区别：绑定值比较 ≠ AOT Diff。** 前者是 `INV-PERF-4` 的直接需求，
后者是可选架构方案。二者不绑在一起冻结。

### 决策 2：`INV-PERF-4` 的责任主体

分三层：绑定读取层 / 绑定缓存层 / 状态更新层。详见契约 §03.1。

即使没有 AOT Diff，也可通过可控测试驱动验证读取层与缓存层。
但不能声称整条运行链路已满足要求——完整链路待 `TASK-STATE-001`。

### 决策 3：`BindingVal` 是否增加类型字段

**不增加。** 类型已由 Analyzer 产出并集中存于 `Facts`；
`BindingVal` 是 Parser 产物，Parser 阶段无类型信息。
重复存储会造成第二份事实，违反单一事实来源。

### 补充冻结：01–05 的留白边界

| 章节 | 冻结 | 不冻结 |
|---|---|---|
| 01 表达式 | `{Path}` 语法、路径语义、取反规则 | 复杂表达式（v1 禁止） |
| 02 类型 | `TypeInfo → PropType`、传递路径 | 不必要的 `BindingVal` 类型字段 |
| 03 状态更新 | 读取语义、变化判定责任、可观察行为 | 通知 API、AOT Diff、细粒度失效实现 |
| 04 代码生成 | `Facts` 驱动生成、读取接口、失败处理 | 未验证的生成模板 |
| 05 缓存性能 | 动态边界、三层缓存责任、验收方法 | 未测量的优化细节 |

### 一个核查发现（影响 05）

**Gio 的 shaping 无法直接计数**：`text.Shaper` 缓存字段未导出，
shaping 由 `widget.Selectable.Layout` 内部驱动，注入 `Shaper` 观测未成功。

因此契约要求：实现阶段**先设计可替换的测试 seam**；
是否引入生产接口**待实现阶段决定**，契约不预设。

## 4. 本阶段明确不做

- 不引入状态管理或 AOT Diff
- 不修改契约 §16
- 不创建新的公共接口
