## 7. S2 实施结果（2026-10-19）

### ① 统一接口已实现

| 页面 | 构造 | Layout |
|---|---|---|
| 静态 | `NewXxxView()`（不变） | `Layout(gtx, th)` |
| 绑定 | `NewXxxView(vm *T) (*X, error)` | `Layout(gtx, th)` |

取值根改为 `v.vm`（View 持有引用）；构造期 nil 明确拒绝。

**过程中抓到并修复**：绑定页面缺 `fmt` import（构造函数用 `fmt.Errorf`）；
旧测试残留三参调用与错位构造——机械替换产生混乱后改为手工清理。

### ② nil 失败形式（按仓库惯例决策）

核查发现：`NewTypeEnv(...) (*TypeEnv, error)` 是 error 先例；
`panic` 仅用于内部不变式破坏（Facts freeze）。

**决策：返回 error**。nil vm 是调用方输入错误（可恢复），
非内部不变式破坏。已写入契约与生成注释。

### ③ Runtime 失效入口

新增 `Invalidator` 接口 + `RunWindowWithInvalidator(..., inv func(Invalidator))`：
- 只交付失效入口，不修改状态、不感知 vm；
- 失败形式与现有签名兼容（RunWindow 内部转发，4 处测试调用不破坏）；
- 不引入事件系统，不违反依赖红线。

### ④ 真实窗口端到端（非 headless 冒充）

```text
首帧 AAAA（帧数=1）→ 改 vm + Invalidate → 帧数 1→2 显示 WWWWWWWW
连续更新 [BBBB CCCCCC DD] 全部按序显示（帧数=4）
```

证据设计区分两件事：
- `frames` 计数 → 确实出现**后续新帧**（不是只调了 Invalidate）
- `observed` 记录 → 新帧**读到了新值**（不是跑了布局但值没变）

测试用 mutex 同步 vm（演示调用方同步责任）；
无图形环境自动 Skip 并记录，不以离屏冒充。

### 回归

静态缓存（TestStaticPageStillFreezes）与绑定缓存五场景（TestB3Scene1-5）
全部通过；codegen 90.1%、app 94.1%。
