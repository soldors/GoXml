## 1. ① 冻结场景 ③ 规则（开工前必须）

### 冻结文本

> 当原始绑定值发生变化，但经显示转换后得到的显示字符串与之前**完全相同**时，
> **允许**复用此前的 shaping 结果；前提是所有影响 shaping 结果的输入与
> 环境条件均未变化。

要点：

- 是**允许**，不是强制——实现可按收益与复杂度决定是否采用；
- **显示字符串相同 ≠ 所有 shaping 输入相同**（字体/方向/约束变了仍须失效）；
- **原始值比较不是必要前提**——复用依据是显示字符串与实际 shaping 输入的有效性，
  原始值变化只作为测试维度。

### 复用条件表

| 条件 | 是否允许复用 |
|---|---|
| 原始值不变，显示串不变，shaping 输入未变 | 允许 |
| 原始值变化，显示串相同，shaping 输入未变 | 允许 |
| 显示串变化 | 不允许 |
| 字体/方向/影响排版的约束变化 | 必须失效 |
| 主题变化但最终 shaping 输入不变 | 先判断主题是否影响实际输入，**不应仅凭主题对象变化就重 shaping** |
| 显示转换失败 | 按失败契约处理，不得用旧结果掩盖失败 |

## 3. ③ 当前缓存实现（三层状态）

| 层 | 缓存内容 | 失效依据 |
|---|---|---|
| 值读取层 | 每次 Layout 读取当前静态类型表达式 | 已实现；自动刷新仍归 `TASK-STATE-001` |
| 显示/绘制回放层 | 每个绑定 `<Text>` 独立槽位；显示串与 `renderKey` 相同则回放 `CallOp`，否则重录 | 已实现；行为测试通过所测范围 |
| Gio shaping 层 | Gio 文本后端内部的 shaping/layout 缓存 | 未直接观测；不声称命中或减少次数 |

**shaping 层不预设由本项目维护**：Gio 内部已有缓存（`layoutCache` 等），
应**先测量再决定**是否加项目层缓存，避免双重缓存。

含绑定页面继续不生成整页静态缓存。绑定文本的节点级 `CallOp` 是独立槽位，
不能等同于动态父容器中的局部静态子树固化。

### ② seam 评估结论（未加生产接口）

按优先级实测：

| 方案 | 结果 |
|---|---|
| 1 注入 Shaper 替身 | ❌ 不可行——`text.Shaper` 是具体类型非接口（步骤 2 已证） |
| 2 项目层显示边界观测 | ✅ **采用**——观测点 = 槽位状态（`valid`/`text`/`call`）+ 渲染像素 |
| 3 新增生产接口 | **不需要**，未引入 |

按验收底线如实定性：

- 可证明：所测输入下的 CallOp 回放/失效与渲染正确性（像素）；
- **不可证明**：文本布局入口实际调用计数、Gio 内部 shaping 是否命中（`layoutCache` 未导出）。

### ③ 缓存实现（前两层）

生成代码新增 `textCache` 槽位 + `bindText` 方法：

- 键 = `renderKey` + 显示字符串；
- 显示串与上下文未变 → 回放（不再调用文本布局入口）；
- 变化 → 在**槽位私有 Ops** 上重录。

**一个设计错误被 ADR-0009 的实测结论拦下**：初稿让多槽共享一个 `Ops`——
但 `Reset` 会使所有指向它的 `CallOp` 失效（panic）。已改为每槽私有。

shaping 层：Gio 内部已有 `layoutCache`，实测同文本 590.9 vs 换文本 750.2 ns/op
（差异仅 ~27%，收益有限），**项目层不加第二份缓存**。

### 稳定帧性能（如实记录）

历史提交样本：

```text
ns/op=140  B/op=0  allocs/op=0
```

环境：Windows amd64 / Go 1.26.1 / Gio v0.10.3 / CGO_ENABLED=0 / 20P；
预热：先显式 Layout 一次触发录制；测量区间：预热后连续 N 次 Layout。
当次探测记录的无缓存对照为 688.9 ns/op；该值是同一历史测试时点的结果，不等于本报告复测值。
最新复测数据与口径见 [`绑定显示缓存验收报告.md`](../../06-测试/绑定显示缓存验收报告.md)。

注：绑定命中（140ns）比静态整页命中（29ns）慢，因为绑定路径每帧仍需
读值、比较显示串、逐槽回放——这是动态性的必要成本，不是缺陷。
