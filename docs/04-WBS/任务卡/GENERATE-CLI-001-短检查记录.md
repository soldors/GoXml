## 6. G2/G6/G7 决策冻结（2026-10-20，1-2 开工前）

### G2：SourceDir 语义

**冻结**：`SourceDir` 是**单文件解析上下文**，不是 CLI 公共根目录。

- 每个 `.gxml` 的解析目录 = 该文件实际所在目录（与 Analyzer 现有语义一致：
  「同包 ViewModel 解析需要与源文件所在 Go 包上下文一致」）；
- 输入路径先规范化，多子目录的 `.gxml` 各按各自目录解析；
- 相对输出基准（契约 §3.2）与源解析目录**不混用**；
- 现有 `pipeline.Config.SourceDir` 字段语义与该冻结一致（注释已写明
  「.gxml 所在目录」），**不需要改 Analyzer**——只需 CLI 侧保证按文件传值。

### G6：--check 承诺边界

**冻结**：分层检查，1-2 只承诺前两层，`--check` 参数**接收但不实现**。

| 层 | 职责 | 状态 |
|---|---|---|
| L1 | Parser/Expander/Analyzer（语法/展开/语义） | 1-2 承诺（generate 默认就做） |
| L2 | Codegen 成功 + 产物可被 `format.Source` 解析 | 1-2 承诺（Pipeline 已内置） |
| L3 | Go 类型检查（生成代码与类型系统兼容） | 未承诺，后续 |
| L4 | `go build` 全工程构建 | 未承诺，后续 |

`--check` 现在的语义：**与默认 generate 相同**（L1+L2 已是默认路径），
但参数被接受并记录——后续实现 L3/L4 时它才产生区分度。
帮助文本如实标注「当前与默认行为相同」。

### G7：fixture 三层

**冻结**：三层夹具，全部放在 `internal/cli/testdata/`（CLI 自己的测试资产，
不污染 examples）。

1. **最小有效**：单 `.gxml` + 同包 ViewModel（`<Text Value="{Title}"/>` +
   `<Button Click="Increment"/>`），覆盖解析→分析→生成→Commit 全链；
2. **多文件**：两个子目录各一 `.gxml`（验证 G2 按文件解析 + 确定性排序），
