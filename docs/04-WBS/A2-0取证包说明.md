> 所属：`TASK-AUDIT-002` §4（A2-0 前置门槛）

> 用途：为**独立审查者**提供可核验的提交链证据，使其不必依赖原执行者的整理结论。
> **本文只说明证据在哪、怎么验；不代替审查者做出核验结论。**

## 1. 为什么需要这个包

A2-0 的核心问题是：本项目的审计输入材料（5 个固定 SHA）**全部未推送到远端**。
审查者若只能访问 GitHub，将**无法**看到 `813b201` 之后的任何提交。
因此必须提供一条**不依赖远端**的核验路径。

| 文件 | 位置 | 说明 |
|---|---|---|
| Git bundle | `D:\Codes\Goxml-audit-evidence\goxml-a2-evidence.bundle` | Git 原生证据包（`git bundle create --all`），自包含完整历史 |

**证据包位于仓库之外**，不进版本控制、不随提交变化——这是刻意设计：

## 4. 审查者独立核验命令

### 路径 A：可直接访问本地仓库 `D:\Codes\Goxml`（最强）

```bash
cd D:/Codes/Goxml
git rev-parse HEAD                      # 完整 SHA
git log --format=fuller --stat <SHA>    # 逐提交：父子关系/作者/提交者/时间/文件清单
git show --format=fuller --stat 813b201 # A1 交付：确认含追踪矩阵 + 发现清单
git show --format=fuller --stat 11dc6b4 # 确认其登记内容指向 813b201
git show --format=fuller --stat 4a181aa # 确认含 A2 卡 + WBS 行 + 总账
git show --format=fuller --stat f6aad90 # 确认其登记内容指向 4a181aa
git ls-remote origin master             # 远端实测，须记录查询时间
```

### 路径 B：只有 bundle（无本地仓库访问）

```bash
git bundle verify D:/Codes/Goxml-audit-evidence/goxml-a2-evidence.bundle
git clone D:/Codes/Goxml-audit-evidence/goxml-a2-evidence.bundle <目标目录>
cd <目标目录>
git log --format=fuller --stat <SHA>
```

⚠️ 路径 B 只能证明 **bundle 自身自洽且可解析**（对象完整、父子关系成立、内容可读）。
它**不能**独立证明 bundle 内容等于真实仓库历史——bundle 由原执行者生成。
若审查者同时具备路径 A，应**优先用路径 A**；
若只有路径 B，须在 A2-0 结果中把「来源可信度」标注为受限。

## 5. 当前已知状态（供审查者比对，**不是核验结论**）

⚠️ **本表刻意不写死易变数值**。本地 HEAD 的完整 SHA、提交数、bundle 内含的 refs
会**随每次提交变化**；写死就会漂移，反而制造新的不一致。
审查者**必须**以证据文件 `00-原始命令输出.txt` 内**当次实测**的输出为准。

| 项 | 处理方式 |
|---|---|
| 基线 `e92e696748b982adb151e397586ccfbc8ede0edb` | **固定** —— A2-0 待核验对象之一；若它本身都无法读取，A2-0 直接记「无法验证」 |
| 本地 HEAD 完整 SHA | 以证据文件中 `git rev-parse HEAD` 的输出为准 |
| `e92e696..HEAD` 提交数 | 以证据文件中 `git rev-list --count` 的输出为准 |
| bundle 内含 refs | 以证据文件中 `git bundle verify` 的输出为准 |
| bundle 自洽性判据 | `git bundle verify` 应输出 `is okay` 且 `The bundle records a complete history`；**由审查者自跑** |
| 证据包生成时刻 | 见证据文件各命令段的时间戳 |

**证据包的再生规则**：每产生新的本地提交，证据包（bundle + 原始输出）**必须重新生成**，
否则其 `refs/heads/master` 会落后于实际 HEAD。审查者若发现 bundle 的 `master`
与本地仓库 HEAD 不一致，**应要求重新生成**，不得接受过期证据包。

## 6. 关于 `curl` 备用通道的口径

本轮曾出现 `curl https://api.github.com/repos/soldors/GoXml/commits/master` 返回空，
其后一次返回的是 **GitHub API 限流消息**（`API rate limit exceeded`）。

按负责人要求，必须保留如下口径：

- `curl` 的返回**既不能证明远端存在、也不能证明远端不存在**相关提交；
- 它只是一次 API 核查，**不等同** `git ls-remote` 实测；
- 限流的具体触发方**保留为未知**，不据此推断仓库状态；
- 远端状态一律以 `git ls-remote` 的**当次实测**为准。

   **不得**反复重试到出现一个有利结果后忽略失败历史，
   **也不得**因此判定整个审计失败或把 A2 标成完成。
4. 证据包**未纳入版本控制**，其完整性依赖文件系统访问；
