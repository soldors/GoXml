# 运维与开发工具指南

> **实现状态**：本表描述 CLI/Watch/Preview 的目标契约；当前仓库尚无已验收的 `goxml generate/watch/preview` 命令。不要把表中命令当成当前可执行的产品接口。当前可运行的开发门禁见 §2。

## 1. CLI 命令

| 目标命令（尚未作为产品 CLI 验收） | 用途 | 契约行为 |
|---|---|---|
| `goxml generate <path>` | 生成 Go 源码 | 解析、分析、格式化、校验后原子替换并更新 Manifest |
| `goxml generate <path> --check` | 生成前执行 package/build 检查 | 失败时保留旧生成文件 |
| `goxml generate <path> --clean` | 清理孤儿生成文件 | 只删除 Manifest 登记且带保护头的文件 |
| `goxml generate <path> --no-cache` | 禁用增量缓存 | 生成结果必须与缓存模式一致 |
| `goxml watch` | 双进程热重载 | 100ms 防抖、构建、进程树清理和状态恢复 |
| `goxml preview <file.gxml>` | 独立静态预览 | 不启动完整应用、不执行平台系统调用 |

## 2. 日常开发流程

```text
make verify
go test ./...
```

`goxml generate` 和 `goxml watch` 属于目标工作流，待 CLI/Watch 任务实现后再启用。

提交前执行 `make contract-lint`、`make lint` 和 `make test`。完整门禁以 [测试与质量门禁规范.md](../06-测试/测试与质量门禁规范.md) 为准。

## 3. 目录和文件

| 路径 | 作用 | 运维规则 |
|---|---|---|
| `<source>_gen.go` | 生成源码 | 不手工编辑；失败时保留旧文件 |
| `.goxml/generate-manifest.json` | 生成文件登记 | 损坏时停止清理并先备份 |
| `.goxml/cache/` | 增量缓存 | 可删除以排查缓存问题；删除不能改变生成结果 |
| `.goxml_state.json` | Live Reload 状态 | 只保存可恢复业务状态，损坏时安全丢弃 |
| watch 日志 | 监听、构建、进程和恢复信息 | 发布和回滚必须归档 |

## 4. 故障排查

### 4.1 生成结果不更新

1. 执行 `goxml generate <path> --no-cache`。
2. 检查输入相对路径、目标 Go package 和保护头。
3. 检查 Manifest 是否损坏；损坏时备份后再修复，禁止直接 `--clean`。
4. 比较连续两次生成的 SHA-256，确认是否为确定性问题。

### 4.2 热重载失败

1. 查看 Watch 的构建错误和子进程退出码。
2. 确认旧进程是否退出、Windows 进程树和文件句柄是否清理。
3. 检查 `.goxml_state.json` 的 schemaVersion 和 JSON 格式。
4. 构建失败时继续使用旧进程，不手工覆盖生成文件。

### 4.3 平台能力不可用

记录平台、桌面环境、权限、能力探测结果和稳定错误分类：`ErrUnsupported`、`ErrUnavailable`、`ErrPermission`、`ErrCancelled`。不得用 `zenity`、`kdialog` 或其他外部命令静默伪装平台实现。

## 5. 监控与退出标准

开发和 CI 至少记录：构建耗时、重启耗时、子进程 PID、状态恢复结果、平台错误、Race 失败和生成文件变更。

出现以下情况应停止发布并转入回滚：

- 进程树持续增长或退出后仍有残留；
- 主窗口被平台调用阻塞；
- 生成失败覆盖旧产物；
- 平台能力返回假成功；
- 生成结果不确定或 Manifest 清理越界。
