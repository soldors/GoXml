# 回滚手册

## 1. 适用范围

本手册覆盖代码、生成产物、Manifest、缓存、Live Reload 进程和已发布二进制的回滚。回滚操作必须保留日志和原始失败报告，不能直接删除证据。

## 2. 触发条件

- 生成代码无法通过 parser、gofmt、package build 或完整应用构建；
- 生成失败覆盖了旧产物，或 Manifest/缓存导致错误清理；
- Runtime、Platform 出现竞态、死锁或 UI 线程被阻塞；
- Windows 热重启残留进程或句柄，无法替换构建产物；
- 单帧 CPU、内存或分配量超过发布目标，且无法在当前版本修复；
- Windows 目标 `CGO_ENABLED=0` 构建失败，或 Linux/macOS 在对应宿主机按平台矩阵使用 `CGO_ENABLED=1` 构建失败。

## 3. 代码版本回滚

在 Git checkout 中执行：

```text
git status --short
git log -1 --oneline
git revert <commit-id>
make contract-lint
make lint
make test
```

如果当前工作区不是 Git checkout，使用发布系统保存的上一份源码快照或构建制品，不执行伪造的 Git 回滚命令。

## 4. 生成文件回滚

1. 停止 `goxml watch` 和生成应用，避免文件仍被占用。
2. 从发布制品或上一份成功构建中恢复 `*_gen.go`。
3. 恢复对应的 `.goxml/generate-manifest.json`。
4. 删除或隔离不属于上一版本的 `.goxml/cache/` 条目；不要删除用户源码。
5. 执行 `go build`、Golden 和生成结果确定性检查。

Manifest 损坏或来源不明时，禁止执行 `--clean`，先备份整个 `.goxml/` 目录并人工核对保护头。

## 5. Live Reload 回滚

- 构建失败：保留旧应用进程，不启动失败产物。
- 新进程启动失败：恢复旧进程（若仍健康），并保留新进程日志。
- Windows：按进程树清理策略终止整个子树，确认 exe 句柄释放后再替换文件。
- 状态文件损坏：备份 `.goxml_state.json`，删除损坏状态后以默认状态启动；不得反复重试同一损坏文件。

## 6. 发布制品回滚

| 步骤 | 操作 | 证据 |
|---|---|---|
| 1 | 定位上一份通过发布单和验收报告的版本 | |
| 2 | 校验二进制和文档归档 SHA-256 | |
| 3 | 停止当前进程并备份日志、状态和配置 | |
| 4 | 部署上一版本制品 | |
| 5 | 执行启动、平台能力和最小业务 smoke test | |
| 6 | 更新发布状态并记录用户影响 | |

## 7. 回滚后验证

- [ ] `make contract-lint`、`make lint`、`make test` 通过；
- [ ] 生成文件可编译且不包含 `reflect`；
- [ ] Manifest、缓存和用户文件边界正确；
- [ ] Live Reload 无残留进程；
- [ ] 目标平台的降级行为符合矩阵；
- [ ] 回滚结果已写入 [验收报告目录](../06-测试/) 和 [发布单.md](发布单.md)。
