## 2. 关键证据表

### 2.1 `$Theme.Primary` 的规范出现位置

| 行号 | 原文片段 | 性质 |
|---|---|---|
| `GXML语言规范.md:634` | `$Theme.Field` | 语法定义 |
| `:637` | 「主题引用只允许出现在颜色属性中…不能写成 `{Theme.Field}`」 | 语法约束 |
| `:720` | `Props="Name:string; Accent:color=$Theme.Primary"` | `<Def>` Prop **默认值** |
| `:872` | 同上（`<Defs>` 示例） | 同上 |
| `:913` | `<UserCard Name="{User.Name}" Accent="$Theme.Primary">` | **调用实参** |
| `:931` | `<Column Background="{Accent}">` + `Accent="#FF0000"` → 背景色为 `#FF0000` | **Prop 替换**示例 |

**结论**：`Primary` 是规范中**唯一**出现的主题字段名，但**无字段定义表、无类型声明、无颜色值来源**。

### 2.2 `Accent` 的角色（关键澄清）

`Accent` 在规范中出现 6 处（`:720/:723/:872/:874/:913/:931`），**全部**是 `<Def>` 的 `Props` 名或其绑定引用：

- 定义侧：`Props="...; Accent:color=$Theme.Primary"` —— `Accent` 是**参数名**，其**默认值**是主题引用；
- 使用侧：`<Text Color="{Accent}"/>` —— 绑定到该 Prop；
- 调用侧：`Accent="$Theme.Primary"` —— 传主题引用作为实参；
- 展开侧：`:931` 明确「`Accent="#FF0000"` → 背景色为 `#FF0000`」，即**展开期替换为具体色值**。

**结论**：`Accent` **不是主题字段**，是组件属性名。B1 初稿曾把它当主题字段，`B1-REVIEW` 已纠正，本轮原文核实**确认纠正正确**。

## 3. 方案 A / B 对等比较

### 方案 A：编译期解析（钉成常量）

**做法**：Codegen 在生成期把 `$Theme.X` 转为具体 `color.NRGBA{...}` 字面量。

| 维度 | 评估 |
|---|---|
| 颜色值来源 | **无法确定**——编译期无窗口、无主题实例。需人为规定「编译期默认调色板」，等于新增一套编译期颜色常量体系 |
| 未知字段处理 | 同 B（需字段清单） |
| 运行时切换 | **完全不支持**：生成物是常量，改 Palette 不影响界面 |
| 与 `:891` 一致性 | ✅ 完全一致（原句即此语义） |
| IR 改动 | 无 |
| Codegen 复杂度 | 低（生成字面量） |
| 诊断可测 | 容易（纯静态） |
| 测试成本 | 低 |
| 后续扩展 | 差——一旦要支持切换，需推翻 |

### 方案 B：运行时解析（读 `th`）

**做法**：生成 `th.Palette.<mapped>`，每帧读取。

| 维度 | 评估 |
|---|---|
| 颜色值来源 | 运行时当前 `*material.Theme`，无需编译期常量 |
| 未知字段处理 | 需字段映射表 + 生成期报错 |
| 运行时切换 | **支持**（前提见 §4 风险 R1） |
| 与 `:891` 一致性 | ❌ **冲突**，须修订契约（需负责人定性） |
| IR 改动 | **无**（`IsThemeRef` 已够） |
| Codegen 复杂度 | 低（生成字段访问） |
| 诊断可测 | 需新测试（未知字段） |
| 测试成本 | 中（需生成代码编译验证） |
| 后续扩展 | 好（新增字段只扩映射表） |

### 对比小结

| 维度 | A | B |
|---|---|---|
| 满足「切换后更新」需求 | ❌ | ✅ |
| 契约一致性 | ✅ | ❌（需改） |
| 实现复杂度 | 低 | 低 |
| 测试成本 | 低 | 中 |
| 扩展性 | 差 | 好 |

## 4. 推荐：方案 B（运行时解析），**提案待批准**

**理由**：
1. 需求本质是「主题变化后 UI 更新」——A 在**定义上**做不到，不是实现难度问题；
2. B 不需扩 IR（`IsRef` 二态充分），不改生成签名，不引入第三方依赖；
3. B 的唯一代价是改一条契约条款，而该条款本身存在语境争议（§5）。

**但必须同时承认 B 的致命前提**：

### R1（阻断级风险，已被 `B1-REVIEW`/`B1-TRACE` 双向证实）

`pkg/runtime/app/app.go:436`：
```go
a.th.Shaper = next.Shaper     // swapPending 全文仅此一行
```
全仓 `a.th.Palette` 赋值 **0 处**。`a.th` 唯一整体赋值是构造期 `app.go:281 a.th = lz.Theme()`。

**后果**：B 交付后，生成代码读的是 `th.Palette.X`，而 `th` 的 Palette 永远是构造期的值 → **切换主题后颜色不变**。B 单独完成 = 「代码正确、行为无效」。

**这不是可选项**：若不做 B4（Palette 刷新），方案 B 在功能层面与 A 等价（都不响应切换），却多付了改契约的代价。

### R2：`font_lazy_test.go:507-509` 已固化「只换 Shaper」假设

```go
// 切换**前**抓一份主题快照：只换 Shaper 的冻结语义保证了
// "temp 与 real 的差别 = Shaper 的差别"，没有 Palette / 字号混入。
```
B4 加 Palette 刷新会**触碰该假设**，需同步更新该测试意图（不是删断言，而是重新定义快照比较范围）。

## 5. `:891-892` 的定性（负责人裁决项）

**事实**：该段位于 `§11.5 「color 与 insets：精确类型身份」`（`:877`），全节是**绑定类型兼容矩阵**（`:883-886`）。

**两方面证据并存**：
- 支持「澄清」：原句主语是「**绑定**到 `color` 属性的值」，推理链是「绑定值→具体颜色→不需要 `IsThemeRef`」；
- 支持「改语义」：原句独立断言「`$Theme.Primary` **在编译期解析为具体颜色**，不是运行时绑定」——这是完整的语义陈述，不依赖绑定语境。

**本报告不作定性**，交由负责人。

## 6. `Background` 与 `Text.Color` 的范围差异

| 项 | `Background` | `Text.Color` |
|---|---|---|
| 规范地位 | `:79` 全局颜色属性 | `:709` Text 正式属性 |
| IR 落点 | ✅ `NodeIR.Background`（`ir_schema.go:717`） | ❌ 仅存 `Attrs`（`:741`） |
| Parser | ✅ `layout.go:61-66` 解析 | ❌ 无专用分支 |
| Codegen 消费 | ❌ 0 处 | ❌ 0 处（`codegen.go:578-603` 只读 Value） |
| 实现改动 | **新增一个颜色表达式分支** | 需改 Text 生成函数 + 可能需 IR 字段 |
| 测试范围 | 颜色生成 + 编译验证 | 同上 + Text 渲染路径 |
| 依赖 | 无 | 需决定「Color 存 Attrs 还是新 IR 字段」 |

**结论**：两者**工作量与风险不同级**。建议：
1. **本轮只做 `Background`**（IR 已就绪，改动最小）；
2. `Text.Color` **单独立项**；
3. **必须登记**：`GXML语言规范.md:723/874` 的 `<Text ... Color="{Accent}"/>` 在 `Text.Color` 实现前**不可生效**（当前静默忽略），不得因分拆而隐瞒。

## 7. 未知字段诊断策略

**现状**：`parser/attrs.go:261-264` 仅校验标识符形态：
```go
field := strings.TrimPrefix(raw, "$Theme.")
if !isIdentifier(field) {
    e := p.diag(span, CodeAttrCall, "invalid theme field %q in %q", field, attr)
```
→ 仅拦 `$Theme.`、`$Theme.1x` 等**非法标识符**；`$Theme.NotARealField`（合法标识符）**任何阶段都不报错**。

**现有诊断码核查**（`诊断码目录.md:107-116`）：

| 码 | 阶段 | 触发条件 |
|---|---|---|
| `GXML-ATTR-003` | Parser | **归集码**：属性值格式非法、布局属性误用、Grid 约束 |
| `GXML-ATTR-005` | Expander | 名称已知但不适用；**「也用于展开后无法解析的颜色属性」**（`:114`） |

**建议**：
- 字段名合法但**不存在** → 属「属性值非法」，语义归 `GXML-ATTR-003` 家族；
- **但字段清单是 Codegen 知识**（Parser/Expander 不知道运行时主题有哪些字段）→ 建议在 **Codegen 阶段**用现有 `fmt.Errorf` 报错（`codegen.go` 全部如此，如 `:560/566/600`）；
- **不新增诊断码**，除非负责人另有裁决；
- 测试：`$Theme.NotARealField` → 生成失败 + 不产生部分产物（`Generate` 返回 `"", err`）。
