## 3. 阻塞项

### Block-1（严重）：§6.1-N2 的变异与判据互不兼容 —— 按现卡执行 N2 必然判"不成立"

- **章节**：§5-A6、§6.1 表 N2 行、§3.3 目标形态
- **风险 / 矛盾**：N2 的变异是「删除 `:721` 的 `if lz.State() == theme.LoadReady { break }`」，
  判据要求「耗时 ∈ `[14s,20s]`、失败原文含『墙钟预算…耗尽』」。
  但静态推演（依据 §3.3 目标形态 + `:731-733`）：
  1. 删除 break 后，循环不再在 Ready 时退出；
  2. 到达后的第一次迭代：`pre == post == Ready`（或出现一次 `straddle` 后紧随一次 `pre==post==Ready`）；
  3. 该帧执行 `a.frame` ⇒ `swapPending` ⇒ `lz.Take()` 完成替换 ⇒ `FrameSubmittedAt` 非零；
  4. 于是 `:731` 的 `else if !lz.Report().FrameSubmittedAt.IsZero()` **成立** ⇒
     `t.Fatalf("确定处于到达前的第 %d 帧发生了替换…")` 在约 **1–2 ms** 触发。
- **影响**：N2 实际会得到 `耗时 < 1 s` + 失败原文出自 `:731-733`（**不是**「墙钟预算…耗尽」），
  直接违反判据 ②③ ⇒ 按 A6「任一项缺失即 N 不成立」判 **N2 不成立** ⇒ §8 收口条件 3 无法满足，
  **实施会被本卡自己的验收标准卡死**（这是"自锁"，不是"证据不足"）。
- **根因**：固定后的循环依赖**循环顶部的 break** 来避免在到达后继续断言；
  只要删掉 break，`:731-733` 就会先于墙钟预算触发。因此"删 break"**不可能**产生 15 s 的墙钟耗尽。
- **最小修订建议**（三选一，推荐 A）：
  - **方案 A（推荐，`rc==0` 型对照变异）**：变异改为 **① 删除 `:721` break ＋ ② 把 `:731` 判定临时改为 `else if false`**（两处都在 `:716-742` 内）；
    判据改为：`rc == 0`、子测试耗时 **∈ `[14s,20s]`**、日志 `before > 500`、输出**无** `panic`。
    证明的是"循环真的以墙钟为唯一出口"，且不需要区外注入。
    ⚠ 须同时写明"①②为**成对**变异，缺一不可：只删 break 会被 `:731-733` 抢先终止"。
  - **方案 B（区外注入）**：临时把 `:694` 的 `newTestLazy(t)` 换成**永不进入 Ready** 的 Lazy
    （如 `theme.NewLazy(theme.LazyOptions{Provider: <返回失败的桩>})` ⇒ `LoadFailed`，`pending=nil` ⇒
    `:731` 永不触发 ⇒ 循环跑满 15 s ⇒ 墙钟耗尽 `Fatalf`）。
    ⚠ 须在 §3.1 为 N2 **单列临时例外**（当前 `:693-715` 写的是"原样保留"，无 N1/N2 例外），
    并规定恢复后该行必须逐字还原。
  - **方案 C（附加对照，建议与 A 并用）**：恢复 `if before > 500 { break }` ⇒ 耗时必须 **< 1 s**，
    用以证明 `[14s,20s]` 判据**有判别力**（能区分"真预算"与"假预算"）。
- **禁止**：不得把方案 B 中"桩可能被嵌入兜底救回 Ready"当作已验证事实——
  本轮**未执行**任何验证，实施 Agent 若选 B，必须先做**桩的可行性预检**并记录结论。

## 6. N3b / N4 专项审查

**N3b —— 证据有效性判断：设计正确，判据不足。**

- 语义真实性：`else if` → `if` 使"到达前不得替换"的判定**对所有帧生效**（含 `straddle` 帧），
  与本用例核心语义直接相关 ⇒ 是**真实语义变异**，不是可达性装饰 ✅
- 假绿路径已识别：卡已写明 `before == 0` 时循环体一次未执行 ⇒ 变异不触发 ✅
- 未变红处理已规定：记录 `before` / `straddle` / 退出码 / 完整日志，标记**"未验证"，不计入通过** ✅
- 时序依赖提示（新增）：N3b 是否变红取决于"到达发生在某一帧运行期间**且该帧内完成替换**"
  （若到达发生在两次 `a.frame` 之间，循环顶部的 break 会先退出）⇒
