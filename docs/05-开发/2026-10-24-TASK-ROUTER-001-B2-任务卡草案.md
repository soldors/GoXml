## 1. 目标与非目标

**目标**：把 B1 路由核心接入生产事件循环的关闭链路，使「窗口关闭 → Router 级 Context 取消 → 页面 Context 取消 → 后续请求被拒/丢弃并有诊断」成为**有测试证据的生产行为**；同时收口 B1 的 P3 遗留（F-01/02/03/05/07/08）。

**非目标**：转场快照与动画（B3）；OSWindow（B4）；codegen 路由表；多窗口；OnMount/OnUnmount 生命周期回调（LIFE-001）；`-race` 的环境解锁（§8 只定义验证要求）。

## 4. 生命周期定义（B2 后的完整链路）

| 阶段 | 定义 | 契约锚点 |
|---|---|---|
| 窗口创建 | 不变（`newWindow` / `new(app.Window)`；首次 `Event()` 创建平台窗口） | 入口契约 §4 |
| 导航切换 | 不变（drain → 工厂 → 成功后取消旧页 Context + 切换）；失败原子性：**构造失败时旧页保持渲染、旧 Context 不取消、NavError 记录**——B2 不得改动该顺序 | B1 实现注释；授权 §4.6 |
| 关闭（DestroyEvent） | 任一事件循环收到 DestroyEvent → 调用 `onDestroy` → `Router.Shutdown()` → rootCtx 取消 → drain/入口进入丢弃模式 | 线程模型 §10.7「关闭窗口时所有 worker 正常退出」 |
| 取消任务 | 页面后台任务持有页面 Context：窗口关闭 ⇒ rootCtx 取消 ⇒ 全部页面 Context 级联取消；任务遵守「取消后停止或忽略结果」 | 线程模型 §5 |
| 同帧合并与诊断口径 | 不变（pendingNav 最后一胜）；**B2-1 后**：丢弃诊断覆盖三路径（Navigate 后关闭、Dispatch 后关闭、drain 清队列与 pending） | 线程模型 §4 |
| 重复关闭 | `Shutdown()` 幂等；`OnDestroy` 回调在关闭后仍最多执行一次 | 本卡新增定义（待裁决 D-3：回调执行次数语义） |

1. **app.go 是唯一交叠面**：G3 门槛前绝不触碰；获得授权后改动前后各跑一次 `go test -count=1 ./pkg/runtime/app/...` 并留证，改动 diff 独立提交评审（不执行 git 操作，以 diff 文件交付）。

3. 双方同时开工时：先做 `git status` 比对，发现交叠 → 停止上报负责人排程，不得并行修改同一文件。
4. B2-2 的 app.go 改动**晚于**字体线 D-ACCEPT 验收执行为宜（避免其验收矩阵基线漂移）——时序由负责人在 G3 裁决时一并确认。

## 8. `-race` 后续验证要求

- 触发条件：获得 CGO 工具链（gcc/clang + `CGO_ENABLED=1`）或具备 CGO 的验收机。
- 执行：`go test -race -count=5 ./pkg/runtime/router/...` 与 `go test -race -count=2 ./pkg/runtime/app/...`；通过标准 = 全绿且 `WARNING: DATA RACE` 零条。
- 未就绪时：报告显式标注「阻塞-环境（D-006 同源）」，**不得**以静态审查或非 race 运行替代宣称并发安全。
- 若 race 报告缺陷：按 P1 登记（并发正确性契约），修复后重跑该命令链。
