# 环境搭建

## 1. 目标与当前状态

本文件描述开发、测试和 CI 的统一基线。当前仓库仍处于设计和契约阶段，若工作区没有 `go.mod`、实现目录或测试目录，不得把初始化命令的失败视为代码回归；应记录为“环境前置未完成”。

## 2. 基础要求

| 项目 | 基线 |
|---|---|
| Go | **1.24 或更高版本**（Gio v0.10.3 硬性要求 `go 1.24.0`）；项目基线 1.26，CI 必须固定具体小版本 |
| Git | 仅在 Git checkout 中执行分支、提交和回滚命令 |
| Shell | Windows PowerShell 7+；Linux/macOS 使用 POSIX shell |
| Make | Windows 使用 GNU Make 或等价任务执行器 |
| 静态检查 | `golangci-lint`，版本写入验收报告 |
| 网络 | 初始化依赖时允许访问 Go module proxy；测试阶段不得依赖公网 |

**平台前置差异（重要）**：Windows 只需 Go；Linux/macOS 还需平台工具链，见 §4。依据见 [ADR-0007](../03-架构/adr/ADR-0007-Zero-CGO降级为Windows侧约束.md)。

## 3. 初始化步骤

在已经包含 `go.mod` 的实现分支中执行：

```text
go version
go env GOOS GOARCH CGO_ENABLED GOPATH GOMOD
go mod download
go install github.com/golangci/golangci-lint/cmd/golangci-lint@<固定版本>
make setup
make contract-lint
make lint
make test
```

`make setup` 只负责整理 module 和下载依赖；它不应修改用户代码。首次初始化必须保存 `go version`、`go env` 和命令退出码。

## 4. 平台前置条件

> 这一节是 2026-10-18 真机实测后新增的。**在干净机器上不安装本节依赖，`make build-linux` 会直接失败**，且失败原因（缺 `gcc`、缺 X11 头文件）对新手不直观。

### 4.1 Windows（只需 Go）

```text
# 无需 C 工具链
CGO_ENABLED=0 go build ./...
```

Gio 的 Windows 后端是纯 Go（`x/sys/windows` + D3D11 绑定），实测 `CGO_ENABLED=0` 构建成功，产物为单文件静态二进制。

### 4.2 Linux（必须安装系统依赖）

Debian / Ubuntu：

```bash
sudo apt-get install -y \
  build-essential pkg-config \
  libx11-dev libx11-xcb-dev \
  libxkbcommon-dev libxkbcommon-x11-dev \
  libxcursor-dev libxfixes-dev \
  libegl1-mesa-dev libgles2-mesa-dev \
  libvulkan-dev libwayland-dev
```

Fedora / RHEL 对应包：

```bash
sudo dnf install -y gcc gcc-c++ make pkgconf-pkg-config \
  libX11-devel libX11-xcb-devel libxkbcommon-devel libxkbcommon-x11-devel \
  libXcursor-devel libXfixes-devel mesa-libEGL-devel mesa-libGLES-devel \
  vulkan-loader-devel wayland-devel
```

验证：

```bash
gcc --version
pkg-config --modversion x11
CGO_ENABLED=1 go build ./...        # 必须为 1
```

运行期还需要（终端用户环境）：

```bash
sudo apt-get install -y libegl1 libwayland-client0 libwayland-cursor0 \
  libwayland-egl1 libxkbcommon0 libxkbcommon-x11-0 \
  libx11-6 libx11-xcb1 libxcursor1 libxfixes3
```

完整依赖清单见 [平台与平台依赖矩阵.md](../03-架构/平台与平台依赖矩阵.md) §4。

### 4.3 macOS（必须在 macOS 上构建）

```bash
xcode-select --install          # 提供 clang 与系统 SDK
CGO_ENABLED=1 go build ./...
```

**Apple 不提供 macOS 交叉编译工具链**，因此 macOS 产物只能在 Apple 硬件上生成（本地 Mac 或 macOS CI Runner）。

## 5. 依赖与平台兼容性检查

实现阶段至少需要核对以下依赖：

- **Gio**：渲染和窗口循环。Windows 纯 Go；Linux/macOS 依赖 CGO。
- `golang.org/x/tools/go/packages`：ViewModel 和组件静态分析。
- `golang.org/x/sys`：Windows 系统调用。
- Linux D-Bus：优先纯 Go 实现（如 `godbus/dbus`），不引入 CGO D-Bus 封装。
- macOS：Gio 后端本身使用 `#cgo` + Cocoa/Metal；平台层若自行绑定 Objective-C Runtime 可用 `purego`。

**规则**：

- **Windows 侧**：依赖必须在 `CGO_ENABLED=0` 下可构建，这是硬门槛。
- **Linux/macOS 侧**：允许 CGO，但新增系统依赖必须登记到平台矩阵。
- 不能只根据仓库 README 判断兼容性——必须实测目标平台的 `go build`。

## 6. 平台验证

| 平台 | 最低运行基线 | 构建命令 | 必做验证 |
|---|---|---|---|
| Windows | Windows 10 21H2+、amd64 | `make build-windows`（零 CGO） | 进程树清理、剪贴板、文件弹窗、托盘/菜单 |
| Linux | Debian 13 / Ubuntu 22.04+、amd64 | `make build-linux`（CGO=1） | Session D-Bus 缺失、X11/Wayland、portal 降级、**运行库齐全性** |
| macOS | macOS 12+、arm64/amd64 | `make build-darwin`（CGO=1，macOS 上） | 权限拒绝、剪贴板、文件弹窗、线程亲和性 |

平台测试中不可用的能力必须写明 `unsupported`、原因和用户可见行为。

## 7. CI 基线

每次提交至少执行契约、静态检查、单元测试、Golden 和生成代码检查；主分支额外执行**分平台**构建：

```text
# Windows Runner（零 CGO）
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build ./...

# Linux Runner（需 §4.2 的 -dev 包）
CGO_ENABLED=1 GOOS=linux GOARCH=amd64 go build ./...

# macOS Runner（需 Xcode CLT）
CGO_ENABLED=1 GOOS=darwin GOARCH=arm64 go build ./...
```

> ⚠️ **不再提供** "三端 `CGO_ENABLED=0` 交叉编译" 门禁。该目标已在 Linux 上穷举 5 种 build tag 组合验证为不可实现（见 ADR-0007 §3.1）。

完整生成应用和宿主机 smoke test 不能被平台包构建替代。CI 结果必须写入 [验收报告目录](../06-测试/)。

## 8. 常见问题

- `go mod tidy` 找不到 module：先确认当前分支已提交 `go.mod`，不要在设计文档分支上伪造通过结果。
- **Linux 上 `CGO_ENABLED=0` 构建失败**：这是预期行为，不是配置问题。Gio 的 `internal/vk`/`internal/gl`/`app/os_x11` 依赖 CGO。改用 `CGO_ENABLED=1` 并安装 §4.2 的包。
- **`cgo: C compiler "gcc" not found`**：安装 `build-essential`。
- **`pkg-config: x11` 找不到**：安装 `pkg-config` 与 `libx11-dev`。
- **运行时报 `libEGL.so.1: cannot open shared object file`**：安装 §4.2 的运行期库，或将应用封装为 `.deb`/AppImage 声明依赖。
- Windows 重启后无法覆盖 exe：按 [回滚手册.md](../10-发布/回滚手册.md) 和踩坑记录清理整个子进程树。
- 平台能力不可用：返回规范化错误，不能用外部命令静默替代原生实现。
