## 人员、目录与并行方式

当前执行容量为协调者加三个子 Agent。A/B/C 分别在 `parallel-compiler`、`parallel-runtime`、`parallel-cli` 独立 Git worktree；协调者在 `night-font-integration` 承担 D 线并最终组合。它们共享 Git 对象，不复制四份仓库历史。

- A 独占 `internal/compiler/**`，B 独占 `pkg/runtime/theme/**`、`pkg/runtime/app/**`（不含 `testdata`），C 独占 `internal/cli/**`、`cmd/goxml/**`。
- D 维护 `docs/**`、`examples/**` 与现状说明；前三条各有独立 `2026-10-31-{compiler,runtime,cli}.md` dev-log，避免竞争写同一日志。
- `contracts/`、依赖版本、未批准 ADR、用户未提交 Router/主题草稿不在开发范围。跨目录需求先报协调者，不能“顺手”修改他人文件。
- 代码可持续开发和精确本地提交，不再每个小修复创建一轮许可/报告链。真实命令和切片交接足以续接，只有中断或重要上下文才另写交接包。

## 开发与交叉审核流水线

1. 协调者做一次基线检查；各开发者只做相关包的验证。普通包测试以 `CGO_ENABLED=0 GOMAXPROCS=2` 限制负载，写代码不互相等锁。
2. A 完成后由 C 审，B 由 A 审，C 由 B 审；D 由空闲的非作者审核。审核者看真实 diff/契约/反例，不只看作者总结，不重跑没有变化的全套检查。
3. 具体阻断由原作者修复，再只复核有关差异；不把一个失败切片变成所有人的等待点。
4. 协调者只组合已通过切片，做一次组合 test/vet/build、docgate/diagdoc、生成代码检查。测试集必须显式排除本批无授权的真实窗口项；未执行范围在测试记录列出。
5. 每次提交禁用自动推送、使用单次空 hooksPath，显式暂存精确文件；最后才向主分支做普通快进合并/推送。远端若有新提交，先审差异，不覆盖、不强推。

## 验收与停止条件

通过：修复前失败和修复后通过有对应关系；没有禁用旧测试或放宽标准；公开语义不漂移；代码作者与审核者分离；组合验证通过；主仓原有 20 条状态和 50 文件字节保持、暂存区未混入用户内容。
