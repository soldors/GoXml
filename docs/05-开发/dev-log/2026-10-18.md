### 00.2 修复内容

**1. 建立 `go.mod`**


**2. 重构 `contracts/ir_schema.go`（81 行 → 441 行）**

按 `GXML语言规范.md` §10 逐条落实，修复两个会直接导致功能缺陷的问题：

- **`ForKey` 完全缺失**：原 IR 只有 `ForEach`/`ForIndex`/`ForIn`。新增 `ForClause.Key` + `HasKey`（Key 零值无法区分「未提供」）。缺失此项会让循环内控件状态串位原样复现。
- **绑定路径不可分段**：原 `BindingVal.Path string` 存整串，Analyzer 每次都要重新切分。改为 `Segments []string` + `Path()` 回显。

新增结构：`NodeKind`（9 种）、`Position`/`SourceSpan`、`IfClause`/`ForClause`/`DefClause`、`DefProp`/`PropType`、`Attr`/`AttrList`、`EventArg`；`CompilerError` 增加 `Code`/`EndLine`/`EndCol`/`Span()`/`NewError()` 与 7 个诊断码前缀。

**3. 补 `contracts/ir_schema_test.go`**

19 个测试，覆盖错误格式、源码范围、EdgeInsets、绑定分段、NodeKind 分类、属性查找、ForKey 存在性、虚拟化缺省值、PropType 解析、nil 安全、诊断码前缀唯一性。

**4. 修正 Go 版本要求**

原文档写 Go 1.23+，但 `gioui.org v0.10.3` 的 `go.mod` 要求 `go 1.24.0`。**按原文档安装会导致构建直接失败**，现已改为 1.24+。

**5. 修 `Makefile`**

- `test` 原为 `go test ./contracts/... ./internal/... ./pkg/...`，在目录尚不存在时报 `directory prefix does not exist`，使门禁卡死。改为 `go test ./...`。
- `verify` 原依赖尚未实现的 `bench-assert`，会永久为红。已移除。

**6. 补 `.gitignore`**

覆盖 `*_gen.go`、`.goxml/`、`.goxml_state.json`、构建产物、编辑器与 OS 文件。

## 0. 架构决策修订：Zero-CGO 降级（当日第二次会话）

### 0.1 背景

ADR-0005 规定「严禁 CGO、三端 `CGO_ENABLED=0` 一键交叉编译」。该规定从未真机验证。本次在真实 Linux 上做了穷举测试。

### 0.2 实测环境与方法

| 项目 | 值 |
|---|---|
| Linux | WSL2 Debian GNU/Linux 13 (trixie)，内核 6.18.33.1-microsoft-standard-WSL2 |
| CPU / 内存 | 20 核 / 15.86 GB |
| Go | go1.24.6 linux/amd64（WSL 内新装） |
| Gio | v0.10.3 |
| 被测程序 | 最小 Gio 应用（Window + Flex + material.Button，含中文标签） |

### 0.3 实测结果

**A. `CGO_ENABLED=0` —— 5 种 build tag 组合全部失败**

| tag 组合 | 结果 |
|---|---|
| （无） / `nox11` / `nowayland` / `noopengl` / `nox11,nowayland` / `nox11,nowayland,noopengl` | 全部 ❌ |

恒定错误：

```text
imports gioui.org/internal/vk: build constraints exclude all Go files
```

**B. `CGO_ENABLED=1` —— 一次构建成功**

先安装 `build-essential pkg-config libx11-dev libx11-xcb-dev libxkbcommon-dev libxkbcommon-x11-dev libxcursor-dev libxfixes-dev libegl1-mesa-dev libgles2-mesa-dev libvulkan-dev libwayland-dev`，随后：

```text
CGO_ENABLED=1 go build → exit 0，产出 11 MB 二进制
```

**C. 产物依赖（`readelf -d`）**

```text
NEEDED: libEGL.so.1, libwayland-egl.so.1, libwayland-client.so.0,
        libwayland-cursor.so.0, libxkbcommon-x11.so.0, libxkbcommon.so.0,
        libX11-xcb.so.1, libX11.so.6, libXcursor.so.1, libXfixes.so.3
INTERP: /lib64/ld-linux-x86-64.so.2
```

X11 与 Wayland 两套库同时被链接。

### 0.4 决策

按 ADR-0007 执行：**Zero-CGO 降级为 Windows 侧约束**，Linux/macOS 接受 CGO。

| 平台 | CGO | 状态 |
|---|---|---|
| Windows | `CGO_ENABLED=0` | 已验证，单文件产物 |
| Linux | `CGO_ENABLED=1` | 编译已验证，运行 smoke 待做 |
| macOS | `CGO_ENABLED=1` | **未验证**（无 Apple 硬件），v1 仅保证功能设计 |

## 1. 文档补充：性能预算与字体策略

### 1.1 背景

在通读全部规范后发现两个系统性空白：

1. **性能只有相对指标**（「单帧损耗 < 5%」），不可证伪且抓不住真正的开销来源（每帧堆分配）。
2. **字体与 IME 完全没有覆盖**。Gio 自带 `gofont` 不含 CJK 字形，中文界面会静默渲染为空白。

### 1.2 实测结论（i7-12700H / Go 1.26.1 / Gio v0.10.3 / CGO_ENABLED=0）

| 对照 | 差距 |
|---|---|
| 10,000 行列表：全量渲染 6,438,000 ns/op vs 虚拟滚动 19,200 ns/op | **335×** |
| 50 节点静态子树：每帧闭包 28,000 ns/op vs 编译期展开 2,550 ns/op | **11×** |
| 文本：稳定字符串 876 ns/op vs 每帧变化长串 82,053 ns/op | **94×** |
| 抽象：接口派发 361,000 ns/op vs 具体调用 61,000 ns/op | **5.9×** |
| 预分配复用切片 vs 不预分配 | **仅 4%**（无效） |

关键修正：**PIT-001 原建议「复用切片缓冲区」是错的**，真正开销来自闭包逃逸，必须编译期展开。
