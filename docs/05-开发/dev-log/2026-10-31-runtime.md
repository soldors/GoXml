## Provider 报告隔离

`ResolveWithReport` 的缓存命中路径已返回深拷贝，但首次系统命中、嵌入兜底、完全失败和 `LastReport` 直接返回内部 `p.last`。调用方改写外层错误或 Candidates、Embedded、Coverage 后，共用 Provider 的后续 Lazy 会读到被改写的历史诊断，出现 Ready 与 Probe.Err 同时非空等不一致。

上述出口现在复用已有 `copyProbeReport`，保留缓存身份、探测次数、错误链和 ProbeRan 的原语义。回归覆盖三条解析路径及两种报告入口，使用真实内置字体和真实 Lazy/Done 消费；并发观察者使用启动屏障与 WaitGroup，不通过 sleep 猜时序。原实现回归 rc=1，修复后 rc=0。

`Faces` 的共享切片身份由既有测试明确约束，本批没有改变它，也没有扩大到新的字体 API 或 Provider 配置冻结语义。错误对象沿用 Go 的只读惯例，不对外部错误做通用深拷贝。

## 窗口测试入口的 stop 等待收口

`RunWindowWithInvalidator` 原先启动一个只等待 stop 的 goroutine；窗口先发出 DestroyEvent、调用方不关闭 stop 时，这个 goroutine 永久等待并持有窗口。现在它同时监听事件循环退出。两个信号已经到达时优先结束等待，避免向已退出窗口补发关闭请求。

为无窗口验证提取了内部 `windowEvents` 边界和实际事件泵；公开 API 不变。回归直接运行生产 stop watcher，分别见证窗口先退出、stop 先到、两个信号均已到达；合成事件经过同一个生产事件泵，检查 invalidator 先交付、Layout 与提交。仅提取旧等待逻辑而未修复时 rc=1；修复后同组回归连续运行 20 次 rc=0。没有承诺取消已进入 Gio Perform 的底层操作。
