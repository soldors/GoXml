## 切片 1（d13ccf5）：结构化事务错误 + 诚实磁盘状态措辞（R3-qcode-01）

**复现**：`stageBatch` 四个失败分支（dir stat/CreateTemp/write/close）都丢弃 `cleanup` 结果；
pipeline 靠 `strings.Contains("回滚时清理")` 分类——而 `stageBatch` 从不产生该串，是死分支，
于是泄漏的临时文件总被裹成「磁盘无任何变更」。Windows 真实复现：`syscall.Open` 持无
`FILE_SHARE_DELETE` 句柄（GOROOT syscall_windows.go:395 固定 READ|WRITE 共享）→ `os.Remove`
真实共享冲突失败；修前错误只有「写入暂存 b_gen.go: boom」，对残留只字不提（红）。

**修正**：私有 `*txnError{op,path,cause,residue}` + `Unwrap` 保留 cause；`fileOps{close,remove,rename}`
按值注入受控故障（`realOps` 包级值从不改写，非全局污染）；四分支均收 `residue`（含当前失败项自身）；
`reportStageFailure` 按 `errors.As`+residue/createdDirs 给三态措辞，删除中文子串分类。退出码不变。
pipeline 的 MkdirAll 改为先 Stat 判存在、新建记入 createdDirs，建过目录不再声称无变更。

## 切片 2（5f59ad1）：可检测提交失败的进程内回滚（R3-qcode-02）

**契约依据**：输出契约 §9 行 524/530「磁盘写入失败…旧生成文件必须保持不变」。旧 `commitBatch`
注释声称「已 rename 不可恢复」与该条矛盾——逐个 rename 是单文件原子，但批次跨多文件，第 k 个失败时
前 k-1 个已被覆盖，旧文件不复存在，违反 §9。

**修正**：提交前把每个**已有普通文件**目标 rename 到同目录备份（rename 不改字节/权限/mtime，
含 Windows 只读属性）；失败时 `rollbackCommit` 用备份恢复旧目标、remove 撤回新建目标，
`txnError` 带 restored/withdrawn/unrestored/residue 实际状态，`reportCommitFailure` 诚实措辞。
**安全边界**：目标若是目录等非普通文件**绝不备份移走**（否则成功删备份会连用户目录一起删），
跳过备份让 rename 自然失败。明确这是**进程内可检测错误**回滚，非多文件 OS 原子、不承诺断电恢复。

**关键发现**：真实 CLI 提交失败不可自然触达——`decideCacheHit`（cache_wire.go:265）先 `readOutput`，
目录占位在缓存判定阶段（写盘前）就 fail-closed。故回滚由事务层用例证明（ops 注入 + Windows 真实 FS
持句柄），Manifest/cache 不登记由冻结顺序（产物→Manifest→缓存）保证。detached 树红证明（against d13ccf5：
a="NEW"、b 未撤回）；真实 exe 磁盘快照 BEFORE==AFTER、exit 2、目录原样、无 Manifest/cache/残留。

## 切片 3（ccfe806）：恢复失败的诚实残留报告 + 回归保护（R3-qcode-03）

切片2 已实现 `rollbackCommit` 的 unrestored/residue 与 `reportCommitFailure`；本切片用**真实
commitBatchOps 流程**（非手搓 txnError）补判别力回归：
- 恢复（备份→目标 rename）失败 → 目标进 unrestored、备份进 residue；**原始提交 cause 经 errors.Is 保留**
  （不被恢复错误顶替）；磁盘上目标仍带新字节、原字节滞留残留备份（用户可手工恢复）。
- 撤回（remove 新建目标）失败 → 进 unrestored（residue 为空也触发诚实措辞）。
- 成功路径删旧备份；删不掉时按**警告**（successResidue）上报而非致命错误，不阻断 Manifest/缓存登记。
- 回归护栏复跑绿：空批次、缓存命中 mtime（TestCacheHitSecondRunSkipsAndSkipsCodegen）、正常覆盖、切片2 真实 FS 回滚。

**mutation red**：把 `rollbackCommit` 换成「吞掉恢复/撤回错误、一律记为已恢复/已撤回」的朴素实现
（独立 detached 树 5f59ad1 + 变异），两个失败用例行为变红（unrestored 该有却空、谎称「磁盘恢复原状」）；
真实实现绿。这是行为失败，非删符号造编译失败。变异 diff 存 raw/slice3-mutation.diff。
**自纠**：首版误断「恢复失败时 a 不应存在」——实际 a 已被覆盖成 NEW-A、恢复失败后仍是 NEW-A（原字节在备份），
跑红后改为断言 a==NEW-A + 备份==OLD-A，更精确刻画 unrestored 磁盘状态。
