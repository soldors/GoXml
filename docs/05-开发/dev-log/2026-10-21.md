### 27.2 B3：产物落地与"可复现性"事故

产物：`pkg/runtime/theme/embedded/`

| 文件 | 字节 | SHA-256 |
|---|---|---|
| `GoxmlSansSC-Regular.otf` | 1,625,796 | `652910bee7fb0facfd9333b173c5ea7819eeadea8950592cf3f748bcb158e507` |
| `charset.txt`（7,540 行） | 52,780 | `d059792a99c1973fae338abaf24f54c383f91e7146888a75af61fa78487ae06f` |
| `LICENSE`（OFL 1.1 全文） | 4,301 | `6a73f9541c2de74158c0e7cf6b0a58ef774f5a780bf191f2d7ec9cc53efe2bf2` |
| `METADATA.json` | 1,754 | — |

**踩到的坑：改名步骤让产物不可复现。** 第一次落地的哈希是 `92d14965…`，
第二次重跑变成 `652910be…`，字节数却完全相同（1,625,796）——典型的"内容变了但长度没变"。
根因：`fontTools.ttLib.TTFont(src)` 默认 `recalcTimestamp=True`，保存时把
`head.modified` 改写成当前时间。

修法：`TTFont(src, recalcTimestamp=False)`，并在 `pyftsubset` 参数里显式加
`--no-recalc-timestamp`（4.67.0 的默认值本来就是 no-recalc，显式写出来是防默认值变化）。
**验证：连跑两次脚本，SHA-256 相同**。这是"产物哈希可断言"的前提——不可复现的哈希
不是证据，只是一次快照。

`scripts/font/subset.py` 的自我保护：输入文件 SHA-256 不符直接拒绝执行；
字符集规模偏离 (7540/6763) 拒绝执行；`--verify-only` 复算三个产物与字体名。
这几个"拒绝"是刻意的：宁可构建失败，也不要静默换字体。

### 27.3 B4：顺序由控制流保证，不是靠开关

- `ProviderOptions.Embedded EmbeddedFontLoader` 是**注入点**。没有它就无法证明
  "系统命中时不解析嵌入"——直接调用 `embedded` 包没法计数。
- `ResolveWithReport` 里 `probe()` 成功即 return，只有 `rep.Err != nil` 才走
  `loadEmbedded()`。顺序写在控制流里，不存在"忘了关开关"。
- 兜底成功后必须把 `rep.Err` **清空**。不清空的话调用方会把"已兜底成功"读成"失败"——
  这是很容易漏的一步，用例里单独断言了。

### 27.4 B5：demo 不能当靶子（本轮的第二个发现）

先按卡面说的用 `examples/demo` 前后对比，结果是：

```
未嵌入=15,158,272 B, 嵌入=15,157,760 B, 增量=-512 B
```

**负增量**。不是压缩，是 demo 用 `app.NewApp(view, material.NewTheme(), …)`
自己注入 Gio 默认主题，**根本不链接 `pkg/runtime/theme`**，链接器把 theme/embedded
整段丢了。拿它做前后对比得到"没超预算"，是假绿——不是达标，是没测到东西。

处理：新建最小靶子 `pkg/runtime/theme/testdata/sizeprobe`（只调一次 `theme.NewTheme()`），
让 `theme → probe → defaultEmbeddedLoader → embedded.Load → fontData` 被真实链接。
放 `testdata/` 下是因为 `go build ./...`、`go vet ./...` 会跳过它。

实测：

| 目标 | 未嵌入 | 嵌入 | 增量 |
|---|---|---|---|
| `examples/demo`（参考，不断言） | 15,158,272 | 15,157,760 | −512 |
| `testdata/sizeprobe`（断言靶子） | 5,454,848 | 7,636,992 | **2,182,144** |

2.18 MB 里除字体 1.63 MB 外，还含 `charset.txt`(52,780) / `LICENSE`(4,301) /
`METADATA.json`(1,754)，以及 `nofontembed` 构建下被 DCE 掉的 `encoding/json` 等。
**这是保守上界**，如实记在卡里。

两条断言缺一不可：`delta >= 1,500,000`（证明字体真进了二进制）与
`delta <= 3 MiB`（规范 §3.1）。只有后者的话，"根本没嵌进去"也会是绿的。

### 27.5 B6：严格语义，以及被同步更新的两个 A 期用例

`app.Run` 改用 `newThemeWithReport = theme.NewThemeWithReport`：`rep == nil` 或
`rep.Err != nil` 都返回错误，后者 `%w` 包装，`errors.Is(err, contracts.ErrFontNotFound)` 成立。
`RunWith` / `NewApp` / `RunWindow*` 一行没改。

**首次跑全量时 A 期两个用例变红**——这是预期内的语义变更，不是回归：

```
--- FAIL: TestFontProbeTimeoutAndDiagnostics
--- FAIL: TestFontProbeErrFontNotFound
    font_test.go:187: 期望 ErrFontNotFound，实际 <nil>
```

它们的前提是"系统候选全失败 = 整体失败"，而 B 之后会兜底成功。
**改法不是放宽断言**，而是给这两个 Provider 注入失败的嵌入加载器，
把被测对象重新隔离成"系统链路"；A 的严格性断言（必须 ErrFontNotFound、
不得空串+nil、候选状态正确）一条没删。"系统全失败但兜底成功"由
`TestEmbeddedFallbackSelectionOrder` 单独覆盖。

`NewTheme()` 保持宽容（签名固定、无错误位），但把"宽容入口 vs 严格入口"写进包注释，
避免后来者以为 `NewTheme()` 失败即报错。

### 27.6 变异验证（先证明测试能失败）

| 变异 | 预期 | 实测 |
|---|---|---|
| 把冻结的产物 SHA-256 改成 `00000000` | Metadata 用例红 | `--- FAIL: TestEmbeddedFallbackMetadata` + "字体 SHA-256 与冻结值不符" |
| 在 `p.last = rep` 后无条件 `_, _, _ = p.loadEmbedded()` | SelectionOrder 4 个子用例全红 | "系统命中却调用了嵌入加载 1 次——白付一次解析成本"（另 3 条报"实际 2"） |
| 把 `Run` 的 `if rep.Err != nil` 改成 `if false` | app 两条用例红 | `TestRunFailsOnFontDiagnostics` / `TestRunWrapsFontNotFound` 均 FAIL |

第一次把变异写成 `_ = p.loadEmbedded()`，编译不过（1 个变量 vs 3 个返回值）——
**编译失败不算变异证明**，重写为 `_, _, _ =` 后才拿到真正的断言失败。

另加两处**永久反向自检**（不是一次性变异）：
- `TestEmbeddedFallbackSubsetCoverage` 里有子用例把清单外码位喂给同一个判定器，
  必须报缺失——否则"零缺失"可能只是判定器恒返回空。
- 元数据用例先锚定包常量与确认名一致，再让元数据与常量比对，
  避免写成 `a != x || a != y` 这种自相矛盾条件（`go vet` 会报 suspect or）。
