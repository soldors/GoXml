# 2026-10-31 开发日志：`<Image>` 静态资产与编译期嵌入

## 背景

`<Image>` 自 v1 起在语言规范与 Schema 中存在（`GXML语言规范.md` §3.2、
`expander/schema.go:166`），但 Codegen 分派没有该标签。本次按
`TASK-IMAGE-001` / ADR-0015 补齐，并避开在制线（Router、主题色、字体/Lazy、
CLI 路径安全、事件字符串/For 作用域、窗口 watcher）。

## 实现

- **契约**：新增规范 §3.2.2、输出契约 §4.8、ADR-0015、诊断码 §2.9。
- **Codegen**：
  - `nodeExpr` 新增 `Image` 分支；`imageExpr` 只接受静态 `Src`；
  - 路径归一化拒绝绝对路径、卷名/UNC、`..`、隐藏/下划线段、控制字符；
  - 生成 `//go:embed` + `goxmlAssets<Source> embed.FS`；
  - View 增加 `img<n> paint.ImageOp`；构造期 `ReadFile` + `image.Decode` 一次；
  - 同一 `Src` 去重，共享字段；绘制 `widget.Image{Fit: <Fit>, Position: Center}`；
  - 静态 `Fit`：`Contain`（默认）/`Cover`/`Unscaled`；绑定与非法值拒绝；
  - `importSet` 支持 `_ "image/png"` / `_ "image/jpeg"` 的 blank import；
  - 命名预检新增 `goxmlAssets<Source>`（`NamingTarget.HasAssets`）。
- **Pipeline/CLI**：
  - `Config.TargetDir`（缺省回退 `SourceDir`），CLI 传入目标包目录；
  - `RunPrepared` 在 Codegen 前校验资产存在性/可读性/格式/1 MiB/4M 像素；
    先 `DecodeConfig` 查尺寸，再完整 `Decode` 查截断/损坏；
  - 失败发射 `CODEGEN-ASSET-001..003`，不进入生成；
  - demo 同步 TargetDir。
- **诊断**：新增 `CODEGEN-ASSET` 前缀与 3 个码，更新 diagdoc 计数与目录。

## 为什么不选 Base64

生成文件只含 embed 路径，资产内容变化不改变生成文件，因此 CLI 现有缓存键
（源内容/输出路径/版本）仍然正确；Go 构建按 embed 文件内容重编译。若把字节
Base64 内联，资产一改就得让缓存键感知资产哈希，且会与在制的 CLI/Manifest
工作重叠。

## 边界

- 只支持静态 Src；不支持绑定、Cover/平铺、SVG、动图。
- 资产必须位于生成文件所在 Go 包目录；`--out-dir` 需把资产放到输出包目录。
- 静态构造期解码失败 panic（pipeline 已校验，属生成文件损坏护栏）。
- 缓存命中路径不重新校验资产存在性；缺失在 `go build` 暴露。
  第二轮把这条从「说明」升级为**实测缺陷**：删资产 / 改成坏字节 / 大小写与磁盘不符三种状态下
  `generate` 都报缓存命中且 rc=0，同状态加 `--no-cache` 才拿到 `CODEGEN-ASSET-002/001`；
  坏字节的产物能编译，失败点退到构造期 panic。修复方案只交提案（CLI 缓存线在制），
  见 `cache-hit-proposal.md`。同时确认：**资产内容变化不需要重生成源码**（源码 SHA 不变而二进制 SHA 变），
  缓存键不含资产字节是正确设计，不要把它当成同一个缺陷一起「修」。
- 大小写门禁只在未命中、走完整管线时生效；命中路径同样跳过它（上一条的同一个洞）。
  在大小写不敏感的本机上，`//go:embed "assets/logo.png"` 指向磁盘 `Logo.PNG` 时 `go build` rc=0，
  所以「本机编得过」不构成拼写正确的证据。
