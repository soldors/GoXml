## 三个实际缺陷

1. Manifest 的 `source` / `output` 只反序列化而不校验。真实独立临时 module 中，
   `output=../outside_gen.go` 让 `generate --clean --check`（含 `--no-cache`）删除 module 外
   的带保护头文件，命令仍返回 0。现在整份 Manifest 先校验所有相对文件路径，
   再核对已有祖先的真实路径与最近 module，拒绝符号链接越界、
   嵌套 module，以及直接作为输出的文件符号链接。新输出也经过同一边界检查，
   全部检查在生成、暂存、清理之前执行。
2. `--clean` 原来把“不在本轮输入内”当作孤儿，生成单文件时会删除另一个仍存在的
   源的产物。现在只在对应源实际不存在时允许清理；源不可读取等错误明确失败。
3. Manifest 伪造 `output=vm.go` 可以让手写 Go 文件从包源码缓存指纹中消失。
   修改 `vm.go` 为非法语法后，CLI 仍返回 0 并报告缓存命中。现在只有仍带规范保护头
   的已登记产物才进入指纹排除集；用户接管的文件继续参加指纹，缓存不会掩盖其错误。

旧 `TestNamingPrecheckSkippedOnAllHit` 把另一个已登记产物去掉保护头并改成用户声明，

## 独立审核修正：Windows junction 不是目录 symlink

首个提交 `6baef289` 的实际链接测试仅覆盖 `os.Symlink`，不能声称已验证 junction。
运行时线独立审核用真实 Windows junction 与尚不存在的输出后代目录复现外写：
Go 1.26.1 的 `Lstat(junction)` 为 `ModeIrregular`，`EvalSymlinks(junction)` 却原样返回
且无错误，原检查把词法路径误当真实路径。新增 `output_path_windows_test.go` 使用
真实 `mklink /J`，修前测试 rc=1，CLI 实际 rc=0 且创建 module 外目录/产物。

后续修复明确拒绝最近现存祖先中的 `ModeIrregular`，并检查解析后路径的祖先，
防止目录 symlink 再指向 junction 叶子。此为保守失败：junction/reparse 路径不受支持，
不冒充已经完整解析其目标；正常目录与 module 内普通目录 symlink 仍可生成。
回归包括 out-dir 缺失后代、symlink→junction、Manifest 缺失/已有输出及合法目录
symlink 对照。原提交保留，不回改首轮失败，独立审核者复核后续差异。

后续完整相关包复验 `go test -p 2 ./internal/cli ./cmd/goxml -cover -count=1`
退出码 0，CLI 覆盖率 85.5%（22.325s）；vet 与 diff 检查退出码 0。
