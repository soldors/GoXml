## CLI 回滚缺陷与接管

qcode `d13ccf55` 首片只有结构化错误与暂存清理，批准它不等于批准后续完整回滚。后续 `5f59ad1`、`ccfe806`、`bcb1840` 被真实 CLI 反例否决：后序目标备份失败时，前序已提交目标未恢复，但消息称已恢复。旧字节仍在备份中，不应描述为永久丢失。

`0f5af3c` 补充 close/remove 次成因；`ad3317d` 是作者日志。DeepSeek 接管 `010deca`、`3c1aef7` 统一 E1（备份失败）、E4（Lstat 异常）、E5（非普通目标）与安装新产物失败的收口。独立终审以真实 Windows 共享句柄阻止后序备份，证实前序字节/权限/mtime 恢复、当前目标和 Manifest 未变、无 tmp/bak 残留；成功对照确实写入新结构。

审核补丁 `7c1f739` 把全局 `osLstatHook` 改为按值 `fileOps.lstat`，加强实际临时备份路径的残留检查，补首项/后序/新旧目标混合入口矩阵，并修正“成功前从不触碰旧目标”等失真注释。实现保证是进程内可检测失败后的恢复与诚实报告；不保证崩溃、断电或多个文件对外原子可见。

## 隔离的 GOFLAGS 候选

`e8b4018` 只修复包名选择，不能代表重复生成全链已完成。独立复核发现：切换 tag 后 Analyzer 仍会读入旧包名生成物而拒绝加载；此外，仅凭三行保护头跳过未登记用户文件会漏掉真实多包冲突。GOFLAGS 候选与其新修复保留在隔离分支，不纳入本次主仓接纳。旧 F2 因此仍为待闭合项，不能把“fresh 生成可构建”外推成“配置切换可恢复”。
