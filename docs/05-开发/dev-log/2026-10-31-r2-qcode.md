### 2.1 R2-qcode-02：定名抓到外部测试包，产物写进构建不接受的包名

`internal/cli/pipeline.go` 的 `packageDirName` 此前按 `ReadDir` 顺序取**第一个**
`.go` 的 package 子句，`*_test.go` 也在候选里。普通工程形态就会踩：

```text
ui/view.go      → package ui
ui/home_test.go → package ui_test   （字母序在前，被老实现抓走）
ui/home.gxml    → 产物 ui/home_gen.go 写成 package ui_test，CLI 报「已生成」rc=0

$ go build ./ui
found packages ui_test (home_gen.go) and ui (view.go) in ...\proj2\ui   rc=1
```

契约依据：`代码生成输出契约.md` §3.2「如果输出目录存在多个非测试 package，
生成失败」、§4.1 与 §13 验收 4「包名能从目标目录正确解析 / 缺失或冲突时返回
明确错误」。修法（`internal/cli/pipeline.go:packageDirName`）：排除 `*_test.go`、
去重收集包名集合，集合为空 → 报「没有可定名的非测试 Go 源文件」，多于一个 →
报「存在多个非测试 package（列出全部，顺序取 `ReadDir` 文件名序）」。
排除测试文件同时与 K3 指纹口径对齐：`internal/cli/cache_wire.go` 的
`packageSourcesFingerprint` 本来就不收 `_test.go`，定名却在收，两边说法不一致。

分层事实（不是本轮改的，但要说清）：「同一目录两个**非测试**包」这种形态，
编译前端也会拒绝——老实现下实测到的是
`GXML-ROOT-002: ViewModel "VM": package ... failed to load: found packages ui (vm.go) and other (zz_other.go)`。
修后由 `packageDirName` 在阶段零 A 先报出指向目标目录的诊断；未新增诊断编号，
改变的只是哪一层先到达。「外部测试包」那侧前端不管（`ui_test` 是合法的外部测试包），
所以只有定名这一层能拦住——这正是缺陷长期存在的原因。

`discoverInputs` 对**单文件输入**只给 basename，于是 `--out-dir` 的

## 3. 切片 3：空格/中文工程的发现与诊断可定位性

### 3.1 先把「Unicode 工程」拆成两种结果不同的形态（实测）

Go 的 import path 只接受 ASCII，所以**中文/空格出现在哪一层**决定成败：

| 形态 | 位置 | 实测 |
|---|---|---|
| A（合法） | 模块根路径含空格+中文（`…\r2 工程甲`），包目录 ASCII，页面**文件名**含空格与中文 | `generate <root>` rc=0 两页出；Manifest 保留 `ui/home page.gxml`、`ui/深度页面.gxml` 且一律 `/` 分隔；第二轮全命中；`--no-cache` 轮产物 md5 与缓存轮**逐字节相同**；`go build ./...` rc=0、`go vet ./ui/` rc=0；`--clean` 正确删掉带空格的孤儿 `ui/home page_gen.go`（`raw/slice3-cli-unicode-module-root.txt`、`raw/slice3-cli-rel-line.txt`） |
| B（Go 自己拒绝） | **包目录名**含中文（`页面 一`）或空格（`admin panel`） | rc=2，`GXML-ROOT-002: … failed to load: malformed import path "…/admin panel": invalid char ' '`；**同一句 `go build ./...` 也报**（`raw/slice3-cli-space-package-dir.txt`、`raw/slice3-cli-nonascii-package-dir.txt`）——不是 goxml 的缺陷，但必须失败得干净 |

B 的失败姿态本轮钉成回归：写盘前停住（无产物、无 `.goxml/` 目录）、退出码 2、
