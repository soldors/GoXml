## 二、契约与代码证据清单

### 2.1 对 router 设计构成硬约束的冻结条款

| 来源 | 条款 | 对 router 的含义 |
|---|---|---|
| 运行时线程模型 §1（冻结 10-18） | UI 线程拥有「路由状态和 Macro 状态」；路由状态变更必须 UI 线程提交 | Router 全部状态仅在帧（UI 线程）内变更；后台只可排队 |
| 线程模型 §3 | 一帧顺序：排空 dispatcher 队列 → 应用路由变更 → 读 VM → … | Router 的 Dispatcher 队列在**每帧 Layout 开头**排空（【设计判断】：不修改 app.go 的前提下，drain 点 = router 根 View.Layout 第一行，语义等价） |

### 3.3 候选 API

type PageFactory func(ctx context.Context) View

// Router 是单窗口路由器，同时是可交给 app.Run/RunWith/NewApp 的根 View。
type Router struct{ /* 未导出 */ }

func New(opts ...Option) *Router

type OSWindowConfig struct{ Title string; Width, Height unit.Dp }
type OSWindow struct{ /* 未导出 */ }

### 3.4 行为定义（授权 §二.2）

**路由注册**：`Register(path, f)` 幂等性为"非幂等"——重复路径返回 error（防静默覆盖）；`path` 为精确字符串匹配（v1 无参数化路由，见 Q4）；注册发生在 UI 线程（文档约束 + 运行期尽力检测，见 §3.5）。

**当前路径**：构造后未导航时无当前页——根 View 渲染空白帧并在首次 `Navigate` 后挂载；`Current()` 在转场期间返回**目标**路径，转场状态用 `TransitionActive()` 单独查询（避免一个 API 返回两种语义）。

**页面分发（每帧固定顺序）**【设计判断，逐条对应线程模型 §3】：
1. 排空 Dispatch 队列（此时可能包含导航请求）；
2. 若发生导航：取消旧页 Context → 置换当前页为新 factory(ctx) 产物 → 进入转场状态（快照 = 上一帧录制的旧页 CallOp）；
3. 转场帧：先回放旧页快照（按进度做透明度合成），再 Layout 新页（新页是"业务 Layout"，旧页**永不**调用）；
4. 非转场帧：仅 Layout 当前页；
5. **每帧末尾**为当前页录制本帧快照进自有 buffer（覆盖上一份）——保证任何时刻切走都有"已提交"的旧页可回放；转场期间不录制新页快照（转场结束后的首帧恢复录制）；
6. 转场进行中追加 `op.InvalidateCmd{At: now+tick}` 驱动下一帧（X3）；进度与结束判定只在 UI 线程。

**Dispatcher**：互斥锁保护的 FIFO 队列；`Dispatch` 仅入队 + Invalidate；帧首 drain 全部（同帧合并天然成立）；Router Context 取消（窗口销毁）后入队的任务被丢弃并计数（线程模型 §4"关闭后返回取消错误或丢弃并记录诊断"——v1 丢弃 + 原子计数器可观测）。

### 3.6 OSWindow 语义（授权 §二.5）【设计判断，定位依据 D-005】

- **创建**：`OpenOSWindow` 在调用时同步创建 `new(app.Window)` 并启动独立事件循环 goroutine（模式同入口契约 §4：Event 循环在 goroutine、不调 `app.Main()`——由宿主进程的 `app.Main()` 统一承载多窗口）。内容 View 由调用方给，**不经过路由分发、无转场、无快照**。
- **所有权**：内容与生命周期归调用方；router 只承载窗口句柄与 Close。
- **关闭**：`Close()` = `Perform(system.ActionClose)` + `Invalidate`（模式同 E3），幂等；用户手动关窗 → DestroyEvent → `Done()` 关闭 + 该窗口 Context 取消。
- **取消语义**：打开后不可"撤销打开"，只能 `Close`；`OpenOSWindow` 失败（参数错误）返回 error。
- **与主窗口路由的关系**：完全旁路——OSWindow 不是路由终点，不参与 `Current()`，不受 `Navigate` 影响；其重绘由调用方对其内容自行 Invalidate（v1 不提供跨窗口通知，遵守状态更新契约 §2.2）。
- **范围声明**：这是对"v1 单窗口"契约的**逃生舱例外**，不是多窗口支持；OSWindow 内不承载绑定失效链（见 §六 R1，需负责人认可该解读）。

### 3.7 Gio 线程约束接线与证据（授权 §二.6）

| 约束 | 接线方式 | 证据 |
|---|---|---|
| UI 状态仅 UI 线程改 | Router 状态只在 `View().Layout`（即 FrameEvent 处理区间）内变更 | 线程模型 §1 + E1 |
| 后台请求排队 | `Navigate/Dispatch` = 加锁入队 + `Invalidator.Invalidate()`（并发安全，X4） | 线程模型 §4/§7 |
| 帧首应用变更 | drain 队列 = 根 View Layout 第一步 | 线程模型 §3（等价实现，见 §2.1 行 3 注） |
| 动画不占后台线程 | 转场帧内追加 `op.InvalidateCmd{At}`，下一帧由 Gio 原生调度 | X3 源码 |
| 页面 Context | `context.WithCancel(r.Context())` per 页，切换即 cancel | 线程模型 §5/§7 |
| 主线程约束 | router 不调 `app.Main()`；生产形态由 `app.Run/RunWith/NewApp` 承载（router 根 View 作为 view 传入） | 入口契约 §2/§4 |
