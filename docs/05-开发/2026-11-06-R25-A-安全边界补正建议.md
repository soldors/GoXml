# R25-A 安全边界补正建议（Image 资产 × CLI 缓存 × overlay）

> **状态：** 补正建议（proposal）。**基线 `docs/03-架构/安全边界与威胁模型.md` 未改动**；
> 本文供协调者三方归并 R25 的 9 项 WIP 时参考，尤其是 `input/wip-bytes/.../安全边界与威胁模型.md`
> 提案 §3.8 中的过期表述。本补正**不新增威胁模型承诺**，只纠正与真实代码不符的一句。

## 背景（事实，非猜测）

9 项 WIP 中的「安全边界与威胁模型.md」建议补丁在 §3.8 末尾写有：

> **缓存命中例外**：当前 CLI 缓存键不包含资产依赖，缓存命中时不重新校验资产；
> 上述门禁只保证生成路径。该例外待 CLI 缓存线接入资产依赖后消除。

该表述**已过期**：R16-A 已把资产内容指纹接入 CLI 缓存键（K12）。

证据（本基线代码）：
- `internal/cli/build_inputs.go`：`assetsFingerprint(file, src, targetDir)` 读取静态 `<Image Src>`
  资产字节（按生成包目录 `TargetDir`），sha256 汇总。
- `internal/cli/cache_wire.go`（`K12` 注释块）：`if af, ok := assetsFingerprint(...); ok { buildInputs += af } else { r.dependencyUnsafe = true }`
  → 资产内容/存在性/读取失败都进入缓存键或被保守判 unsafe（禁止命中）。
- 既有验收 `internal/cli/asset_identity_r16_test.go`：删除→安全 miss→拒绝保旧；内容改→miss 重生成；
  大小写错拼→miss→拒绝；超预算→缓存禁用（不命中）。
- 本轮 `internal/cli/asset_overlay_batch_r25_test.go`：冷/命中 mtime 稳定、内容变/删除/损坏/恢复、
  `--no-cache` 冷批坏资产整批不落盘、暖批坏资产整批拒绝保兄弟/Manifest、overlay 不替换资产字节、跨包 out-dir。

## 建议替换（§3.8 "缓存命中例外" 整段 →）

```
**缓存命中与资产一致性（K12，已接入）**：CLI 缓存键包含静态 `<Image Src>` 资产文件内容的
稳定指纹（`assetsFingerprint`，按 `TargetDir` 生成包目录读取资产字节，sha256 入键）。因此资产
被删除、内容改变、或大小写/拼写变化都会改变缓存键 → 安全 miss → 资产门禁（存在性/路径/格式/
预算）重新执行；资产无法安全读取时该次运行禁止命中（保守 miss）。缓存命中时产物字节、mtime 与
Manifest 均不改变。**注意（R25-A repair-r1 更正）**：Go `-overlay` **会**替换 `//go:embed`
资产字节（本机 Go 1.26 实测：overlay 映射资产到其它文件后，`go test` 读到的 embed 字节即替换内容）。
因此资产门禁与缓存指纹必须校验**有效（overlay）字节**，不能只校验磁盘字节——否则会出现"校验一份、
构建嵌入另一份"的分叉（R25-A 初版即此缺陷，见下方 repair 段）。

批次层面：单页坏资产会使整批退出非零且不落盘任何产物（冷批）或保留全部旧产物/Manifest（暖批），
不会因"另一页命中"而写入半批。
```

## R25-A repair-r1 更正与修复（追加批次，不改旧报告/raw）

**撤销**初版结论"Go overlay 只作用 Go 源，不改变 embed 资产字节 / 基线跨阶段一致、无生产违例"。
独立复核与本地重放均证明：真实 Go `-overlay` 替换 `//go:embed`；磁盘合法 PNG + overlay 坏字节时，
修复前 CLI `--check` 错误 rc0 写盘，随后生成的构造函数解码 panic（`image: unknown format`）。
这是一个真实生产缺陷：**资产门禁校验磁盘字节，而 Go 构建嵌入 overlay 字节**，两阶段分叉。

**最小 fail-closed 修复（不扩大 ADR-0015 可信目录边界、不改 Codegen 模板、不新增诊断号）**：
资产门禁与缓存指纹在 Src 路径/边界/拼写校验通过后，若该资产的**绝对磁盘路径**命中用户 Go overlay，
则改为读取并校验 overlay 的**有效字节**（`""`=删除 → fail-closed 缺失；替换文件须普通文件且受同一
字节预算约束；格式仍由 `ValidateAssetBytes` 校验）。缓存指纹同样以有效字节入键 ⇒ overlay 有效字节
变化 → 安全 miss。`Config.AssetOverlay` 由 CLI 复用只读的 `userOverlayMap` 注入。overlay 目标字节
本即构建实际消费的输入，校验它不扩大信任边界，只是让"校验字节==嵌入字节"。

边界仍在：硬链接/TOCTOU/解码器/解压炸弹/未支持格式 未覆盖（同前）。新批次测试见
`internal/cli/asset_overlay_batch_r25_test.go`、`asset_overlay_embedtruth_r25_test.go`。

## R25-A repair-r2 更正与修复（追加批次，不改旧报告/raw）

**F-A4**：上一修复只匹配 `overlay[精确文件绝对路径]`；Go overlay 支持**祖先目录**删除/替换，其后代
在 Go 有效文件系统里已缺失，而门禁回退读盘 ⇒ 默认生成 rc0 写产物（`--check` 才被 embed missing 拒绝）。
**修复**：`resolveEffectiveAsset` 按最长前缀祖先解析——精确文件→校验目标字节；精确/祖先删除→fail-closed
缺失；祖先替换为非空目录（无法等价解析后代字节）→保守 fail-closed。门禁与 K12 指纹共用同一“有效字节/
缺失”判定。不误拒无关未用 overlay（未命中祖先/精确键时仍读盘）。

**F-A5**：Src 可解析到本批/owned 生成输出（如页面自身 `home_gen.go`）；precommit/构建候选 overlay 对
同路径**优先于**用户 overlay，故有效嵌入字节是生成 Go 源（非图片），而门禁却校验用户 PNG，`--check`
rc0 写盘后构造 panic。**修复**：`Config.AssetOutputPaths` = 本批生成产物 + Manifest 已登记(owned)产物；
Src 解析到其中任一路径即在写盘前 fail-closed（与候选优先一致）。不扩可信目录、不改 Codegen、不加诊断号。

**未证/范围**：跨平台未验；ancestor-replace 目录用例本机更早被 go list（overlay maps child to directory）
先拒，属写盘前拒绝，资产门禁 unprovable 分支由 pipeline 单元测试直接覆盖；同批其它候选/owned 命中路径
的处理范围即“解析到输出路径即拒绝”，不做任意自引用字节求解。
