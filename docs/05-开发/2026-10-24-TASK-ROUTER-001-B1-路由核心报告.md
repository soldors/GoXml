## 2. 接口设计及依据

```go
// 全部签名锚定已冻结契约；结构化等价使本包零依赖 pkg/runtime/app。
type View interface{ Layout(gtx layout.Context, th *material.Theme) layout.Dimensions } // 入口契约 §2
type Invalidator interface{ Invalidate() }                                              // 状态更新契约 §2
type PageFactory func(ctx context.Context) (View, error)                                // 见下「偏差说明」

func New() *Router
func (r *Router) Register(path string, f PageFactory) error  // 精确键；重复→ErrPathRegistered；空路径/nil 工厂拒绝
func (r *Router) Navigate(path string) error                 // 唯一后台合法入口（线程模型 §7）；未注册→ErrPathNotRegistered
func (r *Router) Current() string                            // 初始 ""；帧内应用后才变
func (r *Router) NavError() error                            // 最近一次异步导航失败（成功导航清空）
func (r *Router) DroppedCount() int64                        // Router Context 取消后丢弃的请求数（线程模型 §4）
func (r *Router) Dispatch(fn func())                         // FIFO 全执行；不合并内容
func (r *Router) Invalidate()                                // 透传 Invalidator；未接线时 no-op
func (r *Router) SetInvalidator(inv Invalidator) error       // 恰好一次；重复/nil 拒绝
func (r *Router) Context() context.Context                   // 页面 Context 的派生源
func (r *Router) View() View                                 // 根 View；app.Run/RunWith/NewApp 直接可用
```

**状态语义**（授权 §5 要求逐项）：

| 转换 | 语义 |
|---|---|
| 重复注册 | 返回 `ErrPathRegistered`，不覆盖 |
| 未注册导航 | `Navigate` 同步返回 `ErrPathNotRegistered`（注册表互斥保护；v1 无反注册，无 TOCTOU） |
| 同路径重复导航 | no-op 返回 nil，不重构造页面、不取消 Context；并撤销未应用的待定导航（"最后一次请求胜出"的一致推论） |
| 同帧多次导航 | 合并为最后一个（线程模型 §4），中间页面**不构造**（授权 §4.10 防重复生命周期） |
| 页面创建失败 | 工厂先执行、成功后才取消旧 Context 并切换——失败时旧页原样保留、旧 Context 不取消、`NavError` 记录包裹后的原因；无半提交 |
| Router 关闭后 | `Navigate/Dispatch` 丢弃并计入 `DroppedCount`（线程模型 §4） |

**Context 语义**：页面 Context = `WithCancel(Router.Context())`，每次导航新建；切换时**先构造新页、成功后**取消旧 Context（原子性要求，顺序理由见代码注释）；取消一次性发生（Go cancel 幂等性为最后防线）。

**UI 线程归属与防误用**：除 `Navigate/Dispatch/Invalidate` 外的方法仅限 UI 线程（= 根 `View.Layout` 调用方）。机制 = API 形状隔离 + 全量互斥保护（误用无数据竞争、语义不受支持）+ 测试断言"后台请求延迟到帧内生效"。v1 不做 goroutine 身份检测（Go 无受支持的机制，假阳性检测比缺位更危险）。

**与阶段 A 批准接口的偏差（两处，均由授权直接要求）**：
1. `PageFactory` 增加 error 返回——授权 §4.6 要求"页面创建失败不产生半提交"，阶段 A 的 `func(ctx) View` 无法表达；
2. `Navigate` 增加同步校验与 error 返回——授权 §2 要求"明确的未注册路径错误"（阶段 A 方案是纯异步诊断计数）。
其余与阶段 A 批准的接口逐字一致（含不导入 app 包、`View()` 接入方式）。

## 4. 关键状态转换与生命周期说明

见 §2 状态语义表。补充实现要点：

- **帧内顺序**（`drain()`，对应线程模型 §3）：排空 Dispatch 队列（FIFO，队列清空为止单轮；fn 内再 Dispatch 会在同帧继续执行）→ 应用待定导航（合并后仅最后一个）→ 渲染当前页（`renderCurrent`）。路由变更不产生自己的帧；后续帧由 Gio 事件流驱动。
- **无 goroutine**：B1 的 Router 不启动任何 goroutine（动画 ticker 等由 B2 的 `op.InvalidateCmd` 方案替代，见 §9）——"关闭窗口时所有 worker 正常退出"（线程模型 §10.7）在 router 侧 vacuously 成立，worker 退出验收属 LIFE/OS 阶段。
- **页面构造不持锁**：工厂在锁外执行（页面可回查 `Current/NavError`）；回查看到的是**导航前**状态（构造与切换非同锁原子区间）——已写入 PageFactory 注释。

## 9. B2 转场快照需要的接口条件（已预留的接缝）

1. **唯一渲染入口**：当前页渲染只经 `renderCurrent`（router.go 已收敛）——B2 在其外层包 `op.Record` 即可录制"已提交帧"，**不需要**触碰任何页面代码；
2. **自有 ops buffer**：快照必须录进 Router 自有的 `op.Ops`（app 事件循环每帧重建窗口 ops——`app.go@HEAD:302` 与 `app/app.go:102` `ops.Reset()` 双重证据）；`CallOp` 持有源 buffer 引用（`op/op.go:162-176` 源码），跨帧回放的 API 形状成立但**视觉效果未实测**（B2 第一项测试）；
3. **动画帧调度**：转场帧内追加 `op.InvalidateCmd{At}`（`op` 包源码）驱动下一帧，全程 UI 线程，无需后台 goroutine——与线程模型 §9 兼容；
4. **切换点唯一**：`applyNavigation` 成功分支是旧 Context 取消与新页挂载的唯一位置——B2 在此读取"上一帧快照 CallOp"并进入转场状态；
5. **需要新增的 Router 内部状态**（B2 自带，不动 B1 API）：快照 buffer、最近提交快照、转场状态机、`TransitionSpec`；对外 API 增量最小（`SetTransition` 等），先经负责人批准再落。
