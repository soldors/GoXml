# R8-C 证据工具使用说明（record-command.py / verify-evidence.py）

> 适用基线 `e72c478e6d59b6636b98005c73d580d6f4f7b9f0`。这两个脚本是 R8-C 新增的**随仓工具**，
> 解决 R7 复盘第 3 条"证据质量欠账"（首败 stdout 被覆盖、台账写坏、崩溃后"未运行/已运行/未知"混记）。

## 1. 这套工具做什么、不做什么

| 做 | 不做 |
|---|---|
| 真跑一条命令并把**事实**写成一行 JSONL 台账 | 不重写进程收口与 raw 捕获（`verify_examples_proc.py` / `verify_examples_proctree.py`，R6 已合入并复核） |
| 区分 **prepared / completed / recovered / unknown** 四个状态 | 不按 mtime 补造时间；不把未知记成 0 |
| **记录成功**与**业务成功**分开判定并分别给退出码 | 不把"记录失败"包装成 rc 0；不把编译/解析错误当业务红 |
| 只读校验已有台账（不修复、不吞坏行） | 不删除、不改写他人锁；不杀他人进程 |
| 按**落盘字节**重算 raw 的 bytes/SHA-256 | 不信任台账自述，也不把解码后的展示文本当权威 |

新增文件（生产实现只读，未改）：

- `scripts/evidence_schema.py`：台账 schema 与校验的**唯一**定义（写入方与校验方共用，防字段漂移）
- `scripts/record-command.py`：命令记录入口
- `scripts/verify-evidence.py`：只读证据校验器
- `scripts/test-record-command.py`：真实闭环自检（126 项）
- `scripts/test-verify-evidence.py`：校验器分支毒化（96 项）
- `scripts/mutate-evidence-tools.py`：变异取证（8 个变异必须翻红）

## 2. 记录一条命令

```bash
PY="C:/Users/admin/AppData/Local/hermes/hermes-agent/venv/Scripts/python.exe"

# 基本用法：`--` 之后是**真实 argv 数组**（shell=False，不经 shell）
"$PY" scripts/record-command.py run \
  --id build-narrow --jsonl out/commands.jsonl --log-dir out/logs \
  --cwd . --timeout 600 --expect-rc 0 \
  -- "C:/Program Files/Go/bin/go.exe" build ./internal/compiler/codegen/
```

每次运行会产出（都在**独占**目录里，永不覆盖历史字节）：

```
<log-dir>/<id>/planned.json            # prepared：打算跑什么（含 argv/cwd/环境差异/锁信息）
<log-dir>/<id>/c1/stdout.raw           # 原始字节（CRLF/NUL/非 UTF-8 全保留）
<log-dir>/<id>/c1/stderr.raw
<log-dir>/<id>/c1/result.json          # run_capture 写的事实（rc/raw SHA/收口…）
<log-dir>/<id>/verdict.json            # 本入口的判定（已写出的台账行不可覆写，判定落这里）
```

台账 `<jsonl>` **只追加**（`O_APPEND|O_BINARY`），上一行若是半行会先补一个换行再写，
绝不把两条记录粘成一行"看起来能解析"的假 JSON。

### 常用参数

| 参数 | 说明 |
|---|---|
| `--id` | 台账 id；已存在则顺延 `-2`/`-3`（不覆盖、不重复） |
| `--expect-rc N` | 业务判据期望退出码（默认 0） |
| `--expect-timeout` | 业务判据期望"超时"（与 `--expect-rc` 一起判） |
| `--env K=V` / `--go-env` / `--env-key K` | 子进程**局部**环境；`--go-env` 并入 Go 六项固定值；环境只记白名单 + 差异 + 指纹，**不 dump 父环境** |
| `--args-file P` | argv 的 JSON 数组文件：跨宿主传参保真（推荐 PS 用这个） |
| `--lock-path P --lock-mode acquire\|external` | 见第 4 节 |
| `--report P` | 本次判定的 JSON；路径已存在**直接报错退出 2**（不覆盖用户报告） |
| `--containment auto\|win-job\|none` | 默认 `auto`；能力不足时**启动前拒绝**，一个子进程都不起 |

### 退出码（调用方按此判据）

| 码 | 含义 |
|---|---|
| 0 | 记录完整可信 **且** 业务判据成立 **且** 收口已证 **且** 锁已释放 |
| 2 | 用法/环境错误（参数自相矛盾、输出路径已存在、声明外层持锁却没锁文件） |
| 3 | 没有真正启动 / **结果未知**（退出码 3 ≠ "跑过且失败"） |
| 4 | 跑起来了但业务判据不成立（rc ≠ `--expect-rc`） |
| 5 | 超时（rc 是**我们强制给的** 8，不是进程的自然退出码） |
| 6 | 收口未被证明（contained/activeAfter/cleanup 有问题）——取证可用，但别当"干净跑完" |
| 7 | 记录本身不完整（台账行写坏、raw 哈希与磁盘不符、自相矛盾） |
| 8 | 公共锁被他人持有：**本次没有发起任何子进程** |
| 9 | 自己取的锁没能释放：取证可用，但必须人工处理 |

## 3. 校验一份台账

```bash
"$PY" scripts/verify-evidence.py --jsonl out/commands.jsonl --json out/verify.json
```

退出码：`0 PASS` / `1 FAIL` / `2 用法` / `3 INCOMPLETE` / `4 UNSUPPORTED`（全部行都是历史 schema）。

判定要点：

- 逐行**严格** `json.loads`；CRLF / NUL / 非 UTF-8 只作为字节事实报告，不归一化后再判；
- 缺字段、类型错（**bool 不是 int**）、重复 id、`rcSource` 与 `timedOut` 不自洽、
  时间倒序、raw 的 bytes/SHA 与磁盘不符 → **FAIL**；
- 未启动、超时、收口未知、`recordOk=False`、`unknown` 形态、`elapsedSec` 未知 → **INCOMPLETE**（不是通过）；
- 历史别的 schema（R6 的 `r6c-2` / `r6c-selcase-1`、R7 手写台账形状）→ **unsupported**，
  不做字段级判定，**不因不匹配就叫数据造假**；
- `--json` 路径已存在即报错，不覆盖已有报告；校验过程只读，被校验文件字节不变。

对 R7 作者台账的实测分类（只读复核，原件未改，sha256 `fe5e14b3…`）：
28 行 = 6 行 `bad-json`（FAIL，逐行点名）+ 22 行 `unsupported`（R7 手写台账形状）。

## 4. 锁（Go 重负载）

```bash
# 自己取锁 → 跑 → finally 释放（只按自己的 token）
"$PY" scripts/record-command.py run --id go-heavy --jsonl out/c.jsonl --log-dir out/logs \
  --lock-path D:/Codes/Goxml-night-reports/2026-10-27/heavy.lock --lock-mode acquire \
  --lock-agent workbuddy --lock-task r8-heavy -- <go 重负载命令>

# 外层已持锁：核对持有者 token，不修改或释放外层锁
"$PY" scripts/record-command.py run --id go-inner --jsonl out/c.jsonl --log-dir out/logs \
  --lock-path <同一路径> --lock-mode external --lock-token <外层返回的token> -- <命令>
```

规则：给了 `--lock-path` 就必须挑明 `--lock-mode`（不能默认暗中绕锁）；锁被他人持有时退出码 8、
**不发起子进程**、不删他人锁；硬终止时自己的 token 留在 `planned.json` 里，可据此
`python verify-examples-lock.py release <token> --lock-path ...`——**禁止按年龄删锁**。

## 5. 中断与恢复

- 软中断（Ctrl+C / Ctrl+Break）：第一次信号**不放弃子进程**，让本次执行按有界超时收口再落盘，
  台账行带 `interrupted`；第二次信号才放弃收口。
- 硬终止（崩溃/被杀）：`finally` 不承诺执行，此时 `<run-dir>/planned.json` 是唯一可定位的
  "打算跑什么"证据，**prepared 不能用来声称零启动**。恢复：

```bash
"$PY" scripts/record-command.py recover --run-dir out/logs/<id> --jsonl out/commands.jsonl
```

恢复只认 `run_capture` 写的**最终版** `result.json`（带 `phase='prepared'` 的那版不算）；
拿不到就写成 `unknown` 形态：`started`/`rc`/`rcSource` 全为 `None`，`recordOk=False`，
校验器判 INCOMPLETE——**不补造时间，不把未知记成 0**。

### 独立复核后的收紧

普通用法错误和写盘异常也经过取锁宿主的 `finally`，不能只在成功尾部释放。
恢复时保留原 `result.json` 的 bytes/SHA 承诺，以当前文件核验；字节已变必须拒绝，
不会把新哈希写回历史承诺。恢复只认本 run 的 `c1`、原 argv/cwd 和 caseDir。

校验器交叉核对最终 helper 结果的退出/身份/时间/收口/raw 字段；只有同名文件存在
不构成证据。NaN、Infinity、重复 JSON 键、错误类型、无时区时间均不能判 PASS。
`--no-disk` 只检查结构，最多 INCOMPLETE；混有 unsupported 行也不能宣称整份通过。
完整证据中的业务失败仍可通过证据校验，业务门禁须另读 `business.pass` 和真实 rc。
这些检查证明材料内部一致，不提供防恶意同时改写全部证据的签名认证。

时间字段 `startedUtc/endedUtc` 来自 helper 的实际时刻，`elapsedSec` 来自单调时钟差值；
当前不持久化两个单调时钟端点，不声称可从台账恢复端点。原作者 126/96 统计是原版历史
结果；补修与组合后的实际检查统计见本轮验证记录，不冒充同一次运行。

台账行在正常释放锁前追加，其中 `lock.released` 可为未知；它不证明后来释放成功。
锁释放须另核本次 stdout/`--report` 的 `lockReleased` 和真实锁路径，不能用单纯的
证据校验 PASS 代替此检查。最终发布还要求调用方业务成功且自有锁已释放。

## 6. 自检 / 变异取证

```bash
"$PY" scripts/test-record-command.py   --work <空目录>    # 真实闭环：126 项
"$PY" scripts/test-verify-evidence.py   --work <空目录>    # 毒化分支：96 项
"$PY" scripts/mutate-evidence-tools.py  --work <目录> --out <report.json>  # 8 变异必须翻红
```

`test-record-command.py` 真起进程、真超时、真造"父退孙活"、真硬 kill 后恢复；
另有一个**不在被测 job 里**的见证进程，收口全程不得影响它（其收口放在外层 `finally`，有界）。

## 7. 已知边界

- 整树收口是 **Windows Job Object**：非 Windows / Job 不可用时启动前拒绝（`containment=refused`）。
- `containment=none` 会标 `restrictedSafe=False`，`compute_ok` 必定拒绝——受限门禁不要用。
- 超时后的 rc=8 是强制码；`rcSource=forced-on-timeout` 与 `timedOut` 必须同时出现，否则校验器判红。
- 本工具**不增加第六个示例**，不改 PS 注册/示例/CLI/Codegen，不引入第三方依赖。
