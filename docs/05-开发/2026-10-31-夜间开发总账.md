## 6. 本次整理新增的一条实测（把评审结论变成事实）

另一会话对 Image/Router 的评审记有「1×P2 + 4×P3」，其中 P2 是「**资产路径大小写不一致 → `go build` 晚失败**」。
本次整理把它做成可复核实验（临时模块，`//go:embed "assets/Logo.PNG"` 指向磁盘上的 `assets/logo.png`）：

| 场景 | 结果 |
|---|---|
| Windows 本机 `go build` | **rc=0**（不报错） |
| 生成的 `embed.FS` 键 | **`Logo.PNG`**（跟随声明大小写，不是磁盘大小写） |
| `ReadFile("assets/Logo.PNG")` | **err=nil, len=5**（自洽，不会 panic） |
| `GOOS=linux GOARCH=amd64` 与 `GOOS=darwin GOARCH=arm64` 交叉编译（Windows 主机） | **均 rc=0**（掩盖问题：从 Windows 发起的 CI 交叉构建抓不到） |
| 原生大小写敏感文件系统上构建同一生成文件 | **推断为 embed 无匹配 → `go build` 失败**（本机无 Linux/macOS，**未实机验证**） |

代码侧确认：`internal/compiler/pipeline/assets.go` 与 `internal/compiler/codegen/assets.go` 中
`EqualFold` / `ReadDir` 命中数为 **0**——即门禁只校验存在性、边界、体积与解码，**不校验声明大小写与磁盘一致**。
后果不是错误生成，而是**错误出现在错误的阶段**（用户看到 `go build` 的 embed 报错，而非带源码位置的
`CODEGEN-ASSET-*`）。若要修，位置就在 `pipeline/assets.go` 的 `os.Stat(full)` 前后：用 `os.ReadDir` 逐级比对
磁盘拼写，不一致就发 `CODEGEN-ASSET-001` 并给出实际拼写。本线未改（属并行在制目录 + 需负责人放行）。

同时指出一个取证缺口：那条「1×P2 + 4×P3」的评审**在主仓和 `night-batch-2026-10-30` 取证目录里都找不到落盘文件**
（`grep -rl "goxmlAssets\|TASK-IMAGE-001"` 于 rounds 根目录返回空），4 项 P3 的明细因此无法核对。
建议评审方补一份仓库内文档，否则该结论只能以「另一会话说过」的形式存在。
