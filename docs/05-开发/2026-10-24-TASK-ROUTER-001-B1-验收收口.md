### 2.2 源码证据（本轮 `go list` 实测，精确到 import 层）

| 层 | 导入 | 结论 |
|---|---|---|
| 生产包 `package router`（router.go） | `context errors fmt sync sync/atomic + gioui.org/{layout,widget/material}` | **不含 app** ✅ |
| 包内测试（router_test.go，`package router`） | 上者 + `testing` + `gioui.org/op` | **不含 app** ✅ |
| 外部测试包（integration_test.go，`package router_test`） | 上者 + `time` + **`github.com/goxml/goxml/pkg/runtime/app`** + router | 唯一 app 导入点 |

辅助证据：包声明核对（router.go/router_test.go=`package router`，integration_test.go=`package router_test`）；`grep -l "pkg/runtime/app" pkg/runtime/router/*.go` 会命中 router.go，但那是**包注释文本**提及「不导入 pkg/runtime/app」，非 import——以 `go list` 为准。app.go / 字体在制文件零修改（前后 git status 一致）。

### 2.3 风险评估

- **有**：目录内出现 app 导入使「router 目录与 app 解耦」的叙事多一个例外；若未来有人把测试文件误移入包内（package router），会静默形成生产依赖。
- **无**：生产依赖（go list 实证）、循环依赖、对 app.go 的修改、对字体在制文件的依赖。

### 2.4 裁决建议（三选一，PM 建议为 A）

- **A（建议）追认保留**：理由——外部测试包（`_test` 后缀包）是 Go 标准实践，`go list` 三层证据链清晰；真实事件循环兼容性验证（13 测试中唯一的生产入口级证据）依赖它；删除的代价是该项验证降级为「未验证」。配套护栏：在 `integration_test.go` 头注释与 B2 卡中固化「仅外部测试包可导入 app；包内（`package router`）文件出现 app 导入即违规」——该约束可写进 B2 验收检查项（如 docgate/自定义门禁的后续增强项，不强求本轮）。
- **B 迁出**：把集成测试移到 `pkg/runtime/router/testdata/` 下的独立包（同构 `testdata/windowprobe` 惯例）。代价：不再是 `go test ./pkg/runtime/router/...` 的组成部分，验收命令覆盖不到它，需要单独的验收入口——与原任务卡验收命令冲突，**不推荐**。
- **C 删除**：真实循环验证降级「未验证」，待生产集成（B2-3）时在新位置重建。若负责人从严解释授权，选 C，B2 卡已按此准备（集成测试改挂生产集成阶段）。
