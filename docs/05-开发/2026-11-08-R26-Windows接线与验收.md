## 公共命令

```powershell
goxml watch C:/work/my-module --entry ./cmd/app
goxml watch C:/work/my-module --entry ./cmd/app --exclude-dir logs -- --example-arg
goxml preview C:/work/my-module/view/static.gxml --build-only
goxml preview C:/work/my-module/view/static.gxml --tool-root C:/work/Goxml
```

Watch 必须显式指定模块内 main 包。默认 50ms 轮询、100ms 防抖、每代 generate+build
合计 120s；`--poll-ms`、`--build-timeout-seconds` 可调整，目录排除可重复。每代使用
当前工具 exe 执行真实 `generate --check`，再构建唯一代次 exe。失败/取消/stale 不发布；
成功构建前旧进程继续，成功后先停旧树再起新代。新代启动失败不保证回滚，重启丢失内存
状态，没有 Hydration、零停机握手或模块外输入监听。

Ctrl+C 取消构建/监听并清理自有树；工具取消另有最多3s清理宽限，失败明确上报。
模块内运行日志应放 `.goxml` 或用 `--exclude-dir` 排除，避免输出触发自身重建。
生成物所有权由 Manifest 与真实保护头/Source 匹配共同证明；两次扫描之间的用户保存
按新 Diff 合并，不被旧的 owned-only 通知吞掉。

Preview 只支持模块内无 VM 的纯静态页，复用静态布局、Def/Slot、Image、Expanded 基础范围；
VM、绑定/事件、ThemeRef、Button/Input 拒绝。`--build-only` 不开窗，默认启动专用单窗宿主。
`--keep-host-dir` 保留成功宿主，失败保留证据。构建上限默认300s，可调整。
需匹配的 goxml 源码/模块缓存根及本地依赖；自动定位失败时传 `--tool-root`，不承诺
任意单 exe 脱离源码/依赖离线运行。宿主不导入业务包、不执行用户 main/init，不改用户
生成物/Manifest/成功缓存；损坏 Manifest 先拒绝。资产复制有效 overlay 字节，owned
输出不能通过伪装图片绕过门禁，临时目录清理核对一次性 token。

## 组件范围

`pkg/widgets` 提供 ContextMenu 与 Modal。调用方保证同一时刻只有一个活动弹层，并在背景
之后布局。菜单固定条目、视口钳制、禁用项、外点/Escape关闭、高菜单滚轮访问；无可视
滚动条和拖选。Modal 遮罩点击只报告，不自动关闭；Escape关闭，下一次 Layout回交焦点。
打开转换只请求一次焦点，重复Open不抢内容焦点。全捕获消费者可能先吃Escape，须按名
消费或转发。关闭帧不提交过期弹层Ops，首次后续背景操作无需额外空帧。
无全局弹层仲裁、DataGrid、GXML新标签或ThemeRef。

## 真实执行与失败路径

- 公共 Watch：首次启动、cwd/argv、生成失败保旧、build失败保旧、修复换PID、取消收口。
- 公共 Preview：准入/拒绝、有效资产复制、owned与Manifest守卫、init canary未执行、用户快照不变。
- Watch扫描重叠、构建后取消、构建中目录丢失、损坏Manifest、工具构建失败均有行为回归。
- 可编译源码副本变异分别打红退出清理、owned集合、关闭帧命中、滚轮方向与进程归属时序，恢复绿。
- 自有根进程挂起创建→加入Job→恢复。取消前保留Job内进程句柄，按同一截止时间执行tree终止、
  Job清空和句柄退出等待；获取凭据/终止/超时错误保留。ActiveProcesses为0不单独充当退出凭据。

原生观察由 Computer Use 执行，不冒称负责人亲眼签字：

- Preview：文字、PNG、Def/Slot/Expanded显示、最大化重绘、标题栏关闭rc0、宿主目录移除、无幸存。
- Watch：1→2代PID变化；第3代坏GXML未发布且旧窗口仍可点击；恢复第4代后旧PID退出；定向
  Ctrl+Break取消，CLI rc0、记录器contained、activeAfter0。最终620cb34二进制另做原生启动/取消窄复验，窗口真实显示、stderr空、rc0、activeAfter0、无自有窗口。
- Widgets：禁用忽略、外点阻断背景、向下滚至第24项单次触发、Modal遮罩不关、ASCII输入、
  Escape与焦点回交；菜单/Modal关闭后的首次背景点击有效。

旧 Preview 宿主关窗退出2、原生组件首败、错误探针前提和race首败均保留。Preview改为专用
单窗Gio生命周期并转发stderr，通用App.Run退出策略另记
[BUG-028](../07-Bug/BUG-028-Windows-App-Run独立进程关窗退出.md)，没有偷偷改共享Runtime API。
自有Widgets场景显式退出策略只属于该场景。

## 性能口径

正式[预算§3.2](../03-架构/性能预算与优化策略.md)将热路径定义为Layout，且有静态页面限定。
复用Ops、预热后组件Layout单独测量：菜单8508ns/op、Modal1104ns/op，均0B/op、0allocs/op。
每帧实际执行input.Router.Frame，但该部分在Layout计时区外。

含Router.Frame：菜单13095ns/op、272B/op、6allocs/op；Modal1379ns/op、48B/op、2allocs/op；
仅Gio可聚焦tag对照约629ns/op、48B/op、2allocs/op。第三方焦点排序分配仍存在，不能称
完整帧零分配。这是无GPU微基准，不证明原生冷启动、M1/RSS或整应用<5%开销。

外部Gio泛型排序实验使完整帧零分配，但未接纳；仓库go.mod/go.sum和模块缓存没改。
先前把完整Frame分配当本轮Layout硬门槛的判断已撤销，BUG-002待决与整项目性能目标不变。
