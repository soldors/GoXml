## 1. 核心架构决议表
| 决策编号 | 决议项 | 选定方案 | 废弃方案与理由 |
|---|---|---|---|
| D-001 | 渲染引擎 | Gio (立即模式 GPU 渲染) | WebView (内存过高/IPC卡顿), Fyne (反射损耗大) |
| D-002 | 声明式语法 | GXML (Vue 绑定 + Svelte 控制流) | React JSX (需内嵌表达式解析器), SwiftUI (Go缺少尾随闭包) |
| D-003 | 状态管理 | 原生 Struct + 编译期 AOT 浅对比 Diff + MacroOp 局部失效 | Signals (语法繁琐), TEA (样板代码过多), 运行时反射 (CPU开销大) |
| D-004 | 热重载策略 | 双进程 Live Reload (100ms防抖 + JSON状态恢复) + 静态预览器 | 运行时解释器真热重载 (开发与生产易错位), Go Plugin (平台缺陷) |
| D-005 | 路由架构 | 单窗口 <Router> (MacroOp 转场快照) + <OSWindow> 逃生舱 | 全系统窗口路由 (跨平台层级与焦点混乱) |
| D-006 | 样式系统 | 强类型 $Theme Struct + <Def>/<Slot> 宏展开 | 外部 .gcss (需写庞大CSS解析器并存在运行时选择器匹配损耗) |
| D-007 | 原生系统交互 | Zero-CGO (Win: Syscall, Linux: D-Bus, Mac: Purego) | systray 等带 CGO 库 (破坏 Go 一键秒级交叉编译能力) |
