## 固定测试范围

- 契约测试：`contracts/` 必须 100% 通过。
- 编译器核心：Parser/Analyzer/Codegen 行覆盖率 >= 85%，核心解析路径 >= 90%。
- Golden 测试：验证生成代码确定性、格式、包名、import 和无反射约束。
- 端到端测试：Parser -> Analyzer -> Codegen -> gofmt -> go build 全链路通过。
- 竞态测试：Runtime、Lifecycle、Hydration、Watch 和平台回调执行 `go test -race`。
- 分平台构建：完整生成应用在 Windows 用 `CGO_ENABLED=0`，Linux/macOS 用 `CGO_ENABLED=1` 且在目标平台构建（`make build-windows` / `make build-linux` / `make build-darwin`）。三端 `CGO_ENABLED=0` 已由 [ADR-0007](../03-架构/adr/ADR-0007-Zero-CGO降级为Windows侧约束.md) 判定为不可行目标。
- 平台 smoke test：在宿主机验证剪贴板、文件弹窗、托盘和菜单的成功、取消、权限和不可用分支。
- 性能压测：生成版对比手写 Gio，固定环境下单帧 CPU 损耗目标 <= 5%，同时报告绝对 ns/op 与 allocs/op；稳定帧 `allocs/op` 必须为 0。完整不变量见 `docs/03-架构/性能预算与优化策略.md`。
- 字体与文本：CJK 渲染、系统字体缺失兜底、中文 IME 输入与候选框定位见 `docs/03-架构/字体与文本渲染策略.md`。
- 生成代码不以行覆盖率作为主要指标，以编译、Golden、AST 和运行时 E2E 作为证据。

## 绑定显示缓存专项

专项命令：

```text
go test -count=1 -run '^TestB3' -v ./internal/compiler/codegen
```

必须记录以下证据：

- 稳定值连续布局命中同一槽位，且显示结果一致；
- 显示字符串变化后重新录制并产生新结果；
- 约束、主题等渲染上下文变化会使槽位失效；
- 动态绑定页面不会被错误地整体固化为静态页面；
- 预热后的稳定布局 `B/op == 0`、`allocs/op == 0`。

以下内容仍属于未闭环验收，不得用 B3 通过替代：不同原值映射到相同显示串、读取/转换错误恢复、ViewModel 变化自动刷新、`<For>` 变量绑定、动态父节点内局部静态子树以及 Gio 内部 shaping 调用次数。

## 门禁分层

- 快速反馈：`make contract-lint`、`make test`、`go test -count=1 -run '^TestB3' -v ./internal/compiler/codegen`。
- 提交门禁：`make verify`；当前只包含 `contract-lint` 和 `test`。
- 完整验证：`make test-all`、`make test-race`、目标平台构建和宿主 smoke。
- 发布阻断：Golden、E2E、生成代码、性能断言、状态更新、跨平台宿主和字体/IME 中任一必测项没有证据，都不能签发发布单。
