# 测试与质量门禁规范

- 状态：设计冻结；部分文档门禁已实现并有正反例，其余自动检查与人工审计仍待完成
- 冻结日期：2026-10-18
- 适用范围：contracts、compiler、runtime、platform、CLI、生成代码和发布流程

## 1. 测试目标

测试不仅验证功能存在，还必须验证 Goxml 的架构不变量：

- Windows 侧 Zero-CGO；Linux/macOS 按 Gio 后端要求启用 CGO。
- GXML 编译期完成解析和宏展开。
- 生成代码无运行时反射 Diff。
- 当前状态更新、绑定缓存和事件输入边界可复现；AOT 状态 Diff 结果仅在未来启用该方案时验收。
- 平台调用不阻塞渲染线程。
- 生成输出可重复且失败不覆盖旧产物。

## 2. 测试分层

### 2.1 契约层

覆盖 `contracts/` 的 IR、诊断、生命周期和主题接口。

- 目标：核心契约 100% 通过。
- 命令：`make contract-lint`
- 失败处理：任何契约变更必须同步 ADR、规范和测试。

### 2.2 编译器单元层

覆盖 Parser、属性解析、Analyzer、Macro Expander 和 Codegen 的纯函数行为。

- Parser/属性转换：行覆盖率 >= 90%。
- Analyzer/Codegen：行覆盖率 >= 85%，分支覆盖率作为补充指标。
- 必测：合法输入、非法输入、边界输入、精确源码位置和诊断码。

#### 2.2.1 诊断码门禁（`internal/compiler/diagdoc`）

诊断码的「是否已实现」不能靠人工维护的清单声明——**手写清单会滞后，且会自证**。

历史教训：`diagdoc` 曾用 `frozenCodes` 记录「已定稿但未实现」的码，
Analyzer 的 11 个码全部实现后，清单仍声称它们「不会发射」；
旧测试只校验 `implementedCodes` 与 `frozenCodes` 两个手写清单互不重叠，
从不读取真实代码，因此一直是绿的（见 `docs/06-测试/Analyzer验收报告.md` §3.3）。

门禁必须**从源码推导事实**，检查四件事：

| 检查 | 失败标准 |
|---|---|
| 每个 `Code*` 常量都在所在包内有调用点 | 常量已定义但从未作为诊断发射（死常量）——看起来已实现，实际永不出现 |
| 每个常量都登记在 `implementedCodes` | 新增码未登记，目录与代码脱节 |
| `implementedCodes` 的每个符号真实存在 | 登记了不存在的符号（虚报） |
| `frozenCodes` 的码确实没有对应常量 | 声称未实现，但代码中已有 |

实现方式：用 `go/ast` 解析各阶段包的**非测试** `.go` 文件，
收集 `Code*` 常量声明，以及作为**调用实参**出现的 `Code*` 标识符。
只认调用实参，避免把常量声明本身（`CodeX = contracts.CodePrefixY + "-001"`）算作发射。

适用范围：`parser`、`expander`、`analyzer` 三个发射诊断的阶段包。

命令：`go test ./internal/compiler/diagdoc/`

> 该门禁本身必须能被反向验证：临时加入一个从不发射的常量，门禁应失败。
> 无法失败的校验不构成门禁。

#### 2.2.2 编排层门禁（`internal/compiler/pipeline`）

编排层负责阶段串联与失败门禁。它的门禁必须验证**真实调用链**，而不是单个 API 的返回值。

要求（编译编排契约 §3、代码生成输出契约 §13 第 20 条）：

| 情况 | 必须证明 |
|---|---|
| Analyzer 为 `StatusPartial` | Codegen **未被调用**（调用计数为 0），无产物 |
| Analyzer 为 `StatusBlocked` | 同上 |
| Parser / Expander 有诊断 | 后续阶段未被调用 |
| Codegen 返回错误 | 无 `Artifact`，不写文件 |
| 提交失败 | 目标文件保持原样，无临时文件残留 |

**证据形式**：调用计数 + 目录快照。不能只断言「返回了 error」——
那只能证明管线停了，不能证明它没调 Codegen。

**失败标准**：

- 用「注入失败的 Codegen」以外的方式观察到 Codegen 被调用 → 门禁失效；
- 运行前后目录有差异 → 失败；
- 把「单元测试通过」当作「端到端门禁已验证」→ 结论无效。

命令：`go test ./internal/compiler/pipeline/`

> 第 20 条在 `d5c083b` 前一直标为「不可执行」。这类长期未验证项必须在
> 关闭时留下实测证据，不得仅凭实现完成就改判。

### 2.2.3 文档门禁（`internal/docgate`）

文档门禁由 `go test ./internal/docgate` 定向执行，并由 Makefile 的 `test`/`verify`
通过 `go test ./...` 间接执行。当前自动检查范围：

| 检查 | 失败标准 |
|---|---|
| 近期提交的 dev-log 覆盖 | 非日志维护提交未在开发日志中出现 |
| Markdown 行内本地链接 | 目标文件或目录不存在 |
| WBS 任务卡 | WBS 中任务没有同 ID 任务卡 |
| WBS 依赖 | 依赖任务未登记，或任务依赖存在循环 |

断链、未登记任务、缺失依赖和依赖循环均由针对实际校验函数的负例测试验证。
门禁扫描围栏代码块之外的行内本地链接；目前不校验引用式链接和标题锚点。
它也不判断规范语义冲突、文档事实准确性或 P0 需求追踪完整性，这些仍由人工审计负责。

命令：`go test -count=1 ./internal/docgate`

本地验证若无法运行 `make verify`，应按 Makefile 当前目标执行底层 Go 命令并如实记录；
底层命令通过不应被表述为实际运行了 Makefile 目标。

### 2.3 Golden 层

固定 `.gxml`、ViewModel 和期望生成 Go 文件，验证：

- 生成结果逐字节稳定。
- `go/format.Source` 后无额外变化。
- import、包名和符号名稳定。
- 生成文件包含保护头。
- 不包含 `reflect`。

### 2.4 端到端层

至少覆盖完整链路：

```text
.gxml -> Parser -> Macro -> Analyzer -> Codegen -> gofmt -> go build
```

端到端测试必须包含：布局、绑定、事件、If、For、Def、Slot、主题和生成文件重建。

### 2.5 Runtime 与竞态层

覆盖当前已实现的状态通知、绑定缓存、事件输入、生命周期、路由、Hydration、Dispatcher 和异步平台回调；AOT Diff、Dirty Mask 及循环协调仅在对应方案批准并进入开发批次后纳入实现验收。

- 所有 Runtime 并发测试使用 `go test -race`。
- 必测页面卸载后的异步结果丢弃。
- 必测重复 Key、nil/空 Slice、指针切换和上下文变化。

### 2.6 平台层

平台测试分为：

- **平台构建测试**：Windows 在 `CGO_ENABLED=0` 下构建；Linux/macOS 在目标平台以 `CGO_ENABLED=1` 构建完整生成应用。
- **宿主机 smoke test**：真实调用剪贴板、文件弹窗、托盘和菜单。
- **能力降级测试**：服务缺失、权限不足、用户取消和系统错误。
- **线程测试**：确认平台调用不运行在 `Layout`。

### 2.7 性能层

性能测试必须同时提供生成版和手写 Gio 对照版，记录：

- Go 版本、Gio 版本、操作系统、CPU/GPU。
- 窗口尺寸、DPI、数据量和场景配置。
- 预热次数、采样次数、p50、p95。
- ns/op、allocs/op、常驻内存和冷启动时间。
- 若启用 AOT Diff，记录命中率和 Macro 重录次数；当前版本记录绑定缓存命中/失效和静态 Macro 重录边界。

性能不变量、预算数值与单机基线见 `docs/03-架构/性能预算与优化策略.md`。以下为**必须自动化断言**的部分（`make bench-assert`）：

| 断言 | 阈值 | 依据 |
|---|---|---|
| 静态页面稳定帧 `allocs/op` | **== 0** | INV-PERF-2 |
| 静态子树宏重录次数（稳定帧） | **== 0** | INV-PERF-1 |
| 10,000 行虚拟列表单帧 | **≤ 1 ms** | INV-PERF-3 |
| 10,000 行 vs 100,000 行耗时比 | ≤ 1.5× | INV-PERF-3 |
| 生成源码含静态子树 `CallOp` 字段 | 是 | ADR-0006 |
| 生成源码不含 `fmt.Sprintf` 于 `Layout` 路径 | 是 | INV-PERF-4 |

文本 shaping 与 CJK 渲染的专项要求见 `docs/03-架构/字体与文本渲染策略.md` §7。

## 3. 覆盖率分层

覆盖率不能用一个数字代表整个项目：

| 范围 | 目标 | 主要证据 |
|---|---:|---|
| `contracts/` | 100% 契约测试通过 | 单元测试、vet |
| Parser/Analyzer/Codegen | 行覆盖 >= 85%，核心解析 >= 90% | 单元、Golden、AST 断言 |
| Runtime | 行覆盖 >= 85% | 单元、竞态、生命周期测试 |
| Platform 公共层 | 行覆盖 >= 85% | 模拟能力、错误和线程测试 |
| Platform 原生后端 | 以宿主 smoke 为主 | Windows/Linux/macOS 矩阵 |
| 生成代码 | 不用行覆盖率衡量 | 编译、Golden、运行时 E2E |

生成代码不直接追求行覆盖率；必须验证它能编译、运行、响应事件并满足无反射约束。

## 4. 测试矩阵

### 4.1 编译矩阵

**按平台区分 CGO 开关**（依据 [ADR-0007](../03-架构/adr/ADR-0007-Zero-CGO降级为Windows侧约束.md)，2026-10-18 真机实测）：

```text
# Windows：零 CGO（唯一强制零 CGO 的平台）
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 make build-windows

# Linux：必须开 CGO，且需系统 -dev 包
CGO_ENABLED=1 GOOS=linux   GOARCH=amd64 make build-linux

# macOS：必须开 CGO，且必须在 macOS 上执行
CGO_ENABLED=1 GOOS=darwin  GOARCH=arm64 make build-darwin
```

约束：

- 构建矩阵必须覆盖**完整生成应用**，不得只构建 `pkg/platform`。
- **禁止**再声明"三端 `CGO_ENABLED=0` 交叉编译"作为门禁——该目标在 Linux 上已穷举 5 种 build tag 组合验证为不可实现。
- **依赖回归测试**：断言 Linux 产物的 `readelf -d` `NEEDED` 列表与平台矩阵 §4.2 一致，防止悄悄新增系统依赖。

### 4.2 语法和诊断矩阵

- GXML 根节点、标签、属性和重复属性。
- EdgeInsets 的 1/2/4 参数。
- Color、Theme、Binding、Event。
- If/Then/Else 和 For 作用域。
- Def/Slot 展开、重复定义和递归定义。
- 错误码、文件、行、列和源码范围。

### 4.3 输出和确定性矩阵

- 连续生成两次的 SHA-256 相同。
- import 冲突别名稳定。
- 生成失败时旧文件内容和时间保持不变。
- Manifest 清理不删除用户文件。
- 缓存命中和 `--no-cache` 的输出一致。

## 5. 标准质量门禁

目标门禁命令：

```text
make setup
make contract-lint
make lint
make test
make test-race
make build-windows      # 零 CGO
make build-linux        # CGO=1，需系统 -dev 包
make build-darwin       # CGO=1，需 macOS
make test-golden
make test-e2e
make test-generated
make benchmark
make bench-assert
```

> 注意：`-race` 在**所有平台**都要求 `CGO_ENABLED=1`（`runtime/race` 硬约束），
> 因此 `test-race` 不能与 `build-windows`（`CGO_ENABLED=0`）合并执行。
> 二者是独立目标，CI 中应分 job 运行。

Makefile 目标必须按“可执行”“显式失败占位”“目标平台限定”三类记录，不能因为目标名称存在就视为门禁通过。当前状态如下：

| 目标 | 当前状态 | 说明 |
|---|---|---|
| `setup` | 可执行 | `go mod tidy` |
| `contract-lint` | 可执行 | contracts 的 vet 与测试 |
| `lint` | 环境依赖 | 先执行 `contract-lint`，再要求本机安装 `golangci-lint` |
| `test` | 可执行 | `CGO_ENABLED=0 go test -v -cover ./...`，适合前端与纯 Go 包 |
| `test-all` | 可执行但需 CGO | `CGO_ENABLED=1 go test -v -cover ./...`，依赖 C 工具链/平台库 |
| `test-race` | 可执行但需 CGO | `CGO_ENABLED=1 go test -race ./...`；不得与 Windows 零 CGO 构建合并 |
| `build-windows` | 可执行 | Windows amd64/arm64，`CGO_ENABLED=0` |
| `build-linux` | 目标平台限定 | Linux amd64，`CGO_ENABLED=1`，需 Linux 系统库 |
| `build-darwin` | 目标平台限定 | macOS arm64/amd64，`CGO_ENABLED=1`，需 macOS/Xcode CLT |
| `verify` | 可执行的当前门禁 | 目前只包含 `contract-lint` 和 `test`，不代表完整发布验证 |
| `test-golden`、`test-e2e`、`test-generated` | 显式失败占位 | 等待对应测试资产和编排链路落地 |
| `benchmark`、`bench-assert` | 显式失败占位 | 等待基准套件和性能断言落地 |

`make test-all`、`make test-race`、分平台构建和宿主 smoke 不属于当前 `make verify` 的隐含步骤，CI 必须显式编排。完整状态以仓库根目录 `Makefile` 与 [发布单](../10-发布/发布单.md) 为准。

以下是绕过 Makefile 时用于诊断或逐项复核的底层等价命令；日常入口仍以 Makefile 目标及其状态表为准：

```text
gofmt -l .                                   # 格式
go build ./...                               # 构建
go vet ./...                                 # 静态检查
go test ./...                                # 单元测试
go test -cover ./...                         # 覆盖率
go test ./internal/compiler/diagdoc/         # 诊断码门禁（AST）
```

## 6. CI 规则

- 每次提交执行契约、静态检查、单元测试、Golden 和生成代码检查。
- 主分支执行**分平台**构建矩阵：Windows 用 `CGO_ENABLED=0`，Linux/macOS 用 `CGO_ENABLED=1` 且各自在对应 Runner 上。
- **不得**把"三端 `CGO_ENABLED=0` 交叉编译"作为 CI 门禁——该目标已被实测否决（ADR-0007）。
- Linux 构建 job 必须预装平台矩阵 §4.1 列出的 `-dev` 包；macOS job 必须装 Xcode CLT。
- 平台宿主 smoke test 按平台 Runner 执行。
- 竞态测试不得降级为普通测试。
- Golden 变更必须同时提交输入、输出和变更说明。
- 性能基准只在固定环境比较，不把不同 Runner 的数字直接混合。

## 7. 测试数据与环境

- 测试固定时区、Locale、随机种子和临时目录。
- 生成文件中的路径必须是项目相对路径。
- 禁止测试依赖公网、用户主目录或本机已有桌面状态。
- 平台 smoke test 对不可用能力必须显式标记 `unsupported`，不能静默跳过。
- 验收报告记录提交、Go 版本、平台、覆盖率和性能环境。

## 9. 发布阻断条件

出现以下任一情况不得发布：

- Windows `CGO_ENABLED=0` 构建失败，或 Linux/macOS 在对应宿主机以 `CGO_ENABLED=1` 构建失败。
- 生成代码包含 `reflect` 或运行时 XML/CSS 解析。
- Golden 输出不稳定。
- 生成失败会覆盖旧产物。
- Runtime 或 Platform 存在竞态。
- 主窗口被同步平台调用阻塞。
- 核心编译器覆盖率低于门槛且没有批准的例外。
- 性能结果缺少可复现环境和手写 Gio 对照。
- 静态页面稳定帧 `allocs/op` 不为 0（INV-PERF-2 未满足）。
- 大列表未虚拟化导致单帧超过预算。
- 中文字符渲染为空白或豆腐块，或中文 IME 不可用。
