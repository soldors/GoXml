# I1 IME / 输入法人工验收（证据：为何记为未验收）

状态：**未验收**（不是通过，也不是失败或阻塞）。

## 为什么不能由自动化替代

IME 行为依赖真人键盘交互与系统输入法状态机，自动化无法覆盖以下环节：

1. 候选词窗口的弹出与选择
2. 组合输入（composition）过程中的中间态显示
3. 上屏（commit）时机与文本同步
4. 中英文切换、全角半角
5. 输入框在组合态下的光标与选区行为

## 当前仓库的相关实现

- `internal/compiler/codegen/input.go` —— `<Input>` 生成逻辑
- `internal/compiler/codegen/input_acceptance_test.go` / `input_sync_test.go` /
  `input_conflict_test.go` —— 均为**程序化**读写同步与冲突测试，
  **不涉及** IME 组合态，不能替代人工验收
- `examples/demo/main.go` —— 含 `Editor` 相关演示，可作为人工验收入口

## 记未验收的依据

截至 2026-10-23，本轮测试矩阵**未执行**任何 IME 人工验收，也没有相应的人工执行记录。
因此按四态区分记为「未验收」，不得计入通过。

## 若要验收，至少需要记录

- 操作系统与输入法（如 Windows + 微软拼音）
- Gio / Go 版本、构建方式
- 操作步骤与每一步的实际表现
- 组合态与上屏后的文本是否与 ViewModel 一致
- 异常情况（切换输入法、失焦、窗口缩放）的表现
