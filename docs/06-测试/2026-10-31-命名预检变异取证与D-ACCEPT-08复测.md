## 2. D-ACCEPT-08 现状复测

### 用例已修（非本轮所改）

`pkg/runtime/app/font_lazy_strict_test.go:136-138` 已改用**全新 Provider**：
`theme.NewProvider(theme.ProviderOptions{})`。注释 124-134 载明这正是 D-ACCEPT-08 的修法，并明确
「**断言本身未放宽**：仍然要求 `LoadElapsed > 0`，没有改成 `>= 0`、没有删除、没有加人为延迟、也没有按 `ProbeRan` 做条件放行」。
代码核对：`:177` 仍为 `if rep.LoadElapsed <= 0 { t.Errorf(...) }`。

### 实测

命令：`go test ./pkg/runtime/app -count=1 -v`，**整包重复 10 次**，克隆 HEAD `a2dcff94`、工作树干净。

| 指标 | 结果 |
|---|---|
| 目标用例 PASS / FAIL | **10 / 0** |
| 整包 `rc=0` | **10 / 10** |
| `notFoundCount`（判别力护栏：正则是否真匹配到结果行） | **0** |
| 总耗时 | **85.375 s**（全量 10 次整包） |

`LoadElapsed` 逐次实测：

```
103.8628ms  105.3503ms  119.0252ms  119.1872ms  121.158ms
122.2513ms  122.5331ms  124.1723ms  128.5633ms  140.1508ms
```

相对本机 `time.Now()` 步长约 0.5 ms，有**约 200–280× 余量**（原缺陷是被解析缓存短路后掉到 0.5–1 ms，只剩 1–2 个时钟步）。

### 结论强度

只能表述为「**本轮 10 次整包运行未复现**」，**不能**说「已证明不再失败」——
原缺陷属**概率性时钟量化**，10 次 0 失败把观测频率从 20% 压到测不到，但不等于 0，也不代表换机器同样成立。

⇒ 报 `pkg/runtime/app` 门禁时**必须写清跑了几次、失败几次**；单凭一次 `rc=0` 不能说「app 包测试通过」。
