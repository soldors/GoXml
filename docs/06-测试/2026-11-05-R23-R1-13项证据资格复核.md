## 0. 判定口径（本版）

| 层 | 定义 |
|---|---|
| E0 | 无执行记录：仅卡内断言、契约冻结或设计文字 |
| E1 | 实现方自验：有命名测试/命令/rc 文字，但同一工作区且无原始 stdout 字节 |
| E2 | 版本化报告：另行成文，写明提交/命令/退出码/范围（仍可能同一工作区） |
| E3 | 本轮用标准台账 `record-command.py` 重放并留 raw 与零 SKIP；**这是可复跑的现行证据，不等于独立历史验收** |

四条不可放松的判据：

1. 不因旧总账「待审计」否定已有报告；不因卡写 Done 或一次 `go test` 绿就认定整体验收完成。
2. **`-list` 无测试名，或 `-v` 明确出现 `no tests to run`，记为零匹配/零执行**；
   普通非 `-v` 的 `go test` 只显示包级 `ok`，不能据此认定零执行，只能说未由该行核实具体集合。
   本轮需要明确用例集合的证据采用 `-list` 或 `-v`，不把“未列明”写成“未运行”。
3. 测试名只能来自「编译进指定包的顶层 testing 入口」或该包真实的 `go test -list` 结果；
   **禁止**全仓正则、注释/虚拟源码字符串、同名他包、内部子测试替代。
4. 正则/前缀必须与**包路径一起**按 Go `-run` 语义验证（按 `/` 分段、每段非锚定 regexp）。

**历史执行方独立性**：13 项一律标 **未证（缺具名执行者/独立会话记录）**。
dev-log/交接包里「同一会话」「并发线」是归属线索，不是身份证据；另一份文档不等于另一位执行者。
