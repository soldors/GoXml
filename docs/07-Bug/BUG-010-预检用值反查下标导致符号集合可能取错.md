# BUG-010：`detectNamingConflicts` 用值反查下标，取不到即越界

## 元信息

- 状态：**Fixed**（2026-10-23）
- 发现日期：2026-10-23
- 发现方式：代码审查（读 `internal/compiler/codegen/naming.go` 第二阶段）
- 影响范围：`internal/compiler/codegen/naming.go`
- 关联：`TASK-CODEGEN-NAMING-001` / C1

## 现象

第二阶段（与包内既有声明冲突）先按目录分组存 `NamingTarget` **值**，再用一个
按值反查下标的辅助函数取回符号集合：

```go
byDir[filepath.Clean(t.TargetDir)] = append(..., t)   // 存值
...
for _, t := range byDir[dir] {
    for _, sym := range symbolsByTarget[indexOfTarget(targets, t)] {   // ← 值反查
```

```go
func indexOfTarget(targets []NamingTarget, t NamingTarget) int {
    for i := range targets { if targets[i] == t { return i } }
    return -1                      // ← 返回 -1
}
```

三个问题：

1. `symbolsByTarget[-1]` 会 **panic（index out of range）**；当前不可达，
   但可达性依赖"每个 t 都能在 targets 里找到等值元素"这个**未表达的前提**；
2. 若批次里存在两个字段完全相同的输入，反查会稳定命中**第一个**下标，
   于是第二个输入用错符号集合（静默错误，不 panic）；
3. 每次查找都要做整结构体比较（含 3 个字符串 + 2 个标量），是 O(n²) 的额外开销。

## 根因

分组容器里存的是"值"，而后续步骤真正需要的是"下标"（符号集合按下标存放）。
值与下标之间靠"相等"建立映射，是一种隐性耦合；一旦值不唯一，映射就不成立。

## 修复

分组容器从"存值"改为"存下标"，整个过程不再需要反查：

```go
byDir := make(map[string][]int, len(targets))
for i, t := range targets {
    d := filepath.Clean(t.TargetDir)
    byDir[d] = append(byDir[d], i)
}
...
for _, dir := range dirs {
    idxs := byDir[dir]
    group := make([]NamingTarget, 0, len(idxs))
    for _, i := range idxs { group = append(group, targets[i]) }
    existing, err := existingPackageSymbols(dir, group)
    ...
    for _, i := range idxs {
        for _, sym := range symbolsByTarget[i] { ... }
    }
}
```

同时删除 `indexOfTarget` 整个函数。

行为不变（目录分组口径、冲突归类、排序键全部照旧），只是不再依赖"值唯一"。

## 回归测试

现有门禁已覆盖判定行为：`internal/cli/naming_c1_test.go`（G2/G3/G5/G6 四条冻结断言）
与 `internal/compiler/codegen/naming_*_test.go`。本次为纯结构改动，判定语义未变，
因此**没有新增用例**：新增用例只能锁"值重复"这种当前不可构造的输入，
意义有限——真正的修法就是让下标成为唯一依据。

## 这条 Bug 揭示的问题

"存值 → 反查下标"是一个信号：说明容器里存的东西不是后续步骤真正需要的那件东西。
遇到反查，先问一句"能不能直接存下标/指针"。
