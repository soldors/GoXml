# BUG-012：M1 诊断宿主原执行链缺少结果判读

## 元信息

- 状态：原候选未修复；协调者隔离替代入口已验证，正式产品代码不受此记录直接改动。
- 发现日期：2026-10-29。
- 影响范围：本机 M1 诊断采集宿主的原候选 `diag_host.py run`，不等同 Goxml 生产运行时缺陷。
- 关联：本机 `m1-diagnosis-r1.1/coordinator/host-acceptance.md`、`host-validation/commands.jsonl`。

## 现象和根因

协调者源码审查发现：原 run 分支启动子进程并汇总启动记录，但没有把产出送入既有 JSON 判读器、登记 raw/profile 或在无效样本时停批，也缺收口身份比较。491/551 项无窗口自检通过本身不能说明这条实际执行链完整。具体审查和原件哈希在上述本机交付中保留。

## 处置和验证

保留作者原件，不再使用其 run 入口。隔离入口 `host-final/diag_execute.py` 连接既有判读器和原生进程、锁、raw 组件，增加停批和收口身份检查。既有协调者记录显示：合成正向执行和失败分支连接测试 36/36，测试文件解析 5/5；无授权拒绝码为 3。原始台账位于 `m1-diagnosis-r1.1/coordinator/host-validation/commands.jsonl`。

这些测试没有启动真实诊断窗口。原候选并未原地修复，实际 24 次批次要看其 DONE 和独立复核；不能把替代工具测试称为生产性能验收，也不能据此关闭上游原候选缺陷。
