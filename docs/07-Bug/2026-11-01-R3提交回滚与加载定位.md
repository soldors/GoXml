# R3 提交回滚与加载定位缺陷记录

## 提交期备份失败漏回滚（已修，独立复核通过）

触发：一个批次至少两个目标。前一目标已安装新产物，后一目标的旧文件因为无 DELETE 共享句柄而不能 rename 到备份。旧代码只清理 tmp 返回，未恢复前一目标，也没有把其备份列入残留，错误消息却称“已回滚，磁盘恢复原状”。Manifest 没有更新，不能据此推断生成文件也没更新。

修复：所有提交失败出口统一回滚已提交项并清理本批临时文件。当前失败项尚未安装，不误列 restored/withdrawn；若它已被移到备份而新产物安装失败，才把它加入恢复列表。恢复失败分别记录 unrestored 与备份 residue，禁止声明完全恢复。

证据：作者 `010deca` 与非作者补丁 `7c1f739`；真实 CLI 在新目录用一页到两文本的结构变化，强制 `--no-cache`，确认失败确实发生在提交期。前序目标字节/权限/mtime 恢复，后序目标与 Manifest 未变，临时与备份残留为空；无句柄对照成功且产物改变。

## Lstat 错误与非普通目标（事务层防御已修）

Lstat 非 IsNotExist 错误时，当前目标未动不代表之前已提交目标未动，必须回滚前序。符号链接不能依赖“rename 会自然失败”：Windows 可以替换链接本体。事务层现在显式拒绝非普通目标，保留链接/目录等用户对象，并恢复前序提交。

正常 CLI 原有输出边界检查会拒绝已存在的符号链接；原审核的符号链接反例证明事务 helper 的防御缺口，不是正常 CLI 绕过已经实证。TOCTOU、崩溃与断电恢复仍不在本批证明范围。

## 包加载与命名预检（已修，保持阶段）

- 包加载原来只取错误 Msg，丢失可定位事实。现在优先 Error.Pos，再可靠解析 Msg；无可靠位置不伪造。盘符、空格、Unicode 路径与行列有回归。
- 导出别名先 types.Unalias，再判断命名类型，避免把合法 `type Alias = Real` 当作非法 ViewModel。
- 包级命名预检原以 `x.go` 调用 ParseFile。现在传真实文件名，与 Go 工具的 file:line:column 一致；它仍是命名预检失败，不强行改成 ROOT-002，也不伪造 GXML span。

## GOFLAGS F2（未关闭，本批不接纳）

fresh 无 tag/带 tag 项目可生成并构建，不代表已有产物切换 tag 后可再次生成。隔离候选还存在旧产物参与 Analyzer 加载，以及未登记同保护头用户文件被排除的问题。保留失败日志与旧产物，不删除旧文件“自愈”，不将该候选写成已合入。
