# BUG-025：Manifest伪登记使缓存漏检手写源码

- 级别：P1，缓存改变生成正确性。
- 状态：真实CLI复现与修复回归通过，审核/组合接纳见[本批记录](../06-测试/2026-10-31-并行开发验证记录.md)。

## 复现与根因

Manifest伪造`output=vm.go`，旧逻辑不检查生成保护头就把它排除出K3手写源码指纹。随后vm.go语法损坏，普通generate仍rc0并报告命中，no-cache却能发现问题。合法路径并不等于真实生成文件所有权。

## 修复与证据

只有仍带规范保护头的登记产物可从K3排除，用户接管文件必须重新参与指纹。修前真实Run反例rc1，修后普通/no-cache一致失败，旧生成文件/Manifest/用户字节保持。旧all-hit测试夹具曾依赖此漏洞，已保留全部命中/精确命名冲突断言，仅把夹具恢复为真正有保护头的生成产物；新反例单独锁住用户文件入指纹。见[cache_wire.go](../../internal/cli/cache_wire.go)、[clean_safety_test.go](../../internal/cli/clean_safety_test.go)和[CLI日志](../05-开发/dev-log/2026-10-31-cli.md)。
