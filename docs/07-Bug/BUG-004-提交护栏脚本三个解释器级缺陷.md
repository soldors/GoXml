# BUG-004：`scripts/commit-push.ps1` 三个解释器级缺陷

## 元信息

- 状态：**Fixed**（2026-10-22，`27aa03a`）
- 发现方式：多个会话在提交/推送时反复出现"护栏自己骗自己"
- 影响范围：`scripts/commit-push.ps1`（提交护栏脚本）
- 修复提交：`27aa03aebe23330c8dd09df6fe83d46561a404d3`
- 关联：`PIT-008`（管道吞退出码）、`PIT-009`（index 污染）

## 现象

护栏脚本负责"先跑门禁、再按路径提交、最后推送"，但它自己有三个缺陷，
每一个都让**护栏失效或误报**：

| # | 现象 | 后果 |
|---|---|---|
| 1 | 脚本不是 UTF-8 **with BOM** | 中文路径、中文提交说明被吞/乱码 |
| 2 | `$ErrorActionPreference = 'Stop'`（PowerShell 5.1） | native 命令即使成功也会 exit 1 —— **推送成功却报失败** |
| 3 | 控制台代码页 CP936 | 中文路径被判成"清单外"，护拦拒绝提交合法文件 |

第 2 条尤其恶劣：它把**成功显示为失败**，长期下来会让人习惯性忽略护栏的输出。

## 根因

三个都是**解释器/控制台层面**的问题，与业务逻辑无关：

1. Windows PowerShell 5.1 读取 `.ps1` 时依赖 BOM 认 UTF-8；
2. 5.1 下 `'Stop'` 对 native 命令的退出码处理不一致（native 命令写 stderr 就会被当成错误）；
3. CP936 下 `[Console]::OutputEncoding` 与文件系统实际使用的 UTF-8 不一致，
   路径字符串在比较时就已经被改写过一次。

三者都不在 Go 测试覆盖范围内——脚本本身没有自动化保护。

## 修复

```powershell
$ErrorActionPreference = 'Continue'                                  # 第 38 行
try { [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false) } catch { }  # 第 45 行
# 文件以 UTF-8 with BOM 保存
```

改为 `'Continue'` 之后，**每一条关键命令都显式检查 `$LASTEXITCODE`**：

```powershell
if ($LASTEXITCODE -ne 0) { Fail "go test 失败" }      # 第 84 行
```

即：不再依赖解释器自动报错，而是把退出码判定写回脚本自己手里（与 `PIT-008` 同源）。

第 16-18 行的注释保留了这条改动的动机，后续维护者不要再"优化"回 `'Stop'`。

## 回归测试

脚本级用例 **14 个隔离验证**（覆盖三处修复各自的行为），随 `27aa03a` 一并提交。

口头复验：

```powershell
# ① BOM
Get-Content -Encoding Byte scripts\commit-push.ps1 -TotalCount 3   # ef bb bf
# ② 退出码语义
Select-String -Path scripts\commit-push.ps1 -Pattern 'LASTEXITCODE' | Measure-Object   # 多处
# ③ 编码
Select-String -Path scripts\commit-push.ps1 -Pattern 'OutputEncoding'
```

## 这条 Bug 揭示的问题

护栏脚本本身没有"护栏"：它是最需要正确性保障的一段代码，却长期没有自动化验证。
之后凡是新增/修改 `scripts/` 下的脚本，都应同时提交隔离用例，
并坚持"退出码显式判定"而不是解释器自动行为。
