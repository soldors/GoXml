# R9 缺陷与修复

## S1错误回退宿主标签（P1，真实CLI）

GOENV持久化windows/386，目标always.go为enabled、另一个!regabiargs文件为disabled。
Go判多包rc1，原ffbe9f9将错误文案视作“未初始化”再用宿主ToolTags筛文件，CLI却rc0写
enabled。目标全部文件被386排除也沿宿主写出。合法386对照可正确生成，证明不是环境
整体不可用。补修取消错误文案白名单及宿主回退，结构化核唯一包、InvalidGoFiles、
选中文件与package声明。真正未初始化才沿用回退；4个root真实CLI对照转绿。

相关同批补修：resolver显式按批传递避免全局状态；overlay不能只看登记+保护头，须核
Source对应关系。原f2f5159仍保留terminal BLOCK历史，本轮新基线实现不追认旧版本。

## 早期观测点冒充场景完成（P2）

B的11wrapper虽然拒Skip/零测试，完成判据却只要求SCEN。可编译探针打印早期SCEN后return，
子go test正常结束即可绕过最后业务断言。补修SCEN-DONE放在每场景最后断言之后，整行
精确匹配；独立反例证明原版假绿、新版拒绝。保留已批准Input语义，不加来源标志或放宽帧数。

## 自检重跑删除预存报告（P2）

作者为了避免读陈旧报告引入fresh_path，无所有权核验就remove已有路径。真实USER-REPORT
被删。补修只创建独占run/report子目录，旧用户材料及首败保持字节不变；同work根重复两次
仍通过，并有旧实现行为红→补修绿，不能靠清理原证据让重跑通过。

## 锁busy stdout遗漏脱敏（P2）

台账和正常report已脱敏，但busy早退直接输出holder全对象，包含仍可用token。真实私有锁
反例rc8且不启动子进程，仍在stdout泄漏。补修此出口也复用public_lock_block副本脱敏；
独立9项核验通过，锁字节未变、真实owner释放，无共享锁操作。

## 保留的欠证据

C旧raw丢失、B像素首败根因未证、A业务e2e行未补录都如实登记，不以复测覆盖历史。
只将有证据支持的修复结果作为最终接纳依据；完整检查及主仓/远端状态以组合回执为准。
