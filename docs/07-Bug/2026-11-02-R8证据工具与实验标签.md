# R8 缺陷处理记录

## 证据工具普通错误漏锁（P1）

触发：acquire 模式取下自有锁后，给已存在的 `--report`。原版退出 2，但锁文件仍在。
后果：没有执行子命令仍阻塞下一任务。根因是尾部 release，没有覆盖参数检查/写盘异常。
修复：同一宿主取锁后的整个阶段由 finally 保护；已有报告和后期追加 IO 失败均有独立回归。
硬终止无法保证 finally，仍须靠 token/身份人工核验恢复，不能按年龄删锁。

## recover 重新认证变化的 raw（P1）

触发：健康执行后只改 stdout.raw，再向新台账 recover。原版 rc0、recordOk=true，使用
改后 SHA，原 helper 结果却仍留旧 SHA。修复保留捕获时承诺，当前字节只用于核验，不回填。
恢复必须认本 run 的 c1、相同 argv/cwd/caseDir，prepared 仍为 unknown，不能算已跑过。

## 校验器假绿与类型异常

原版只要求 result.json 存在，没有消费其内容；stillRunning/failClosed/infraOk、创建身份
和未知 rc 也可能未进入最终判据。独立探针给矛盾证据得到 PASS。补修交叉核验执行/收口/
双通道、拒绝类型/JSON 歧义，未知给 INCOMPLETE；`--no-disk` 不能承诺原始证据完整。
合法业务非零与证据无效分开：校验 PASS 不是命令成功，发布门必须再核业务判据。

## CPU 特性补丁仍阻断

A `f2f5159` 修了真实 RISC-V 词汇与 parser 范围，但 GOEXPERIMENT 显式增量不能直接
等同最终启用集；不同目标架构默认集也不能套宿主。真实反例见协调者 a-repair-r1/run2。
仅给故障分类，不把非法参数的内部 helper 防御缺口夸大成已证生产绕过。

## Input 旧候选与本轮批准

R6/R7 已阻断候选不会因新方案获批而变成通过。R8 负责人批准的是完整用户优先规则，
并要求更新契约和回归再验收；历史全包失败及 raw 原样保留，新版结果单独记录。
