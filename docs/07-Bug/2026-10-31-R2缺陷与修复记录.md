## 开放的契约与实现问题

### R2-zcode-01：Def Prop 与 For 变量冲突

Def 定义 `Props="label:string"`，其体内 `For Each="label"` 使用 `{label}`，在调用处传 `label="LIMIT"` 时，Expander 会把每行绑定替换成常量 LIMIT；传绑定时则替换为外层 VM 字段。作者有真实生成代码证据，问题仍开放。

语言规范的禁止覆盖条款、Expander 的盲替换与 Analyzer 的内层作用域行为不一致；不能因为生成代码可编译就认为语义正确。原提案建议新诊断编号仅是建议，不在本次接纳中自动登记或实现。应先统一正式作用域规则与诊断契约，再实现拒绝或作用域替换。原提案位于外部 `product-batch-r2/zcode/R2-zcode-01-proposal.md`。

### CLI 后续边界

作者提案 R2-qcode-05～11分别涉及 Source 保护头相对基准冲突、单文件输出压平映射、输出移动后的孤儿登记、跨包输出缺少 VM、包加载错误定位、失败批次提前打印命中行、错误文本子串分类。它们没有在本轮被统一批准或全部修复；已明确的故障应继续技术修复，涉及两个正式契约冲突的项须先统一口径。

复审另发现 build-ignore 生成脚本可被包名扫描误算为生产包；此项与排除 *_test.go 是不同边界，不能仅凭后者通过宣称遵循 Go 的全部构建文件选择规则。
