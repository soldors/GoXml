# BUG-016：M1解析异常导致已启动样本漏记

- 级别：P1，诊断工具执行审计问题；非字体生产路径故障。
- 状态：独立host-r3修复及复审通过；未获新的窗口运行许可。
- 基线：31945a1；问题对象为外部冻结host-r2，不回改其原件。

## 现象与真实反例

在第二个CPU尝试的解析输出目录预置一个名为go-cache的普通文件。真实`parse_profile → parser_env.mkdir`抛FileExistsError；上层execute捕获成infra rc4、batchValid=false，但异常发生在样本row落盘之前。两个合成启动已返回，meta却只记executed=1，将第二个尝试列为notRun，且第二record不存在。原始诊断raw与profile文件已经存在。

反例不启动真实样本进程，只注入launcher结果和合成JSON，调用真实helper目录错误路径；不能称为真实窗口失败。证据在本机night-batch-2026-10-30/preparation/gate-review/real-helper-exception-evidence.json及相应脚本。原有“辅助解析失败会停批”属实，但不等于已启动尝试被准确记账。

## 修复与验证

独立host-r3在解析器抛异常时保留raw/profile身份及原异常，写invalid样本行，parser command/exitCode未知时为null而不伪造；继续以infra rc4首败停批。普通解析器返回invalid仍rc5。执行数不再从已持久化rows推导，分别登记attempted、known-started、recorded、failed-start、unknown-start与notRun。

独立171项场景与22项最终绑定核验通过。原反例在R3为executed2/attempted2/recorded2/valid1/notRun22，第二record/raw/profile SHA正确；另测正常合成24、普通invalid、锁释放失败、PID0启动失败、启动结果未知、启动后raw失败。均0真实窗口/0诊断exe运行。

R3固定manifest SHA `c5947693537f41238aa5be463cd1dfa8e4145a4eac6acc75821cc73100f9a332`，原host-r2与旧2/1/22失败批次不变。本次文档/工具收口提交会改变仓库HEAD，未来新24必须重新冻结当前身份和许可，不直接复用31945a1快照。
