# BUG-009：阶段一 `MkdirAll` 与"磁盘无任何变更"的错误信息不符

## 元信息

- 状态：**Fixed**（2026-10-23）
- 发现日期：2026-10-23
- 发现方式：代码审查（逐段核对阶段边界与其对外声称）
- 影响范围：`internal/cli/pipeline.go` 阶段一
- 关联：`PIT-012`（同为"声称与事实不符"）、`docs/07-Bug/BUG-005`（同为延迟暴露的承诺破口）

## 现象

阶段一（生成阶段）的循环里，对每个未命中输入先建输出目录，再生成：

```go
// 输出目录只为真正要写的文件创建：命中的文件不改动磁盘（连目录都不建）。
if err := os.MkdirAll(d.r.targetDir, 0o755); err != nil { ... }
```

而同一阶段的失败出口写的是：

```go
return fmt.Errorf("生成失败（%s，状态 %v，%d 条诊断）——批次全部放弃，磁盘无任何变更", ...)
```

也就是说：**生成失败时，目标目录已经被创建出来了**，错误信息却声称"磁盘无任何变更"。
在 `--out-dir` 指向尚不存在的多层目录时尤其明显：失败之后，`gen/nested/deep` 留在磁盘上。

## 根因

把"为写盘做准备"的动作放在了"生成"循环里，而生成是**允许失败**的阶段。
副作用与"可失败阶段"混在一起时，失败路径就无法保证零副作用。

注释本身也承认了它是写动作（"只为真正要写的文件创建"），只是没意识到
"这次生成可能失败"——写盘动作必须发生在"已经确定要写"之后。

## 修复

把建目录动作从阶段一的循环里移出，集中到**阶段二开头**（`stageBatch` 之前）：

```go
// ---------- 阶段二：有未命中才写盘（全或无）；命中不碰任何文件 ----------
if len(preparedFiles) > 0 {
    for _, p := range preparedFiles {
        if err := os.MkdirAll(p.r.targetDir, 0o755); err != nil { ... }
    }
    sorted := sortTargets(missTargets)
    ...
}
```

`stageBatch` 要求目标目录已存在，因此这一步必须排在它之前；
而它排在阶段一之后，就意味着阶段一真的变成了纯内存阶段——那条错误信息才站得住。

## 回归测试

`internal/cli/pipeline_test.go` 两条，互为护栏：

```go
TestGenerateFailureDoesNotCreateOutDir  // 失败时 out 目录必须仍不存在（--out-dir 指向多层新目录）
TestGenerateCreatesOutDirOnSuccess      // 成功时目录与产物必须存在（防止用"干脆不建"通过上一条）
```

**变异取证**（2026-10-23 执行）：把 `MkdirAll` 放回阶段一循环 →

```text
--- FAIL: TestGenerateFailureDoesNotCreateOutDir (0.32s)
    pipeline_test.go:228: 阶段一失败时不得创建输出目录 ...\gen\nested\deep（错误信息声称「磁盘无任何变更」）: <nil>
```

还原后复跑 `exit 0`。

## 这条 Bug 揭示的问题

错误信息里的"零副作用"是**对外承诺**，不是修辞。凡是承诺了"磁盘无变更"的路径，
都不能在它之前安排任何写动作——包括"只是建个目录"这种看起来无害的动作。

顺带纠正了同一处的一句注释：阶段一的注释原本写"全部暂存"，但实际阶段一只在内存生成，
暂存发生在阶段二。注释与代码不符时，下一步的改动会跟着注释走错。
