# BUG-003：`For` / `If` 契约把布局路径分配错误挂到 `INV-PERF-4` 名下

## 元信息

- 状态：**Fixed（仅存在于分支 `docs/fix-inv-perf-scope`，尚未合入主干）**
- 发现日期：2026-10-23
- 发现方式：所有者（用户）静态评审指出，随后由维护会话逐句核对 `性能预算与优化策略.md` 原文
- 影响范围：`docs/03-架构/For列表输出契约.md`、`docs/03-架构/If条件渲染输出契约.md`
- 关联文档：`docs/03-架构/性能预算与优化策略.md` §3.2 / §6.1、`BUG-002`
- 修复提交：`0647fbc`（C1 适用域区分）、`6eff102`（C5 三层口径收窄）；登记 `987e4f8` / `5835bdd` / `5b3caf5` / `c99f8f3`

## 现象

修复前，主干上 `For列表输出契约.md` 第 87 行写道：

```text
这是**每帧堆分配**，与 `INV-PERF-4` 的"稳定帧零分配"**不兼容**。
```

第 255、259 行与 `If条件渲染输出契约.md` 第 198 行同口径，把含 `<For>` / `<If>` 的页面
计入 `INV-PERF-4` 的"证据范围"排除逻辑，判据是 `[]layout.FlexChild` 的分配。

问题有三层：

1. **`INV-PERF-4` 管不到这类分配**：它的断言对象是**文本路径**
   （绑定值未变化时不重建字符串、不重新 shaping、`allocs/op == 0`），
   `[]FlexChild` 是布局路径，不属于它的适用域；
2. **"稳定帧零分配"这个说法也不属于 `INV-PERF-2` 的表述**：第 167 / 284 行的要求是
   "**静态页面**稳定帧 `allocs/op == 0`"，含 `<For>` 的页面本就不在承诺范围内，
   所以谈不上"违反"，只能说"未纳入承诺"；
3. 原文把"属于某一不变量讨论的领域"直接写成了"已违反其现行要求"。

## 根因

**跨不变量引用**：把"看起来相关"的性能概念当成判据，而不是回到 `性能预算与优化策略.md`
逐条核对定义原文与适用域。

```text
误：[]FlexChild 有分配 → 违反 INV-PERF-4
正：[]FlexChild 有分配 → 属布局路径；INV-PERF-4 只约束文本路径
    → 不在其适用域；同时 INV-PERF-2 只承诺静态页面 → 也不能判 INV-PERF-2 违规
    → 结论只能是「未纳入现有零分配承诺」，既不违规也不达标
```

另一个隐蔽要点：`For` §6.2 只记录了"每帧重新布局"，**没有**测过堆分配、
也没测过重复 shaping——"每帧布局"本身推不出"每帧分配"或"每帧重新 shaping"。

## 修复

不换编号，改为**按适用域分层描述**：

- `For` §2.2：拆成三层——**整页**（不享有整页零分配保证）/ **布局路径**（`[]FlexChild`，
  属布局路径，在每个布局周期内重新构造）/ **文本节点**（是否达标**尚未验证**）；
- `For` §6.2 附注：补事实边界——**每帧布局 ≠ 每帧堆分配 ≠ 每帧重新 shaping**；
- `For` §7 表格：一行拆两行（整页 / 页内文本节点）；
- `For` §7 与 `If` §6 的边界句：保留原句核心，追加范围澄清，并明确写明
  "整页作为达标证据"是**本次新增的澄清**，不宣称原句本就含此限定；
- `If` §6 的 `make []FlexChild` 证据只引用**本契约 §5 的生成形态示例**
  （该 `make` 位于 `Layout` 闭包内），**不借用** `For` 侧的实现事实；
- 三句警示写进契约：「属于某不变量讨论的领域 ≠ 已违反其现行要求」、
  「未纳入承诺范围 ≠ 允许无条件分配」、「≠ 已证明性能合格」。

**未改动** `性能预算与优化策略.md` 主契约。
