# R6 进程工具缺陷与 Input 候选阻断

本记录区分候选中的缺陷和主干既有行为，不占用全局诊断码，也不把测试工具的失效归因于示例业务。

| 项 | 影响与复现 | 处理 |
|---|---|---|
| 工具有界等待 P1 | 原工具 `47a00dd` 接受 4294967.295 秒，DWORD 为 INFINITE；再大值可截断为 0 | 补修 `c569760` 限制四舍五入后毫秒为 1..0xFFFFFFFE；bool、NaN、Inf、溢出与零拒绝，零进程启动 |
| 进程身份 P2 | GetProcessTimes 失败但其余字段健康，原 compute_ok 可为 true | 创建时间失败/零值即 failClosed，挂起进程归属后收口、不 Resume；身份未知不伪造 |
| 报告所有权 P2 | 两选择器 `--out` 指向既有文件时覆盖报告 | 启动前 lexists 拒绝，结束独占 x 创建；已有目录/文件和竞争文件均保留，锁仍释放 |
| Input 新候选 P1（未合入） | `9fecd88` 上空编辑器、数字 Filter、外部值 letters 投影为空，随后真实 EditEvent 插入1再删；产生 ChangeEvent 却回调0次，无外部写入对照1次 | BLOCK，候选与独立红证据隔离；本任务同根补修轮已用完，不追加算法修复、不改变主干 |

前三项均通过非作者差异复核：进程层23/23，上层20/20；回归在旧实现上红、新实现上绿。大预算反例只通过安全 mock 验证 DWORD/创建调用，不实际启动无限等待。身份失败只用合成 API 返回值，不制造真实孤儿进程。

Input 旧缺陷与新缺陷不能混记：旧 `1925d1d` 的 MaxLen+非幂等回调每帧增长已在新候选闭环（count=1、model=Ab，quiet帧4–8稳定）；新候选仍丢失一类用户 ChangeEvent。Return 对照保留一次 Submit，不能据此判定没有丢事件。正式主干仍采用原 Input 回调规则，用户只批准了 Background B。
