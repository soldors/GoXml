# R5 踩坑：测试发现、证据与保守缓存（2026-11-02）

1. **测试文件存在不代表测试被选中**：先go list看TestGoFiles/IgnoredGoFiles、构建标签和当前包，再用go test -list核函数。不能没有证据就归因“detached缓存”；本次同名文件可被选中，历史未执行原因无足够原件，不补造根因。
2. **编译失败不能证明分配守卫**：变异必须维持编译与测试入口，确实进入热路径并在目标断言上红。ALLOCS=0只证明当次观测；Logf没有拒绝能力。可用可控包级sink保证注入分配逃逸，overlay保护作者字节。
3. **哨兵稳定不等于保守miss**：unresolved/truncated这样的常量也会形成稳定键。必须在真实缓存consumer上拒复用，并保留普通工程真命中对照。
4. **空环境值不等于工具默认值**：Go还读取GOENV/go.work等有效上下文。观测应在被分析工程目录、有超时、失败不猜值；不能用宿主期望值冒充实际工具值。
5. **文案不是数据结构**：skipped路径后带原因再拿它比较bare path，会把已处理项误列pending。路径集合与显示消息分开；多个cause应一起保留，后续失败不能抹掉先前事实。
6. **两态含同一子串时Contains永远区分不了**：“有未保存”与“无未保存”都含“未保存”。比较完整预期值或机器布尔值，使用能改变目标行为的变异。
7. **几何随状态变化**：删除后旧按钮坐标可能无命中。按当前布局扫描，负对照保留；不要把操作重排成另一条更容易通过的流程。
8. **幂等不保证模型和控件同步**：ToUpper幂等而仍可分歧；不把数学分类、观察后果与设计意图混为一谈。
