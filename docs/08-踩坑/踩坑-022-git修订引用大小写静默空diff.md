# PIT-022：git修订引用大小写——小写head在diff范围里静默返回空结果

## 现象

脚本化比对本机 integration 树时，`git diff a2dcff94…​..head -- <path>`（小写 `head`）返回 **rc=0 且输出为空**；同命令改用大写 `HEAD` 后正常返回差异文件列表。后果一处：断言失败（"被测代码已变更"未检出）；更危险的一处：**"诊断仪器源未变"的检查空洞通过**——空输出被当成了"无差异"证据。

## 根因

该环境下小写 `head` 未按预期解析为 HEAD，且 git 对这种引用失败**不报错**（rc=0、stderr 空、stdout 空）。凡以"空输出"当作"无差异"的脚本断言都会被静默击穿。

## 处理与预防

1. 脚本化 git 比对一律使用显式 `HEAD` 或完整 SHA，不使用大小写歧义缩写。
2. 对"空输出 = 无差异"类断言，必须先做**阳性对照**（用一个已知有差异的路径验证命令本身有效），再采信阴性结果。
3. 本仓库脚本（`night-batch-2026-10-30/zcode/` 下各验证器）已全部改为显式 `HEAD`。

## 数据来源

- 现场证据：`night-batch-2026-10-30/zcode/next-phase-prep-r1/logs/verify.1793380949927*.log`（断言失败）与 `1793380949927-crashed`（连带暴露）；修正后 `verify.1793381051982.*`（21/21）。
- 复现命令：`git -C <tree> diff --name-only <sha>..head -- pkg/runtime/app/app.go`（输出空）vs 同命令 `..HEAD`（输出文件列表）。
