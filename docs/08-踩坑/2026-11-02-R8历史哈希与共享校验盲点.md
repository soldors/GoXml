# 历史哈希、共享校验和恢复语义

1. **恢复不是重新认证。** 历史 bytes/SHA 是捕获时承诺，不能用现在的文件重算替换，
   否则篡改恰好被洗成新基线。当前计算值只能和承诺比较；没有承诺就明确未知。
2. **共享 schema 不能替代独立消费者核验。** 写入和校验共用模块能防字段漂移，也会
   共用漏判。测试要把 stillRunning、创建身份、result 退出码和 prepared 内容逐个毒化。
3. **普通错误同样会漏锁。** 参数验证位于 acquire 之后时，也必须处在 finally 内。
   只检查成功路径释放或只看“存在 finally”都不足以证明所有出口。
4. **空结果文件不是健康 fixture。** `{}` 只通过 exists 检查。健康对照应有完整 synthetic
   helper 事实，并由独立磁盘核验复算；与执行未知和业务失败分别建对照。
5. **Python JSON 默认不够严格。** NaN/Infinity 和重复键需要显式拒绝；bool 是 int 子类，
   raw bytes 等数字必须先校验类型。先记录坏类型再强制 int()/日期比较仍会裸异常。
6. **技术批准有范围。** amd64 对照不能覆盖 RISC-V/实验默认集；4 个窄探针 PASS 也不能
   把候选全包 10 个旧断言失败写成全量通过。用户语义决策与技术验证各留独立事实。
7. **共享输入有渲染顺序。** 后渲染控件改模型，先渲染控件可能下一帧才收敛。Submit
   原文与帧末归一化模型不同，不是天然丢事件；必须说明取值时点。
