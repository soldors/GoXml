# PIT-008：管道吞掉命令退出码，让红灯变绿灯

- 分类：工程纪律 / Shell 与 Git
- 关联：`scripts/commit-push.ps1`、`docs/05-开发/dev-log/2026-10-23.md` §1.2、§19.1

## 现象

三类命令串起来跑时，**命令实际失败，但脚本看到的是 0**：

```bash
# ① 门禁与提交串成一条管道 —— 门禁红了照样提交
go test ./... | tail -n 20 && git commit -m "..."

# ② 网络错误退出码被 tail 吃掉 —— 拿到的是过期的远端引用
for i in 1 2 3 4 5; do git fetch origin | tail -2; echo "rc=$?"; done
# 实测：每次都 rc=0，而 in./tmp/f.err 里是
#   fatal: unable to access 'https://github.com/soldors/GoXml.git/': CONNECT tunnel failed, response 502

# ③ 推送失败的退出码变成 tail 的退出码
timeout 25 git push origin master 2>&1 | tail -3; echo "push_rc=$?"
# 实测输出：
#   fatal: unable to access '...': schannel: failed to receive handshake, SSL/TLS connection failed
#   push_rc=0        ← 这是 tail 的 rc，不是 git 的
```

第 ③ 条最危险：它把**"推送失败"显示成"推送成功"**，而人眼看到的最后一行是 `push_rc=0`。

## 根因

Shell 管道中 `$?` 取的是**管道最后一条命令**的退出码，不是被测命令的。
`A | B` 之后 `$?` 是 `B` 的 rc；`A | B && C` 中 `&&` 判断的也是 `B` 的 rc。

只要 `B` 是 `tail` / `head` / `grep` / `tee` 这类"一定会成功"的过滤器，
前面的失败就被静默吞掉。

## 解决

**重定向到文件，再单独取退出码**——不要让任何过滤器接在被测命令后面：

```bash
cmd > /tmp/out.txt 2>/tmp/err.txt
rc=$?
if [ $rc -ne 0 ]; then
    echo "命令失败 rc=$rc"
    tail -5 /tmp/err.txt
fi
```

PowerShell 同理：`.ps1` 里用 `$ErrorActionPreference = 'Continue'` +
显式检查 `$LASTEXITCODE`，**不要**用 `'Stop'`
（5.1 下 `'Stop'` 会让 native 命令成功时也 exit 1，见 PIT-010 与 `scripts/commit-push.ps1` 第 16-18 行注释）。

## 预防

- **门禁类命令禁止与格式化命令串联**。要看输出就把输出先落文件，再单独 `tail` 文件。
- 提交前的"护栏"必须是：跑命令 → 取退出码 → 非 0 即止，**中间不得插入管道**。
- 写进 Bash 用例 / CI 步骤时，用 `set -o pipefail` 作为兜底（本项目 CLI 场景建议显式写 rc 判定）。
