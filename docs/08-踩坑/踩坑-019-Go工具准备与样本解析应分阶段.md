# PIT-019：Go工具准备与样本解析应分阶段

## 现象

R4的诊断进程已退出0、CPU profile保留，辅助`go tool pprof`已打印完整top，却在30秒界限内未退出，批次按规则停止。之后离线冷缓存调用28.515秒，暖缓存约2秒；仅看stdout存在无法证明命令完成。

## 根因范围

`go tool`在该Go版本可能先构建工具，首次构建和profile解析落入同一个超时预算。冷暖差异与此解释相符，但没有足够证据把历史一次超时完全归因于构建、符号化或某个后代。保持“候选解释”，不写成已定根因。

## 处理

R52独立执行有界工具准备，冻结工具bytes、Go身份与不可变回执，后续解析直接调用冻结exe。准备Job和解析Job分别记实际退出、整树activeAfter、handle关闭结果；收口字段必须在上层真实消费者判据中使用，不能只记日志。解析30秒不变，不能以扩大超时或追改旧valid掩盖问题。

## 预防与数据来源

将安装/构建/准备与测量分开验收；每个阶段用真实命令和独立预算。stdout、直接进程退出、后代清理、证据落盘是不同事实，任何一项未知都不能补造成功。R52真实准备3/3、保留CPU/trace两条smoke 2/2，只证明此环境工具可用，不证明性能分布、M1收益或历史根因。详见[R52收口记录](../06-测试/2026-10-31-R52工具准备与解析收口.md)中的冻结证据路径；旧4次离线与2次smoke预算均已消耗，不为补文档重跑。
