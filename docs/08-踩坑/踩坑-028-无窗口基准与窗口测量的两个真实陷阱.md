# 踩坑-028：无窗口基准与真实窗口测量的两个真实陷阱

> 归类：测试/测量工程；来自方向 A（稳态帧测量）的真实踩坑，非字体生产故障。时间：2026-10-31。

## 陷阱 1：`go test ./...` 从错误 cwd 运行，误跑整仓基准

- 现象：在会话工作目录（主仓库 `D:\Codes\Goxml`）执行 `go test -bench . ./...`，实际跑的是**仓库自带**的大量基准（codegen 等），而非自建 `bench/` 模块；耗时数十秒且与本任务无关。
- 根因：`./...` 相对**当前工作目录**解析；未切到自建 module 目录。
- 正确做法：在自建 module 目录内用 `go test .`（单包），或显式 `go test -C <dir> ./bench`；**绝不**用 `./...` 从别的 cwd 触发。
- 影响：只吃编译缓存，**不改源码/不改 git**；但会误导测量归属。

## 陷阱 2：`Start-Process -WindowStyle Minimized` 阻断 Gio 帧

- 现象：真实窗口测量程序在 `-WindowStyle Minimized` 下 45 s 无任何 FrameEvent、无输出、只能超时杀掉；去掉该参数后 4.5 s 正常完成。
- 根因：最小化启动使窗口不进入可见/渲染状态，Gio 收不到 `FrameEvent`（或呈现回调不触发）。
- 正确做法：真实窗口测量用**普通启动**（不要 Minimized / Hidden）；并设置**硬超时**与**自终止**逻辑，跑完确认 `Get-Process` 无残留。
- 附带教训：先用**最小 probe**（打印 5 帧即退出）验证窗口是否可用，再跑测量程序，避免长时间空等。

## 通用纪律

- 自建基准/测量 module 用**自有** `GOCACHE`/`GOTMPDIR`、`GOPROXY=off` 离线；不碰共享缓存与诊断锁。
- 任何 GUI 窗口测量：**显式 opt-in**、自终止、有超时、跑后查残留进程。
- 测量结论只用于**回归护栏**，不替代真实设备/性能验收，不外推为"提升 X%"。
