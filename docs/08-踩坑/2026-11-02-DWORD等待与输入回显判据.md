# DWORD 等待与 Input 回显判据的两个边界

## 超时是浮点有限值，不代表 WinAPI 等待有限

WaitForSingleObject 的等待参数是 DWORD，0xFFFFFFFF 有特殊含义 INFINITE。Python 大整数传 ctypes 时可能截断；4294967.295 秒虽有限，换算毫秒后恰好变无限。应在任何进程创建之前限制转换后的整数范围，既拒绝保留值，也拒绝溢出和 bool。测试用 FakeK32 捕获等待实参及零创建调用，不用真的等待几十天证明问题。

创建成功、退出码存在、Job 活动数为零是三件事，创建身份查询成功是第四件事。GetProcessTimes 失败不得凭 PID 拼出创建时间。若进程尚挂起，应保持用户代码未执行并用自持 handle/Job 完成收口；查询失败和清理失败分别记录。

## 文本相等不能单独证明是程序化回显

Gio changed 标志通常先于事件队列消费，使程序化 SetText 回显先单独到达。但空文本写为空文本、Filter 将输入全部滤空时，SetText 可能不产生回显。若仅留下 prog 标志，随后用户插入再删除，最终文本又等于镜像，真实 ChangeEvent 也会被错当回显。

候选必须覆盖“写入没有产生回显”的情况，并以真实 input.Router 事件链和无外部写入对照证明。只看最后字符串相等、quiet帧稳定或 Submit 未丢，都不能证明 ChangeEvent 没丢。当前 Input 候选因这一实际反例停止，不把未经批准的算法加入主干。

## 报告也有所有权

原始流使用独占 case 目录，不代表汇总 JSON 也安全。最终 `open('w')` 仍会毁掉用户报告；启动前拒绝已有路径并使用 `x` 创建，可同时避免普通重复运行和结束时的竞争覆盖。遇到旧报告要换一个新任务输出路径，不能覆盖旧证据后称“已保留历史”。
