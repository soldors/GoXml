# PIT-001：Gio 布局闭包嵌套导致堆内存逃逸与 60FPS GC 抖动

- 分类：性能 / 内存分配
- 关联：`docs/03-架构/性能预算与优化策略.md` §2.3、INV-PERF-1

## 现象

Codegen 生成多层 `layout.Rigid(func(gtx) { ... })` 时，闭包捕获局部变量导致逃逸到堆。50 个子节点的静态布局实测：

| 方案 | ns/op | allocs/op |
|---|---:|---:|
| 每帧新建闭包 + `append` | 28,000 | 51 |
| **仅预分配复用切片缓冲区** | **27,000** | **51** |
| 编译期完全展开（无闭包/无切片） | **2,550** | **0** |

## 关键结论（此前的建议是错的）

> **原文档建议「复用子元素切片缓冲区」来解决此问题，实测证明这条路基本无效——只省约 4% 时间、35% 字节数，分配次数完全没有下降。**

真正的开销来源是**闭包本身逃逸到堆**，不是切片容量。只要仍在循环内构造闭包，分配就存在。

## 解决

**静态子树必须由 Codegen 在编译期完全展开**：

- 不含绑定/事件/条件/循环的子树，直接生成顺序调用，不生成循环、不生成切片。
- 固化其绘制结果为 `op.CallOp`，稳定帧只回放 `CallOp.Add(gtx.Ops)`。
- 效果：28,000 → 2,550 ns/op（**11×**），51 → 0 allocs/op。

动态部分仍需要闭包时，才考虑缓冲区复用作为次要手段。

## 预防

- 用 `go test -gcflags="-m"` 监控逃逸。
- 断言：静态页面稳定帧 `allocs/op == 0`；静态子树稳定帧宏重录次数为 0。
- 回归：`allocs/op` 由 0 变非 0 即阻断合并。
