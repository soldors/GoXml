# PIT-002：同步调用原生文件弹窗导致主窗口假死

- 分类：线程模型 / 平台能力
- 关联：`docs/03-架构/运行时线程模型.md` §4、§6.1、§7；`AGENT.md` 架构红线

## 现象

在事件回调（`Layout` 或按钮 Click 处理）中直接同步调用系统文件选择弹窗时，主窗口停止重绘，表现为「假死」——直到弹窗关闭才恢复。

## 根因

原生文件弹窗是**阻塞式系统调用**：它接管线程并运行自己的消息循环，直到用户选择或取消才返回。

Gio 是单线程立即模式渲染：UI 线程负责事件分发、Diff、`Layout` 与绘制。在该线程上执行阻塞调用会直接停掉整条渲染循环，窗口自然无法重绘。

`window.Invalidate()` 也无法救场——它只是「请求下一帧」，而 UI 线程本身卡在系统调用里，根本没有机会处理该请求。

## 解决

依据 `运行时线程模型.md` 的分层，文件弹窗必须放在 **Platform worker**：

```text
UI 线程（Click 回调）
  → 投递请求到 Platform worker
  → 立即返回，Layout 继续
Platform worker
  → 阻塞调用系统弹窗
  → 得到结果后投递更新函数
  → 调用 window.Invalidate()
UI 线程（下一帧）
  → 应用结果
```

关键约束（摘自 `运行时线程模型.md`）：

- 后台任务完成后**只能投递更新函数并调用 `Invalidate`**，不得在后台直接触发第二次布局。
- `Invalidate` 可以从后台线程调用，但调用次数允许被合并。
- Dispatcher 不允许执行阻塞任务；任务必须拆分或转交 worker。

## 预防

`运行时线程模型.md` §7 列出的禁止项中，第一条就是：

> 在 `Layout` 中同步打开原生文件弹窗。

可验收的断言（同文件 §5）：

> 文件弹窗不会阻塞 Gio 绘制。

因此测试应能在弹窗打开期间持续触发重绘并观察到帧推进，而不是仅检查代码里有没有 `go func()`。
