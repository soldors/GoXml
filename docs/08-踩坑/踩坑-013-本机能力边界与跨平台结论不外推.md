# PIT-013：本机能力边界——跨平台结论不得外推

- 分类：环境 / 工具链可用性
- 关联：`docs/03-架构/平台与平台依赖矩阵.md`、ADR-0007、`AGENT.md`

## 现象

在 Windows 开发机上实测得到的若干结论，曾被当成通用结论写进文档或设计：

| 本机实测 | 曾被误推成 |
|---|---|
| Windows 零 CGO 构建通过 | 三端可零 CGO 构建（**已被 ADR-0007 实测否决**） |
| `CGO_ENABLED=0` 下 font-go Windows 增量近似 0 | Linux 精简容器也不需要嵌入补充链 |
| 本机 CPU/OS 上的 ns/op | 任意平台的性能结论 |
| `goxml` CLI 在本机能跑 | macOS / Linux 已经可用（实际两个平台均未验收） |

另外**本机不可用但容易被假定可用**的能力：

- `-race`：本机缺 C 工具链（无可用 gcc/msyslink），跑不起来 → 凡是与竞态有关的验收都不能在
  本机用 `-race` 主张；
- `make`：不在 PATH；构建/验证入口是 PowerShell 脚本 + `go` 命令；
- `go vet` / `go build ./...` **跳过 `testdata/`**（见 PIT-012）；
- git 通道对 github.com 不稳定（代理 502 / TLS 握手失败），见 PIT-008、PIT-010。

## 根因

"本机跑通"只覆盖一个 OS × 一个 CPU × 一组依赖版本。Windows 是本项目**唯一当前可执行的平台**，
因此它天然成为默认的推理起点——这也是最容易出错的地方：样本数为 1。

## 解决

- 文档里每条跨平台结论必须写明**平台 + Go 版本 + Gio 版本 + CGO 开关**，
  并给出当时的实测命令与数值（见 `docs/03-架构/平台与平台依赖矩阵.md`）。
- 声称"已验证"时必须写明**在哪台机器、哪个平台**验证的；本机未覆盖的平台写"未验证"。
- Windows 上得到的**零 / 极小**数值，尤其不得向 Linux/macOS 外推。

## 预防

- 涉及 CI / 交叉编译 / 跨平台出包的任务，一律以 `平台与平台依赖矩阵` 为准，不以本机实测为准。
- 想验证跨平台结论时，先在 `docs/03-架构/平台与平台依赖矩阵.md` 里查哪些项标注为"未验证"。
