# PIT-006：每帧拼接显示文本击穿 Gio 文本 shaping 缓存

- 分类：性能 / 文本渲染
- 关联：`docs/03-架构/字体与文本渲染策略.md` §5、INV-PERF-4

## 现象

在 `Layout` 内用 `fmt.Sprintf` 生成显示文本，单帧耗时从 **876 ns 暴涨到 82,053 ns（94×）**，分配从 0 升到 **270 allocs/op、137KB/帧**。

按 60fps 计算，即每秒 8.2MB 分配，GC 必然被频繁触发。

## 根因

Gio 的 `text.Shaper` 以字符串内容为缓存键。字符串每帧变化时，整条 glyph 布局缓存失效，需要重新做 shaping（字形选择、排版、度量）。

注意短字符串的惩罚相对小（1,079 ns / 16B），**长度越长、变化越频繁，代价越陡**——长文本计数器、统计摘要、时间戳这类显示最容易踩中。

## 解决

1. 在 ViewModel 侧缓存字符串化结果，只在依赖字段变化时重建。
2. 文本绑定值未变化时，不重新构造字符串。
3. 禁止在 `Layout` 路径出现 `fmt.Sprintf` / `strconv` 拼接。

## 预防

- 断言：稳定帧文本节点 `allocs/op == 0`。
- AST 断言：生成代码 `Layout` 路径无 `fmt.Sprintf`。
- 回归：若 `allocs/op` 由 0 变为非 0，阻断合并。
