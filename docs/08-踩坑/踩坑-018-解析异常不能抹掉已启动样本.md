# PIT-018：解析异常不能抹掉已启动样本

## 现象

诊断子进程已退出并留下stdout/stderr/profile，但辅助解析器创建缓存目录时抛异常。宿主按规则停批、返回非零，meta却将该尝试列入notRun，因为executed由已写入的rows长度推导。

## 根因

“启动”“观测退出”“解析有效”“样本记录落盘”是不同阶段。只数最终记录会把中间失败的实际执行抹掉；rc非零和batchValid=false虽然避免性能假绿，却不能补回执行审计。BUG-015的cache环境正常/错误位置单测不能替代真实execute异常分支。

## 处理与预防

独立记录attempted、已知started、recorded、failed-start与unknown-start；notRun只表示确实未执行，不能把未知启动结果当未启动。解析异常写invalid样本行，保留原诊断raw/profile身份、异常原因；未返回的解析命令和退出码为null。先落原始证据再停批，不重试/补样或追改历史valid。

反例应穿过真实辅助helper，例如用go-cache普通文件触发FileExistsError，同时核对meta、第二record存在、raw双通道SHA、profile SHA、首败停批与锁/claim释放。完整正向合成24仍需与真实窗口明确区分。

## 数据来源

2026-10-30内部gate-review真实helper反例，host-r3独立171场景+22最终绑定检查；本机night-batch-2026-10-30/preparation/gate-review-r2。窗口与诊断exe均0。
