# PIT-005：大列表全量渲染导致单帧 6.4ms 与每帧 1.5MB 分配

- 分类：性能 / 渲染规模
- 关联：`docs/03-架构/adr/ADR-0006-列表虚拟化与静态子树宏固化.md`、INV-PERF-3

## 现象

`<For>` 直接对全部元素生成 `layout.Rigid` 闭包，10,000 行文本列表在 800×600 窗口下：
单帧 **6,438,000 ns（6.4ms）**、**10,010 allocs/op**、1.5MB/帧。

已占 60fps 预算（16.67ms）的 38%，且每帧 1.5MB 分配会持续触发 GC，导致帧率抖动。

## 根因

立即模式渲染的代价与**元素数量**成正比。视口只能显示约 20 行，却为 10,000 行执行了布局与绘制记录。

## 解决

启用虚拟化，只对可见窗口（含预取边距）执行布局：

```xml
<For Each="item" In="{Items}" Key="{item.ID}" Virtualize="true" ItemExtent="32">
```

同场景降到 **19,200 ns/op、0 allocs/op、7 B/op**，相差 **335×**。

## 预防

- 单帧工作量必须只与可见元素数相关。
- 断言：10,000 行与 100,000 行耗时比 ≤ 1.5×。
- `DataGrid` 必须复用同一虚拟化机制，不得另写一套窗口逻辑。
