# PIT-016：自检通过不等于真实执行链已接通

- 分类：测试基础设施、证据完整性。
- 关联：`docs/07-Bug/BUG-012-M1诊断宿主执行链缺少结果判读.md`、`docs/06-测试/2026-10-29-M1诊断宿主无窗口验证记录.md`。

## 现象与根因

M1 原候选宿主已有大量判读器自检，但实际 run 分支没有接上判读、raw 登记和失败停批。分别测试组件可以证明组件本身工作，不能证明生产调用路径确实使用它们。

此前窗口采集器还出现过另一类证据破坏：launcher 捕获原始字节后，被后续解码和文本持久化覆盖，非 UTF-8、stderr 或 CRLF 无法原样保留。复审报告位于本机 `D:/Codes/Goxml-agent-rounds/2026-10-27/face-selection/window-collector-r1/zcode/final-report.md`。

## 预防

1. 用隔离哨兵贯穿实际执行入口，验证子进程 → 原始 bytes → 解析 → 判断 → 持久化 → 批次退出全链；同时用无效输入证明失败即停。
2. stdout/stderr 原件按文件字节哈希、只读登记；解码仅用于内存副本。测试非 UTF-8、CRLF、非空 stderr、非零退出和部分输出。
3. 锁/claim 的释放结果从实际返回值记录，不能写固定成功；身份应使用 PID 和创建时间，不能只看 PID。
4. 明确每项测试是合成、headless、窗口还是跨平台实测，不能相互替代；记录真实退出码和原始日志。

## 数据来源与边界

协调者 M1 接线验收为本机 `D:/Codes/Goxml-agent-rounds/2026-10-27/face-selection/m1-diagnosis-r1.1/coordinator/host-acceptance.md`，其中 36 项连接检查使用 Python 哨兵；不证明真实 M1 改善。窗口采集器问题和独立反例见上述复审报告；原始材料与修复过程保留。
