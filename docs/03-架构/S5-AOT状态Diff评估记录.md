## 1. 评估问题

> 当前阶段是否需要引入编译期 AOT 状态 Diff（生成字段对比 + 节点级失效）？

## 2. 实测证据（S0–S4）

| # | 证据 | 数值 |
|---|---|---|
| 1 | 绑定显示缓存命中路径（含值比较） | **140 ns/op，0 B/op，0 allocs/op** |
| 2 | 纯重绘（Invalidate 后值未变）稳定帧 | **131 ns/op，0 B/op，0 allocs/op** |
| 3 | 整窗失效触发 → 新帧产生 | 真实窗口实测 <100ms 级延迟（S2/S3 帧计数观测） |
| 4 | 无缓存对照 | 688.9 ns/op（缓存收益 4.9×–58×） |
| 5 | 静态整页命中 | 29 ns/op |

## 3. 分析

### 3.1 AOT Diff 要解决的问题在当前形态下不存在

AOT Diff 的价值命题：**避免「状态变了但只有部分节点受影响」时的全量重布局**。

但当前形态的失效-绘制链路是：

```text
Invalidate → FrameEvent → Layout
  → 静态子树：CallOp 回放（29ns，与状态无关）
  → 绑定节点：读值 → 显示串比较 → 命中回放 / 未命中重录（140ns）
```

- **值未变的节点**：显示串比较命中 → 回放，成本 ~ns 级；
- **值变化的节点**：本来就需要重录（AOT Diff 也省不掉）；
- **与状态无关的静态部分**：CallOp 直接回放，根本不看状态。

即：**绑定显示缓存已经实现了 AOT Diff 想要的效果**（按节点判定复用/重绘），
只是判定信号是「显示串 + 上下文」而非「字段位对比」。

### 3.2 AOT Diff 的额外成本

引入它需要：生成 oldVM 快照结构、硬编码字段比较、Dirty Mask、
节点-字段依赖表（即 `Deps`）。

- 生成代码体积与复杂度显著上升；
- 引入「字段 ↔ 节点」映射的维护负担（节点结构变化即失配）；
- 而其能省下的工作——「值未变节点的显示串比较 + 回放」——
  实测只有 **131–140 ns/op**，且已经是零分配。

### 3.3 何时应重新评估（触发条件，不是时间表）

| 触发条件 | 说明 |
|---|---|
| 单页绑定节点数达到数百级 | 逐节点读值+比较的线性成本开始可观 |
| 实测单帧 Layout 超出帧预算（如 >1ms） | 现有 `FrameEvent` 级测量手段已具备 |
| 引入复杂状态（深嵌套、大列表）且实测热点在状态比较 | 列表虚拟化（ADR-0006）落地后复测 |

## 4. 结论

**当前阶段不引入 AOT Diff。**

- 绑定显示缓存已以更低复杂度实现等效的「按节点复用/重绘」；
- 全部稳定帧路径实测零分配（131–140 ns/op）；
- 细粒度失效（Deps）与 AOT Diff 一并**推迟**，触发条件见 §3.3；
- REQ-003 与 `AOT状态Diff语义.md`（v1）保留为**设计储备**，
  状态改记「推迟（推迟依据见本记录）」，不作废。

## 5. 对 REQ-003 的处置

- REQ-003 状态：**P0 → 推迟**（推迟到 §3.3 任一触发条件成立）；
- 不删除需求、不修改 `AOT状态Diff语义.md` 冻结稿（设计仍是有效的储备）；
- `TASK-STATE-001` 的旧版子任务（生成 shadow 结构 / 对比逻辑）随之搁置。

## 6. 未决与边界

- 列表虚拟化落地后**必须复测**（列表项数是最可能击穿现有模型的变量）；
