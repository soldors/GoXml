# ADR-0014：Lazy 晚绑定的终态观察与帧内交接

- 日期：2026-10-30（北京时间）。
- 状态：本次 BUG-013 修复决策，依据项目所有者“处理遗留的两项”的开发授权实施；不升级 FONT 正式验收。
- 范围：`theme.Lazy` 的完成观察，以及 `app.NewLazyApp` 绑定失败时的唤醒补偿。
- 关联：[BUG-013](../../07-Bug/BUG-013-Lazy提前请求可能丢失终态唤醒.md)、[IMPL-1](../../04-WBS/任务卡/TASK-FONT-001-D-IMPL-1.md)、[IMPL-2](../../04-WBS/任务卡/TASK-FONT-001-D-IMPL-2.md)。

## 问题与反例

调用方先 `Request()`，后台捕获当时的通知，再将 Lazy 交给 `NewLazyApp`。后者无法重新绑定，只在构造器补一次 `Invalidate()`。Gio 在原生驱动未创建时可跳过这次请求；首帧若仍为 Loading，后台完成后又无有效回调，空闲窗口便没有必然的下一帧。`pending` 没丢失，不代表它必然被消费。

旧任务卡“通知不是正确性依赖”的论证缺少下一帧的来源。本决策纠正该假设，保留 `SetNotify` 原有的一次性、早绑定规则；不覆盖调用方已有回调，不把晚绑定改成成功。

## 决策

1. 新增 `Lazy.Done() <-chan struct{}`，只观察当前尝试。首次 Request 前可取得第一轮的通道；不触发 IO、加载或重试。Ready/Failed 的状态、报告和 pending 在同锁发布后关闭通道。失败后显式 Request 创建新通道，旧通道保持关闭；观察重试者需要重新获取。正常未使用 Done 的路径不分配通道。
2. `NewLazyApp` 仅在 SetNotify 失败时启用补偿，保留构造期的一次 Invalidate。在第一个真实 FrameEvent 开始后，按当前尝试启动至多一个完成等待者；终态只触发 Invalidate。若后续显式重试，由触发重试的事件/帧注册新尝试。没有事件循环的 App 不创建等待 goroutine。
3. 等待者不接触主题，不调用 Layout/Take；`Take → Shaper 交换 → Layout → 提交` 顺序不变。窗口事件循环退出时取消等待，不要求字体读取必须被取消。
4. 不采用定时器、持续轮询、全局回调注册表、覆盖旧 notify、后台直接交换 Shaper 或首帧等待字体完成。稳定帧不创建 goroutine、不分配新通道；补偿仅增加已有通道身份的检查。

## 兼容与边界

`ProviderOptions`、`LazyOptions`、`LoadReport`、`FontProvider`、默认探测和覆盖阈值不变。StrictFontFailure 仍在窗口关闭后返回，加载失败不强制关窗。M1 起止不变，不能把此正确性修复称为启动性能优化。

完成观察不是取消加载的接口，也不自动启动重试。返回的通道是一次尝试的快照，不是永远复用的广播。使用 Lazy 的调用方仍须在状态变化后驱动帧；本实现保证既有加载尝试终态在窗口开始处理帧后能够请求重绘。

## 验证与限制

受控事件泵仅在实际补偿回调发生后驱动第二帧，红基线保留原生产调度，仅增加可观察回调字段；旧行为超时失败，修复后通过。覆盖无旧回调/已有回调、失败显式重试、已 Ready、默认与选面终态、并发读取、稳定观察零分配、一次交换和提交。完整命令与边界见 [回归记录](../../06-测试/2026-10-30-两项遗留修复回归记录.md)。本轮逻辑测试不冒充真实空闲原生窗口验收。
