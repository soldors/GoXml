# ADR-0006：列表虚拟化与静态子树宏固化的编译期决策

- 状态：已接受，实现验证待完成
- 冻结日期：2026-10-18
- 关联需求：REQ-002、REQ-003
- 关联文档：[性能预算与优化策略.md](../性能预算与优化策略.md)、[GXML语言规范.md](../GXML语言规范.md)、[AOT状态Diff语义.md](../AOT状态Diff语义.md)、[代码生成输出契约.md](../代码生成输出契约.md)

## 1. 背景

GXML v1 与 AOT Diff v1 已经冻结了语义层面的大部分决策，但**没有定义两个直接影响帧性能的编译期行为**：

1. `<For>` 的渲染范围——是渲染全部元素，还是只渲染可见元素。
2. 静态子树（无绑定、无事件、无条件、无循环）是否必须被固化为可回放的绘制宏。

这两点看似是「实现细节」，实测后确认它们是**量级决策**，必须在 Codegen 定型前锁定：

| 决策 | 全量 / 未固化 | 虚拟化 / 固化 | 差距 |
|---|---:|---:|---:|
| 10,000 行列表单帧 | 6,438,000 ns | 19,200 ns | **335×** |
| 50 节点静态子树单帧 | 28,000 ns | 2,550 ns | **11×** |

数据来源与完整环境见 [性能预算与优化策略.md](../性能预算与优化策略.md) §2。

一旦 Codegen 按「全量渲染 + 逐节点闭包」定型，后续修改需要重写代码生成器与生成的 API 形态，代价极高。因此即便 GXML 语义已冻结，仍需就这两个行为单独作出决议。

## 2. 决策

### 2.1 静态子树必须编译期固化（不涉及语法变更）

Codegen 必须识别满足以下全部条件的子树，并为其生成 `op.Record` / `op.CallOp` 缓存槽位：

- 不含任何 `{Binding}`、事件绑定（如 `Click`）；
- 不含 `<If>`、`<For>`；
- 不含交互控件（`Button`、`Input` 及有状态自定义组件）；
- 其布局结果只依赖已纳入 `renderContextKey` 的上下文。

稳定帧只执行 `CallOp.Add(gtx.Ops)` 回放，不重新记录宏。该决策**不改变 GXML 语义**，属于 Codegen 输出契约的强制要求，因此不构成 GXML 版本变更。

### 2.2 列表虚拟化（涉及语法扩展，需独立批准）

为支持大列表，`<For>` 增加一组**可选**属性：

```xml
<For Each="item" In="{Items}" Key="{item.ID}"
     Virtualize="true" ItemExtent="32">
  <Row>...</Row>
</For>
```

| 属性 | 必选 | 说明 |
|---|---|---|
| `Virtualize` | 否 | `true` 时启用虚拟化，缺省为 `false` |
| `ItemExtent` | 条件必选 | 固定行高（dp）。启用虚拟化且未提供时必须使用 `Measure` 回调模式或编译失败 |

规则：

1. 未指定 `Virtualize` 时行为与现有规范完全一致，保证向后兼容。
2. `Virtualize="true"` 时，元素只在进入可见区域时创建行状态并执行 `OnMount`，离开可见区域后按滚动窗口策略保留或释放。
3. 虚拟化不改变 `<For>` 的 Key 语义与协调算法，只改变「何时创建/释放行状态」。
4. 虚拟化要求元素高度可预测。固定 `ItemExtent` 为标准路径；变高实现必须在 v1.1 中另行定义并给出明确诊断。
5. 虚拟化列表中的交互控件状态必须与 Key 绑定，滚动不得导致状态串位。

## 3. 替代方案与取舍

| 方案 | 否决理由 |
|---|---|
| 不虚拟化，要求用户自己分页 | 把框架性能缺陷转嫁给用户。实测全量渲染 10,000 元素单帧 6.4ms，已超 60fps 预算的 38%，且每帧 1.5MB 分配会持续触发 GC；任何元素数随数据增长的 `<For>` 都会触及该上限，框架不应把该约束推给调用方 |
| 默认开启虚拟化，不提供开关 | 改变了既有语义（`OnMount` 时机、全量遍历的副作用），破坏向后兼容；且小列表下优化收益为负 |
| Codegen 全部生成虚拟化，不做区分 | 同上；且与 `AOT状态Diff语义.md` §8 已冻结的生命周期边界冲突 |
| 静态子树只做「预分配切片复用」 | 实测仅省约 4%，未命中真正开销来源（闭包逃逸） |

对 `Virtualize` 缺省为 `false` 的取舍：**默认保守**，由需要的人显式开启。这样既保住兼容性，又让性能优化可被审计（Golden 测试能看到显式属性）。

## 5. 验收要求

实现必须覆盖：

1. 静态子树在稳定帧不重新记录宏（宏重录计数为 0）。
2. 含绑定子树在绑定未变时同样不重录；绑定变化时只重录受影响节点。
3. `Virtualize="true"` 下，10,000 行与 100,000 行的单帧耗时差异 ≤ 1.5×。
4. 虚拟化滚动过程中，带 Key 的 `Button`/`Input` 状态不串位、不丢失。
5. 未指定 `Virtualize` 时，行为与 v1 基线逐字节一致（Golden 对照）。
6. 虚拟化启用但缺少 `ItemExtent` 且未提供 `Measure` 时，编译期给出明确诊断。
7. 虚拟化与 `<If>` 嵌套时，可见区内的条件分支仍正确执行 `OnMount`/`OnUnmount`。

## 7. 版本演进边界

改变以下任一项必须新增 ADR：

- `Virtualize` 的默认值；
- 虚拟化的可见区保留策略与行状态生命周期；
- 静态子树固化的识别边界；
- 变高虚拟化算法。
