# 运行时线程模型

- 状态：冻结
- 冻结日期：2026-10-18
- 适用范围：Gio 主循环、Runtime、Router、Lifecycle、Platform、Watch、Hydration

## 1. 核心原则

Goxml 使用单一 UI 状态所有者和多类后台 worker：

1. Gio UI 线程拥有 ViewModel、组件状态、路由状态和 Macro 状态。
2. 后台 Goroutine 不得直接修改 UI 状态。
3. 所有跨线程状态修改必须通过 UI dispatcher 串行执行。
4. `window.Invalidate()` 只负责唤醒渲染，不代表可以跨线程直接读写 UI 数据。
5. `Layout(gtx)` 内禁止阻塞 I/O、系统弹窗、网络、进程管理和无界等待。
6. 生命周期和路由的状态变更必须在 UI 线程提交。

## 2. 线程角色

| 角色 | 所有权 | 允许执行 | 禁止执行 |
|---|---|---|---|
| Gio UI 线程 | ViewModel、Widget、Router、Macro | 事件分发、Diff、Layout、绘制、生命周期提交 | 同步 I/O、系统弹窗、网络、等待后台结果 |
| Runtime worker | 编译外的后台任务 | 定时器、状态序列化、非阻塞计算 | 直接修改 UI 状态、直接调用 Widget |
| Platform worker | OS API 和 IPC | 剪贴板、文件弹窗、托盘、菜单、D-Bus | 直接调用 Layout 或修改 ViewModel |
| Watch worker | 文件和子进程监控 | fsnotify、构建、进程管理、状态文件 | 直接替换 UI 状态 |
| UI dispatcher | UI 队列 | 批量应用后台结果和路由请求 | 执行长时间任务 |

## 3. 一帧的执行顺序

```text
Gio 收到窗口事件
  -> UI 线程排空 dispatcher 队列
  -> 应用生命周期和路由变更
  -> 读取当前 ViewModel
  -> 绑定缓存判定与必要的静态 CallOp 回放
  -> （若未来引入 AOT Diff）执行 ShadowState Diff 与循环状态协调
  -> 交互控件输入处理
  -> 必要的布局与 Macro 记录
  -> 提交绘制操作
  -> 提交本帧缓存和绘制操作
```

后台任务完成后只能投递更新函数并调用 `Invalidate`，不得在后台直接触发第二次布局。

## 4. Dispatcher 契约

Runtime 必须提供等价于以下语义的接口：

```go
type Dispatcher interface {
    Dispatch(func())
    Invalidate()
    Context() context.Context
}
```

规则：

- `Dispatch` 保证函数在 UI 线程执行。
- 多个更新可以在同一帧合并。
- Dispatcher 关闭后，新任务必须返回取消错误或被丢弃并记录诊断。
- `Invalidate` 可以从后台线程调用，但调用次数允许被合并。
- Dispatcher 不允许执行阻塞任务；任务必须拆分或转交 worker。

## 5. ViewModel 访问规则

- UI 线程可以直接读取和修改当前 ViewModel。
- 后台线程只能持有只读快照，或通过消息把变更提交给 UI 线程。
- 不允许用一个全局互斥锁包住整个 `Layout` 以掩盖跨线程访问。
- 需要跨线程共享的数据应使用不可变快照、消息传递或明确的原子字段。
- 后台任务使用页面 Context；页面卸载时 Context 取消，任务必须停止或忽略结果。

## 6. 平台调用线程

### 6.1 文件弹窗、剪贴板、托盘和菜单

平台 API 必须在 Platform worker 中执行：

```text
UI 线程请求
  -> 创建带取消的操作
  -> Platform worker 调用系统 API
  -> worker 生成结果或错误
  -> Dispatch 到 UI 线程
  -> 更新 ViewModel
  -> Invalidate
```

Windows 和 macOS 需要线程亲和性的 API 可以使用专用锁定 OS 线程；这一细节只能存在于 `pkg/platform`，不得泄漏到 Runtime 公共 API。

### 6.2 回调规则

- 平台回调不得直接调用 `Layout`。
- 平台回调不得直接触碰 Widget。
- 回调结果必须带操作 ID 或 Context，防止页面卸载后写入旧实例。
- 用户取消、权限拒绝、服务不可用和系统错误必须保持不同错误语义。

## 7. 生命周期与路由

- `OnMount` 和 `OnUnmount` 在 UI 线程提交。
- `OnMount` 可以启动后台任务，但不得同步等待任务完成。
- `OnUnmount` 必须先取消子 Context，再释放组件资源。
- 异步结果到达已卸载页面时必须丢弃。
- 路由切换请求可以来自后台线程，但必须通过 Dispatcher 排队。
- Router 在 UI 线程创建旧页面视觉快照、取消旧页面 Context 并挂载新页面。
- 转场动画只读取已提交的绘制快照，不执行旧页面业务 Layout。

## 8. Hot Reload 与 Hydration

Watch worker 负责：

- 文件监听和 100ms 防抖。
- 生成、构建和子进程管理。
- 写入状态暂存文件。

UI 进程负责：

- 读取并校验 Hydration 数据。
- 在 UI 线程应用恢复状态。
- 对损坏、版本不兼容或页面已卸载的数据返回诊断并丢弃。

Watch worker 不得直接操作 UI Widget；热重启通过进程边界完成隔离。

## 9. 明确禁止的行为

以下行为属于 P0 缺陷：

- 在 `Layout` 中同步打开原生文件弹窗。
- 在后台 Goroutine 直接修改 ViewModel 并触发渲染。
- 在后台 Goroutine 调用 Widget、Router 或 Macro API。
- 在事件回调中等待网络、文件或子进程。
- 页面卸载后仍向旧页面写入异步结果。
- 用全局锁包住渲染循环并允许无界等待。

## 10. 验收测试

必须覆盖：

1. 后台任务通过 Dispatcher 更新状态。
2. 多个后台结果在同一帧合并。
3. 页面卸载后异步结果被丢弃。
4. 文件弹窗不会阻塞 Gio 绘制。
5. 路由切换取消旧页面 Context。
6. Windows/macOS 线程亲和性操作不会泄漏到 Runtime。
7. 关闭窗口时所有 worker 正常退出。
8. `go test -race` 无数据竞态。
9. 取消、超时和权限错误可以返回 UI 层。

## 11. 版本演进边界

改变 UI 状态所有权、Dispatcher 语义、平台回调线程、路由取消或生命周期线程，都必须更新本文件并通过新的 ADR。
