# 平台与平台依赖矩阵

- 状态：设计冻结，Linux 编译路径已真机验证，运行 smoke 待完成
- 冻结日期：2026-10-18
- 关联 ADR：[ADR-0007](adr/ADR-0007-Zero-CGO降级为Windows侧约束.md)（取代 ADR-0005 的全局 Zero-CGO 要求）
- 适用范围：`pkg/platform`、生成应用、CI、发布和运行时线程模型
- 取代：原 `Zero-CGO平台兼容性矩阵.md`

## 1. 目标与边界

Goxml 的目标是**三端可用**，而不是三端零依赖。

- **Windows** 保持 `CGO_ENABLED=0`，产物为单文件静态二进制。
- **Linux / macOS** 接受平台工具链（CGO），由 Gio 的后端决定系统依赖。
- **平台能力**分三类：
  - **核心能力**：窗口、Gio 渲染、基本输入、应用生命周期。
  - **可选能力**：剪贴板、文件弹窗、托盘、系统菜单。
  - **降级能力**：系统服务缺失、权限不足或桌面环境不支持时返回明确错误，不阻塞、不假成功。

## 2. 平台构建矩阵

| 平台 | 构建开关 | 构建机前提 | 产物形态 | 状态 |
|---|---|---|---|---|
| Windows | `CGO_ENABLED=0` | 仅需 Go | 单文件静态二进制 | **已验证** |
| Linux | `CGO_ENABLED=1` | Go + gcc + §4.1 的 `-dev` 包 | 动态链接，依赖 §4.2 运行库 | **编译已验证**，运行待 smoke |
| macOS | `CGO_ENABLED=1` | Go + Xcode Command Line Tools | 动态链接系统框架 | **未验证**（需 Apple 硬件，v1 仅保证功能设计） |

### 2.1 运行目标

| 平台 | v1 运行基线 | 桌面前提 |
|---|---|---|
| Windows | Windows 10 21H2+ / 11，x64 | 无额外桌面服务 |
| Linux | Debian 13 / Ubuntu 22.04+ amd64 | X11 或 Wayland；Session D-Bus 可选 |
| macOS | macOS 12+，Apple Silicon / Intel | 系统权限与应用签名按发布流程处理 |

### 2.2 CGO 策略（本次修订核心）

| 平台 | CGO 要求 | 理由 |
|---|---|---|
| Windows | **必须为 0** | Gio 的 Windows 后端是纯 Go（`x/sys/windows` + D3D11），零 CGO 可达成且已验证 |
| Linux | **必须为 1** | Gio 的 `internal/vk`、`internal/gl`(`gl_unix`)、`internal/egl`、`app/os_x11`、`app/os_wayland` 均 `import "C"`；实测 5 种 build tag 组合全部无法绕过 |
| macOS | **必须为 1** | Gio 的 `app/os_macos.go`、`app/metal_macos.go` 依赖 CGO + Cocoa/Metal |

> 说明：`CGO_ENABLED=1` 只表示"允许 CGO 存在"；若依赖树中无包实际使用 CGO，交叉编译仍可成功。Gio 在 Linux/macOS 上属于**实际使用**的情况。

## 3. 能力矩阵

| 能力 | Windows | Linux | macOS | 不可用时行为 |
|---|---|---|---|---|
| 基础窗口与渲染 | 必须 | 必须 | 必须 | 应用启动失败并返回诊断 |
| 剪贴板 | Win32 API（纯 Go） | Session D-Bus / 桌面服务 | Objective-C Runtime（经 CGO 或 purego） | 返回 `ErrUnsupported` 或 `ErrPermission` |
| 打开/保存文件 | Win32 通用对话框（纯 Go） | 优先桌面 portal；无服务时返回不可用 | 原生系统 API | 返回 `ErrUnsupported`，不得阻塞 UI |
| 系统托盘 | Shell API（纯 Go） | D-Bus StatusNotifier 等 | NSStatusItem | 返回不可用，主窗口继续工作 |
| 系统菜单 | Win32 菜单 API（纯 Go） | 桌面环境适配 | NSMenu | 返回不可用，主窗口继续工作 |
| 异步回调 | 平台 worker / 专用 OS 线程 | D-Bus worker | 专用 OS 线程 | 回调错误进入 UI 队列 |

## 4. 系统依赖清单（发布必读）

### 4.1 Linux 构建依赖（CI / 贡献者必须安装）

```text
build-essential pkg-config
libx11-dev libx11-xcb-dev
libxkbcommon-dev libxkbcommon-x11-dev
libxcursor-dev libxfixes-dev
libegl1-mesa-dev libgles2-mesa-dev
libvulkan-dev libwayland-dev
```

安装命令（Debian/Ubuntu）：

```bash
sudo apt-get install -y build-essential pkg-config \
  libx11-dev libx11-xcb-dev libxkbcommon-dev libxkbcommon-x11-dev \
  libxcursor-dev libxfixes-dev libegl1-mesa-dev libgles2-mesa-dev \
  libvulkan-dev libwayland-dev
```

### 4.2 Linux 运行依赖（终端用户环境）

实测产物 `readelf -d` 的 `NEEDED` 列表：

```text
libEGL.so.1            libwayland-egl.so.1     libwayland-client.so.0
libwayland-cursor.so.0 libxkbcommon-x11.so.0   libxkbcommon.so.0
libX11-xcb.so.1        libX11.so.6             libXcursor.so.1
libXfixes.so.3
+ 动态加载器 /lib64/ld-linux-x86-64.so.2
```

**发布要求**：Linux 产物必须在发布说明中列出上述运行库；建议同时提供 `.deb` / `.rpm` / AppImage 封装，把依赖声明进包元数据。

对应运行时安装（Debian/Ubuntu）：

```bash
sudo apt-get install -y libegl1 libwayland-client0 libwayland-cursor0 \
  libwayland-egl1 libxkbcommon0 libxkbcommon-x11-0 \
  libx11-6 libx11-xcb1 libxcursor1 libxfixes3
```

### 4.3 macOS

- 构建需 Xcode Command Line Tools（`xcode-select --install`）。
- 依赖系统框架：Cocoa、Metal、QuartzCore 等，随系统提供，无需单独安装。
- 分发需签名与公证，属发布流程，不由 Runtime 绕过。

### 4.4 Windows

- 无外部运行依赖，单文件即可分发。
- 目标机需 Windows 10 21H2+。

## 5. 验证矩阵

### 5.1 构建验证

```text
# Windows：零 CGO，单文件
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build ./...

# Linux：需在 Linux（或 WSL/容器）中执行
CGO_ENABLED=1 GOOS=linux GOARCH=amd64 go build ./...

# macOS：需在 macOS 中执行
CGO_ENABLED=1 GOOS=darwin GOARCH=arm64 go build ./...
CGO_ENABLED=1 GOOS=darwin GOARCH=amd64 go build ./...
```

**不得**再声称三端可在 `CGO_ENABLED=0` 下交叉编译——该要求已被实测否决（见 ADR-0007 §3.1）。

### 5.2 平台包测试不能替代完整应用测试

完整门禁必须额外构建生成后的旗舰 Demo：

```text
# Windows
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build ./examples/flagship/...

# Linux
CGO_ENABLED=1 GOOS=linux GOARCH=amd64 go build ./examples/flagship/...
```

### 5.3 运行验证

编译通过只证明依赖与链接条件满足。剪贴板、文件弹窗、托盘、菜单和 IME 必须在对应宿主机执行 smoke test，并把结果写入 `docs/06-测试/测试报告.md`。

## 6. 平台实现规则

### 6.1 Windows（保持纯 Go）

- 使用 `golang.org/x/sys/windows` 或纯 Go syscall 动态加载系统 DLL。
- **禁止**引入任何需要 CGO 的托盘、窗口或对话框库。
- 需要线程亲和性的原生 API 由平台层创建专用 worker，必要时 `runtime.LockOSThread`。
- 文件弹窗、剪贴板、托盘操作不得在 `Layout(gtx)` 或事件回调中同步执行。
- 子进程与句柄必须在取消、错误和退出路径释放。

### 6.2 Linux

- 允许使用 CGO，但**仅限 Gio 后端所需**；新增 CGO 依赖须登记到本矩阵。
- 平台 IPC 优先 D-Bus Unix Socket；不依赖 CGO D-Bus 封装（用 `godbus/dbus` 等纯 Go 实现）。
- Session D-Bus 不存在时，能力探测必须快速返回，不得等待服务永久响应。
- 不通过执行 `zenity`、`kdialog` 等外部命令伪装平台实现。
- X11、Wayland、portal 与托盘协议必须通过独立能力探测和错误码区分。
- 不同桌面环境差异不得泄漏到 Runtime 公共接口。

### 6.3 macOS

- 允许使用 CGO；Gio 的 Cocoa/Metal 后端必须依赖它。
- 若在平台层自行绑定 Objective-C Runtime，可用 `purego`，但**不得声称 Gio 整体可在纯 Go 下构建**。
- Objective-C Runtime 调用集中在平台包，业务代码不得直接操作 selector 或 ABI。
- 需要主线程或专用线程的 AppKit 操作必须经平台 dispatcher 调度。
- 符号缺失、权限拒绝、用户取消必须分别返回错误。

## 7. 公共错误与能力探测

平台层必须提供稳定错误分类：

```go
var (
    ErrUnsupported = errors.New("platform capability is unsupported")
    ErrUnavailable = errors.New("platform service is unavailable")
    ErrPermission  = errors.New("platform permission denied")
    ErrCancelled   = errors.New("platform operation cancelled")
)
```

能力探测必须是只读、快速、可重复的：

```go
type Capabilities struct {
    Clipboard  bool
    FileDialog bool
    Tray       bool
    Menu       bool
}
```

能力不可用时不得返回空字符串、假成功或永久等待。

## 8. 测试分层

- **构建测试**：按 §5.1 的平台矩阵执行，Windows 零 CGO，Linux/macOS 开 CGO。
- **依赖测试**：断言 Linux 产物的 `NEEDED` 列表与本矩阵 §4.2 一致，防止悄悄新增依赖。
- **能力探测测试**：服务存在、不存在、权限不足、用户取消。
- **宿主机 smoke test**：真实剪贴板、文件弹窗、托盘、菜单、中文 IME。
- **线程测试**：确认平台调用不在渲染线程执行。
- **竞态测试**：后台完成回调、取消、窗口关闭并发执行（`CGO_ENABLED=1` 下 `-race`）。
- **失败测试**：平台 API 错误时主窗口继续工作，错误正确传回。

## 9. 版本演进边界

新增平台、改变 CGO 开关、新增原生依赖、改变支持版本、改变降级行为、改变线程亲和性，都必须更新本矩阵与 ADR-0007（或新增 ADR）。
