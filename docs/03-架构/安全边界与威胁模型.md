# 安全边界与威胁模型

- 状态：**有条件通过**（2026-10-19）
- 对应任务：`TASK-SEC-001`
- 审计范围：Parser → Expander → Analyzer → Codegen → Artifact → Commit → 运行时入口
- 审计方式：**实证探针**，每条结论附可复现的测试或代码位置

> **结论口径**：本报告区分「已修复缺陷」「已量化的风险」「未验证项」。
> 「未验证」不等于「存在漏洞」；「文档已写完」也不等于「安全审查通过」。

---

## 1. 资产与信任边界

### 1.1 资产

| 资产 | 受损后果 |
|---|---|
| 开发机文件系统 | 生成物被写到非预期路径、覆盖无关文件 |
| 生成 Go 源码的语义 | 注入导致非预期代码执行 |
| 编译进程的可用性 | 资源耗尽、栈溢出、长时间卡死 |
| 依赖与构建环境 | 意外联网、执行非预期命令 |

### 1.2 信任边界

| 输入 | 信任级别 | 依据 |
|---|---|---|
| `.gxml` 文件内容 | **不可信** | 可能来自第三方模板、代码生成工具 |
| `ViewModel` 声明 | **不可信**（受文法约束） | Analyzer 已限制为模块内类型，拒绝绝对路径/`..`/完整导入路径 |
| `Options.PackageName` / `SourcePath` | **半可信** | 由调用方传入；Codegen 校验标识符合法性 |
| `pipeline.Artifact` | **半可信** | 可能由调用方构造，`Commit` 必须自行防守 |
| Go 模块与依赖 | **可信** | 由 `go.mod` 决定 |
| 生成文件的输出目录 | **可信** | 由调用方指定 |

**关键判断**：`Artifact` 被列为半可信，是因为它的字段（尤其 `OutputName`）是导出字段，
调用方可以直接构造。`Commit` 不能假设它来自 Codegen。

## 3. 逐项证据

### 3.1 【已修复缺陷】`Commit` 可被路径穿越

**风险等级：高**（可写任意路径）

修复前 `Commit` 直接执行 `filepath.Join(dir, a.OutputName)`，未校验 `OutputName`。
实测验证：

```text
OutputName = "../<outside>/evil.go"
→ Commit 返回 path="...\\001\\evil.go" err=<nil>
→ 文件被写到目标目录之外
```

**修复**：新增 `validateOutputName`，要求纯文件名——

- 不含 `/` 或 `\`
- 不是 `.` / `..`
- 不以 `.` 开头
- 以 `.go` 结尾

**回归测试**：`TestCommitRejectsPathTraversal` 覆盖 9 种非法名，并断言
「目标目录之外不得出现任何文件」。

### 3.2 【已量化风险】Parser 无嵌套深度限制

实测（`<Column>` 逐层嵌套）：

| 深度 | 源码大小 | 结果 |
|---:|---:|---|
| 100 | 1.7 KB | 0.01 s，正常 |
| 1,000 | 17 KB | 正常 |
| 5,000 | 85 KB | 0.23 s，正常 |
| 20,000 | 340 KB | 3.26 s，无 panic |
| 100,000 | 1.7 MB | **超过 20 秒未返回** |

**判断**：复杂度超线性（深度 ×4 → 时间 ×6.5），构成资源耗尽向量。

**未修复**，原因：修复需要引入显式深度上限，而该上限是**语义决策**（多少层算合理），
应由规范定义，不能由实现随手拍一个数字。

**建议**：在语言规范中定义最大嵌套深度（例如 256），Parser 超限报新诊断码。
在此之前，`.gxml` 输入应视为可信——这与当前「`.gxml` 来自本仓库」的用法一致。

### 3.3 【已量化风险】`<Def>` 组合可指数膨胀

实测（每层 Def 调用下一层两次，形成 2^n 节点）：

| 层数 | 源码大小 | 展开耗时 |
|---:|---:|---:|
| 8 | 490 B | 0.5 ms |
| 12 | 690 B | 5.6 ms |
| 16 | 894 B | 68 ms |
| 20 | 1,098 B | **1.11 s** |

源码仅增加 204 字节，耗时增加约 1000 倍。**确认指数级**。

已有的防护：`GXML-DEF-010` 检测**直接或间接自引用递归**。但本用例不构成递归
（`L20 → L19 → ... → L0` 是有向无环的），因此不被现有检测拦截。

**未修复**。修复方向有两个，需先定策略：

1. 限制展开后的**节点总数**（实现简单，但阈值是语义决策）；
2. 限制 Def 调用的**嵌套深度**（同上）。

**建议**：与 §3.2 一并在规范中定义资源上限。当前 `.gxml` 由本仓库编写，
不构成实际威胁；但若将来支持第三方模板，必须在此之前修复。

### 3.4 Analyzer / VerifiedDoc：未发现绕过路径

| 检查 | 结论 |
|---|---|
| `VerifiedDoc` 能否在包外构造 | ❌ 不能：字段全未导出，只能由 `Result.Verified()` 构造（反射测试锁定） |
| 能否伪造 `StatusOK` | 不能：`Verified()` 同时要求无诊断、`Doc` 与 `Facts` 非 nil |
| 旁表是否可被外部改写 | 不能：`NodeFacts` 只提供返回副本的访问器 |
| 签发后能否继续写 Facts | 不能：冻结后 `set` 会 panic |
| Codegen 能否绕过凭证 | 不能：入口签名为 `*analyzer.VerifiedDoc` |

已由 `TestVerifiedDocHasNoExportedFields`、`TestVerified()` 系列、
`TestNodeFacts*ReturnsCopy`、`TestFactsSetPanicsAfterFreeze` 覆盖。

**残余风险**：`Facts` 是包内构造的，若 Analyzer 自身逻辑错误导致「验证通过但事实错误」，
类型系统无法拦截。这属于正确性而非安全性问题，由 Analyzer 的测试覆盖。

### 3.5 Codegen 字符串处理：未发现注入

实测 6 类输入（双引号、换行、反斜杠、尝试闭合调用的 `"); panic("pwned`、
Unicode/emoji、制表符），全部生成成功且可通过 `go/parser` 解析。

**机制**：文本值经 `%q`（Go 字符串字面量转义）后写入源码，再经 `format.Source`
二次校验。`%q` 会转义引号、反斜杠、控制字符与不可打印字符。

**残余风险**：

| 位置 | 现状 | 说明 |
|---|---|---|
| 文本字面量 | ✅ 安全 | `%q` + `format.Source` |
| `PackageName` | ✅ 校验 | `isGoIdent` |
| 符号名 | ✅ 校验 | `viewSymbol` 生成后过 `isGoIdent` |
| import 路径 | ⚠️ 半安全 | 当前来自代码常量，不是用户输入；若将来接受用户组件，需校验 |
| 布局属性（未实现） | ⚠️ 待查 | 引入 `Width`/`Gap` 等数值时需确认不拼接原始文本 |

**扩展准入条件**见 §5。

### 3.6 运行时入口生命周期：未发现缺陷

| 探针 | 结果 |
|---|---|
| 正常启动 → close(stop) → 退出 | ✅ 0.22 s 内退出 |
| `stop` 在启动前已关闭 | ✅ 正确返回，无死锁 |
| 重复创建/关闭 3 次 | ✅ 无泄漏、无 panic |

**已知实现细节**：`RunWindow` 必须由独立 goroutine 触发 `Perform(ActionClose)`
才能让阻塞的 `Event()` 返回（初版缺陷，已修复并有测试锁定）。

**残余风险**：`Run`/`RunWith` 调用 `app.Main()` 后永不返回，属 Gio 设计约束。
生产代码若在 goroutine 中调用 `Run`，平台行为未定义——已在契约 §4 写明。

### 3.7 依赖与构建边界

| 项 | 结论 |
|---|---|
| 依赖来源 | 仅 `gioui.org` 与其传递依赖，均可由 `go.sum` 验证 |
| 是否联网 | 构建期不需要（`GOPROXY=off` 可编译，已验证） |
| 是否执行外部命令 | Codegen 与 Pipeline 均不执行；`go build` 只出现在测试中 |
| 生成代码的依赖 | **当前实现**只 import `gioui.org/*`（`layout`、`material`）。依赖方向受 `AGENT.md` 架构红线约束：允许 `生成代码 → pkg/runtime/* → pkg/platform/* → contracts`；**禁止逆向**（`pkg/runtime` / `pkg/platform` 不得反向依赖 `internal/compiler`）。当前未依赖任何项目包，是现状而非契约禁令 |

**无 `reflect` 导入**（契约 §13 第 15 条），已由 Codegen 的固定 import 集合保证。

## 5. Codegen 扩展准入清单

在扩展 `<Column>`、布局属性、绑定、事件、`<For>` 之前，必须完成：

| # | 检查项 | 验收证据 |
|---|---|---|
| 1 | 数值属性不以原始文本拼接 | 生成 `Width`/`Gap` 时用 `unit.Dp(...)` 且值为解析后的 float，不是字符串 |
| 2 | 绑定路径逐段经 `isGoIdent` 校验 | 恶意标识符（含 `.`、`;`、空白）无法进入生成源码 |
| 3 | 事件方法名与实参经校验 | 同上 |
| 4 | import 路径来自受控来源 | 若接受用户组件，需白名单或路径校验 |
| 5 | 新增生成的每个字面量都有注入测试 | 至少覆盖引号、换行、反斜杠、`");` |
| 6 | `format.Source` 失败必须报错而非降级 | 已有 `Generate` 的行为，扩展后不得放宽 |

**第 1、2 项是重点**：它们是「静态文本」之外第一次引入**非字面量**源码片段。
