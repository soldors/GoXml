# 字体与文本渲染策略

- 状态：设计冻结，实现验证待完成
- 冻结日期：2026-10-18
- 关联需求：REQ-001、REQ-002
- 关联 ADR：ADR-0002、ADR-0006
- 适用范围：Parser、Codegen、Runtime、`pkg/runtime/theme`、`pkg/widgets`、发布产物

## 0. 本文件为何存在

此前全部规范文档（GXML、AOT Diff、Codegen、线程模型、平台矩阵）**均未涉及字体与输入法**。这不是小型遗漏，而是会导致「中文应用交付即失败」的空白。

### 实测证据

使用 Gio v0.10.3 自带的 `font/gofont/goregular` 解析字形：

```text
U+0041 'A'  -> glyphIndex=36   （存在）
U+4E2D '中' -> glyphIndex=0    （缺失）
U+6587 '文' -> glyphIndex=0    （缺失）
U+754C '界' -> glyphIndex=0    （缺失）
U+9762 '面' -> glyphIndex=0    （缺失）
U+FF0C '，' -> glyphIndex=0    （缺失）
U+3002 '。' -> glyphIndex=0    （缺失）
```

`glyphIndex == 0` 表示字体不含该字形。Gio 的默认字体集合只覆盖 Latin / Greek / Cyrillic。**任何包含中文的界面在不额外配置字体时会渲染为空白或错误符号**，且不报错、不警告——属于静默失败。

Goxml 定位为中文开发者使用的 Go 桌面框架，必须把字体作为一等设计项，而不是留给用户自行摸索。

## 1. 目标与不变量

1. 中文、日文、韩文界面在**默认配置**下即可正确渲染，无需用户额外代码。
2. 字体加载失败必须产生明确诊断，不得静默降级到空白渲染。
3. 字体嵌入不得破坏 `AGENT.md` 的常驻内存与二进制体积预算。
4. 文本 shaping 结果必须可被缓存复用（与 `性能预算与优化策略.md` INV-PERF-4 一致）。
5. 输入法（IME）输入必须可用，且候选框位置跟随光标。
6. 跨平台行为差异只允许存在于 `pkg/platform` 与 `pkg/runtime/theme`，不得泄漏到生成代码。

## 2. 字体来源策略

### 2.1 三种来源

| 来源 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| **嵌入（`//go:embed`）** | 字体随二进制分发 | 行为确定、零系统依赖 | 增大产物体积 |
| **系统加载** | 运行时从 OS 字体目录读取 | 体积小、观感原生 | 各平台路径/格式不同，可能缺字 |
| **用户显式注册** | 应用自行提供字体文件 | 完全可控 | 需要用户干预 |

### 2.2 v1 决策

**采用「系统字体优先 + 嵌入式兜底」的双轨策略：**

1. **首选系统字体**：按平台探测常见 CJK 字体，命中即使用。
2. **兜底嵌入子集**：内置一份 CJK 子集字体，仅在系统探测全部失败时启用。
3. **统一 fallback 链**：由 `pkg/runtime/theme` 提供，按字形覆盖自动切换，生成代码不感知。

> 取舍说明：纯嵌入会让所有用户都背上数 MB 体积（包括纯英文应用）；纯系统字体在精简版系统或容器环境会失败。双轨是唯一同时满足「体积」与「确定性」的方案。

### 2.3 各平台探测顺序

**Windows**

```text
C:\Windows\Fonts\msyh.ttc      （微软雅黑）
C:\Windows\Fonts\msyhbd.ttc
C:\Windows\Fonts\simsun.ttc    （宋体）
C:\Windows\Fonts\simhei.ttf    （黑体）
```

**macOS**

```text
/System/Library/Fonts/PingFang.ttc
/System/Library/Fonts/STHeiti Light.ttc
/System/Library/Fonts/Hiragino Sans GB.ttc
```

**Linux**

```text
/usr/share/fonts/opentype/noto/NotoSansCJK-Regular.ttc
/usr/share/fonts/truetype/wqy/wqy-microhei.ttc
/usr/share/fonts/truetype/arphic/uming.ttc
$(fc-match -f '%{file}' 'sans-serif:lang=zh')   （仅诊断用，不依赖外部命令做实现）
```

规则：

- 探测必须**快速且有超时**，不得因文件系统缓慢阻塞启动。
- 探测结果必须可观测（诊断日志或 `Capabilities` 字段），便于用户排查。
- 文件存在但解析失败时继续尝试下一个候选，并记录原因。
- 不得通过执行 `fc-match` 等外部命令作为**实现路径**（与平台矩阵「不伪装平台实现」一致），仅可作为诊断信息。

## 3. 字体嵌入与体积预算

### 3.1 子集化要求

若使用嵌入兜底，**必须做子集化**，不得整包嵌入：

| 项目 | 要求 |
|---|---|
| 字符集 | GB2312 一级/二级常用字（约 6,763 字）或按项目实际用字裁剪 |
| 格式 | 优先 WOFF2 或 TTF 子集 |
| 体积目标 | **≤ 3 MB** |
| 生成时机 | 构建期工具，不在运行时做子集化 |

### 3.2 对全局预算的影响

`AGENT.md` 声明常驻内存 15–30MB。字体数据属于**只读映射**，不计入堆内存，但计入二进制体积与 RSS。必须遵守：

| 指标 | 预算 |
|---|---|
| 嵌入字体对二进制的增量 | ≤ 3 MB |
| 运行时字体对象常驻内存 | ≤ 5 MB |
| 字体加载耗时（冷启动内） | ≤ 20 ms（懒加载时应 ≤ 首帧 budget） |

### 3.3 懒加载

字体**不得**在 `main` 或包 `init` 中同步加载，必须：

- 在首次需要文本 shaping 时加载，或
- 在 UI 线程启动后异步加载并先以占位渲染，加载完成后 `Invalidate`。

## 4. 输入法（IME）

### 4.1 v1 要求

| 项目 | 要求 |
|---|---|
| 中文输入 | 必须可用（拼音/五笔等系统 IME） |
| 候选框定位 | 必须跟随光标位置 |
| 组合文本（composition） | 必须正确显示下划线组合态 |
| 取消/确认 | Esc 取消、Enter 确认行为正确 |
| 非 IME 输入 | 不得因 IME 支持引入额外延迟 |

### 4.2 平台风险

Windows 上 Gio 的 IME 支持历史上有边界问题（候选窗位置、组合文本事件时序）。因此：

- **必须在 v1 验收中显式测试中文输入**，不得假设其可用。
- 若某平台 IME 存在已知缺陷，必须在 `平台与平台依赖矩阵.md` 的能力矩阵中标注，并给出用户可见的降级说明，而不是静默失败。

### 4.3 与 `<Input>` 的关系

`<Input>` 的输入处理属于交互控件，受 `AOT状态Diff语义.md` §6.2 约束：**不得把事件处理与绘制整体缓存为永久宏**，否则 IME 事件将无法被消费。

## 5. 文本 shaping 缓存

### 5.1 规则

1. `text.Shaper` 必须全局复用单例，不得每帧创建。
2. 缓存键至少包含：字符串内容、字体族、字号、字重、语言与文本方向。
3. 绑定值未变化时**不得重建字符串**（见 `性能预算与优化策略.md` INV-PERF-4）。
4. 由多字段拼装的显示文本，必须在 ViewModel 侧提供已缓存的 `string` 字段，或在框架侧提供 `Text.Format` 节点并在其内部缓存。

### 5.2 实测依据

| 场景 | ns/op | allocs/op | B/op |
|---|---:|---:|---:|
| 每帧同一字符串 | 876 | 0 | 0 |
| 每帧 `fmt.Sprintf` 短串 | 1,079 | 1 | 16 |
| 每帧变化的长串 | 82,053 | 270 | 137,461 |

## 6. 对 GXML 与 Codegen 的影响

### 6.1 GXML 层

v1 **不新增**字体相关语法（保持语义冻结）。字体通过主题配置：

```go
// pkg/runtime/theme
type Theme struct {
    // ...
    Fonts FontConfig
}

type FontConfig struct {
    Family  string   // 逻辑字体族名
    CJKFallback []string // 可选：自定义 fallback 顺序
}
```

该类型是**运行时**的便利层，供使用者配置字体策略；它不是生成代码可见的类型
（理由见 §6.2 与 `代码生成输出契约.md` §4.3.2）。

### 6.2 Codegen 层（ADR-0012 决策 1：路线 B，本节已修订）

- 生成代码**不得**包含字体路径、字号常量或 collection 构建逻辑。
- 生成代码**不引用任何字体字段**。字体选择（探测、fallback 链、懒加载）由
  `pkg/runtime/theme` 在**运行时主题构建过程**中完成，结果体现为已配置好
  `text.Shaper` 的 `*material.Theme`，由 `pkg/runtime/app` 交给视图。
- 文本节点的 shaping 结果由框架缓存，生成代码不直接操作 `text.Shaper`。

#### 6.2.1 为什么删除「生成代码必须引用主题的字体字段」

本节原文要求生成代码通过主题引用字体字段，与 `代码生成输出契约.md` §4.3.1/§4.3.2
**不可能同时成立**：那里把 `Layout` 的主题参数固定为 Gio 的 `*material.Theme`
（该类型没有字体配置字段），理由之一是「项目主题会演进，不应反向改变已生成
代码的签名」。§4.3.1 当年只登记了冲突，没有裁决，于是两份冻结文档长期各说各话。

裁决结果（ADR-0012 决策 1）取后者。被删除的旧要求原文见 ADR-0012 与本文件 §9.1
变更记录；规范正文不再复述该写法，以免被误读为现行要求。

| 方案 | 代价 |
|---|---|
| A：把主题参数换成项目 `Theme`，生成代码引用其字体字段 | 需改契约 §4.3.1/§4.3.2、改 Codegen、并让全部已生成代码与相关测试迁移签名；字体平台细节泄漏到每一页生成代码 |
| **B（本决策）：保留 `*material.Theme`，字体在运行时解析** | 需修订本节（即本次修订）；生成代码一行不改 |

路线 B 不是「少改几行代码」的权宜：**当前生成代码并不依赖任何自定义 Theme 字段**，
字体探测也不应迫使所有页面的签名迁移。§6.2 原来的**禁令**（不得出现字体路径、
字号常量、`text.Shaper` 构建）在 B 下同样成立，而且更强——生成代码不引用任何
字体字段。

一致性由门禁 `TestThemeRouteBDocumentationConsistent`（`internal/docgate/theme_seam_test.go`）
锁住：本节任何一处恢复生成代码侧的字体引用，或输出契约改动主题参数类型，都会红灯。

### 6.3 契约层

`contracts/` 需要扩展主题相关契约（当前 `ThemeProvider` 仅有 `GetColor`）。建议增加：

```go
type FontProvider interface {
    // Resolve 返回逻辑字体族的实际字体集合标识
    Resolve(family string) (string, error)
}
```

该变更必须走 `contracts/` 并跑 `make contract-lint`（见 `AGENT.md` §6.3）。

**状态（2026-10-20）**：`FontProvider` 已随 ADR-0012 冻结进
`contracts/runtime_api.go`，包含职责边界、`ErrFontNotFound` 错误语义与调用时机
（主题构建期或首次 shaping 时，不得每帧调用，不得阻塞首帧）。
它当前**没有调用方**，接线条件是 `TASK-FONT-001-A`。
`ThemeProvider` 同样是未接线接口（保留原因与替换规则写在 `contracts/runtime_api.go`
的注释里）：两者分管**颜色**与**字体**，不是同一抽象的两种实现。

## 7. 验收要求

1. 中文界面在 Windows / macOS / Ubuntu 默认环境下正确渲染，无空白或豆腐块。
2. 系统无 CJK 字体时，嵌入兜底生效并给出诊断。
3. 字体文件损坏/缺失时产生明确错误，不静默渲染空白。
4. 中文 IME 输入可用，候选框跟随光标，组合文本显示正确。
5. 中英混排与 emoji fallback 正确。
6. 稳定帧文本节点 `allocs/op == 0`。
7. 字体加载不阻塞首帧，不破坏冷启动 ≤ 50ms 目标。
8. 嵌入字体增量 ≤ 3MB。

## 9. 版本演进边界

以下变更必须更新本文件并通过新的 ADR：

- 改变字体来源策略（系统优先 / 嵌入优先）；
- 改变子集字符集或体积预算；
- 引入运行时字体下载；
- 改变 IME 支持范围；
- **改变「字体由运行时解析」这条边界**（例如改回「生成代码引用字体字段」的路线 A）。
