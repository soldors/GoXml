## 2. D-ACCEPT-07 `ProbeElapsed`/`LoadElapsed` 指标语义（本轮实证，注入时钟确定性）

证据：`probe_elapsed_cache_semantics_test.go`（`TestAccept07*` 全 PASS），确定性虚拟时钟、不依赖真实计时与本机字体。

| 场景 | 实测（虚拟时钟步长 14ms） | 语义 |
|---|---|---|
| **冷加载（未命中）** | `Elapsed=14ms, ProbeRan=true`；`Now() 调用 3 次` | 本轮真探测，`ProbeElapsed` 记录本轮的 `probe.Elapsed` |
| **缓存命中** | `ProbeRan=false`；`第二阶段 Now() 调用=0` ⇒ 命中**没有**跑 probe；`LoadReport.ProbeElapsed==0` | 命中本轮**无探测** ⇒ `ProbeElapsed` 恰 0（不沿用历史） |
| **复用（第 2 个 Lazy 同 Provider）** | `Lazy#1 ProbeElapsed=14ms(ProbeRan=true)` → `Lazy#2 ProbeElapsed=0(ProbeRan=false)`；`Scans=1`（不重扫）、`Read=1`（不重读） | 复用命中：`ProbeElapsed=0`，历史 `Probe.Elapsed=14ms` **保留**（契约要求） |
| **失败** | 步长 ×10 ⇒ `Elapsed 10.0x`；失败不缓存、重试重扫 | `ProbeElapsed` 只反映本轮；`LoadElapsed` 为后台墙钟总量 |
| **零候选早退** | `Scanned=0, ProbeRan=true, Elapsed=7ms` | 探测跑了（`ProbeRan=true`）但工作量为 0 |

**关键口径（避免混写）**：`ProbeReport.Elapsed`＝**历史值可保留**；`LoadReport.ProbeElapsed`＝**仅本轮**，由 `Probe.ProbeRan` 门控，命中为**精确 0**；"有没有探测"看 `Probe.ProbeRan`，**不看**是否 0。缓存读取耗时不计入 `ProbeElapsed`（命中 `Now()` 调用为 0）。

## 3. 本轮新发现的真实缺陷（B2/B3）

**Provider.loadEmbedded 并发竞争**（`-race` 实证）：临时主题由**每个 Lazy 各自**构造，多个 Lazy **共享同一 Provider** 时并发进入 `newTempTheme → Provider.loadEmbedded → Embedded.Load()`；`loadEmbedded` 无 Provider 级同步 ⇒ 调用方注入的（可能非并发安全的）`EmbeddedFontLoader` 会被并发调用，`-race` 报 DATA RACE（`TestNight07ConcurrentWarmLaziesNoRescan` 命中）。

- **修复（合同内最小）**：`Provider` 增加 `embMu sync.Mutex`，串行化同一 Provider 的 `loadEmbedded`；不改变调用次数语义、不改变诊断/失败语义。同一加载器若跨多个 Provider 共享，调用方仍须自行同步，不能从本修复外推。
- **验证**：协调者 theme 全包 `-race -count=3` 通过；守卫 `TestLoadEmbeddedConcurrentSharedProviderIsSerialized`（32 并发）非 race 下功能一致、race 下无告警；可编译变异（去 `embMu`）⇒ 守卫 `DATA RACE/FAIL`，恢复 PASS。
