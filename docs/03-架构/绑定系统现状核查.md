## 核查 1：`BindingVal`

**位置**：`contracts/ir_schema.go`（`type BindingVal struct`）

### 定义

```go
type BindingVal struct {
    IsBinding bool     // true = 绑定路径；false = 静态字面量
    IsNegated bool     // 路径带 ! 前缀（仅布尔绑定允许）
    Raw       string   // 原始文本，用于诊断回显
    Segments  []string // 按 "." 切分后的路径分段
}
```

方法：

| 方法 | 行为 |
|---|---|
| `Path()` | 用 `.` 连接 Segments；静态值返回 `Raw` |
| `IsZero()` | `!IsBinding && Raw == "" && len(Segments) == 0` |

### 四态判定

| 能力 | 状态 |
|---|---|
| 静态/绑定二值区分 | ✅ **已实现** |
| 路径分段（构造期完成，不在运行时切分） | ✅ **已实现** |
| 取反标记 | ✅ **已实现** |
| 原始文本保留（诊断回显） | ✅ **已实现** |
| **携带类型信息** | ✅ **已实现（Facts 旁表）**——`BindingVal` 保留原始绑定，Analyzer 将路径、根类型和目标类型写入 `Facts`；类型不泄漏到 `contracts`，由 Codegen 消费已验证事实 |

### 谁负责构造

`parser` 包（`internal/compiler/parser/attrs.go` 等）。Parser 只做**语法切分**，不做类型解析。

## 核查 2：`Facts` / Analyzer 事实模型

**位置**：`internal/compiler/analyzer/ir.go`

### 结构

```go
type NodeFacts struct {
    attrs  []ResolvedAttr
    events []ResolvedEvent
    forCl  *ResolvedFor
}

type ResolvedAttr struct {
    Name   string
    Target contracts.PropType
    Path   *ResolvedPath
    Span   contracts.SourceSpan

type ResolvedPath struct {
    Root     string      // ForVar 时为变量名
    RootKind RootKind    // RootViewModel / RootForVar

    Type     TypeInfo    // 整条路径解析后的类型

    Type TypeInfo
}
```

### 四态判定（对应你的核查项 2）

| 信息 | 状态 | 证据 |
|---|---|---|
| 绑定路径 | ✅ **已实现** | `ResolvedAttr.Path` |
| 属性目标类型 | ✅ **已实现** | `ResolvedAttr.Target`（来自 Schema） |
| 表达式最终类型 | ✅ **已实现** | `ResolvedPath.Type`、`PathStep.Type` |
| 可访问性 | ✅ **已实现** | 未导出字段报 `BIND-003`，不产出 `ResolvedPath` |

## 核查 4：Codegen — 是否消费 `Facts`、是否有绑定分支

**关键发现**：`internal/compiler/codegen/codegen.go` 中**唯一**出现 `IsBinding` 的地方是：

```go
func staticAttr(n *contracts.NodeIR, name string) (string, bool) {
    for _, a := range n.Attrs {
        if a.Name != name { continue }
        if a.Value.IsBinding {
            return "", false        // ← 绑定一律拒绝
        }
        return a.Value.Raw, true
    }
    return "", false
}
```

### 四态判定

| 能力 | 状态 |
|---|---|
| 消费 `Facts` | ✅ **已接通（最小切片）**——`Generate` 从 `VerifiedDoc.Facts()` 读取节点属性事实；查不到事实时失败，不回退为字面量 |
| 绑定代码生成分支 | ⚠️ **部分接通（仅 `<Text Value>` 字段路径）**——直接调用 `Generate` 可生成字段读取表达式；其它控件和绑定属性未支持 |
| 使用 `ResolvedPath` | ✅ **部分接通**——Facts 用 `PathStep.IsMethod` 区分字段与方法；Codegen 生成字段选择器或零参方法调用，定向运行时路径测试通过 |
| 生成缓存（静态子树） | ✅ 已实现（A4） |
| 生成 `<Column>` / `<Row>` | ✅ 已实现（B1） |

**集成限制**：`pipeline.go` 构造 `codegen.Options` 时尚未填充 `ModulePath`。因此跨包 ViewModel 的绑定虽可在直接调用 `Generate` 并显式提供模块路径时生成，但默认 Pipeline 目前无法完成该路径。2026-10-19 定向运行时路径测试已覆盖多段字段、指针字段和零参方法；绑定缓存、自动刷新和事件仍没有实现。

## 核查 6：性能约束清单（不可违反）

| 约束 | 内容 |
|---|---|
| `INV-PERF-1` | 静态子树（无绑定/事件/条件/循环）必须 `op.Record` + `op.CallOp` 固化，稳定帧只回放 |
| `INV-PERF-4` | `<Text>` 绑定值未变化时**不得重建字符串、不得重新 shaping**；拼装文本必须在 ViewModel 侧或框架侧缓存，**禁止 Layout 内每帧 `fmt.Sprintf`**；稳定帧文本节点 `allocs/op == 0` |
| 契约 §16 | 静态缓存的所有权、失效、嵌套边界；`renderKey` 四项 |
| ADR-0001 | 零反射、静态子树固化、列表虚拟化 |

### 一个必须澄清的点

`INV-PERF-4` 的「不得重新 shaping」约束**当前无法验证**。绑定读取表达式已经接通，
但绑定值缓存、显示值复用和 shaping 计数尚未实现；A1–A6 的静态树测试不覆盖这些行为。
