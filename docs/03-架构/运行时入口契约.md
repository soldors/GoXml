# 运行时入口契约（`pkg/runtime/app`）

- 状态：冻结
- 冻结日期：2026-10-19
- 适用范围：把生成视图接入 Gio 主循环的最小运行入口
- 关联：`代码生成输出契约.md` §4.3（统一 `Layout(gtx, th)`；绑定页面由构造函数持有 ViewModel）

## 2026-11-09 批准增量（Windows 基础范围限定验收通过）

旧 Run/RunWindow 等库入口不隐式终止调用者进程，Windows Gio Main 不返回的边界不变。两条事件循环应交出 DestroyEvent.Err，正常关闭为 nil；与严格字体原因同时存在时 errors.Join，两条原因均可判别。

新增显式 `RunSingleWindowProcess(view, cfg, opts)`，只供拥有整个进程的单窗 main 调用；回调和清理完成后调用 Observer，再按正常 0/错误 1 终止整个进程。公开 ProcessOptions 仅 Theme/Lazy/Observer；Theme 与 Lazy 互斥，两者皆空用默认同步来源。公开结果包括 Code、Err、DestroyErr、FontErr、CallbackDone、CleanupDone；事件/错误/退出注入和步骤为包内自检，不是公共合同。多窗口/跨平台退出不由该范围保证。

具体 API 与调用边界见 [单窗入口说明](../../pkg/runtime/app/README.process.md)，验收层级见 [R27 范围与组合验收](../05-开发/2026-11-09-R27-基础范围与组合验收.md)。本增量已通过无窗口及本机原生限定验收；自动严格失败场景未做人工视觉，未证边界不升级。BUG-028 保留旧入口/跨平台/多窗口范围，下面旧冻结正文按原范围理解。

## 1. 职责

只做三件事：

1. 创建窗口并设置标题、初始尺寸；
2. 驱动 Gio 事件循环，把事件转成布局调用；
3. 处理关闭事件后正常退出。

**不做**：路由、生命周期、主题构建、状态序列化、热重载。那些属于 `pkg/runtime/router`、`lifecycle`、`theme`、`hydration`。

## 2. API

```go
// Package app 提供把生成视图接入 Gio 主循环的最小入口。
package app

// View 是可被渲染的页面。
//
// 生成代码为每个 .gxml 产生一个实现该接口的类型：
//
//	func (v *GoxmlDashboardView) Layout(gtx layout.Context, th *material.Theme) layout.Dimensions
type View interface {
	Layout(gtx layout.Context, th *material.Theme) layout.Dimensions
}

// Config 是窗口配置。
type Config struct {
	// Title 是窗口标题，为空时使用默认值。
	Title string
	// Width / Height 是初始逻辑尺寸（dp），为 0 时使用默认值。
	Width, Height unit.Dp
}

// Run 启动主循环，直到窗口关闭。
//
// 内部会创建主题（material.NewTheme）并传给 View.Layout。
//
// 注意：本函数会阻塞，且必须调用 Gio 的 app.Main()——该函数要求运行在
// 主系统线程。从 goroutine 中调用 Run 会导致平台行为未定义。
func Run(view View, cfg Config) error

// RunWith 与 Run 相同，但允许注入主题，便于测试与主题复用。
//
// 一行式形态：内部 NewApp + Run。需要在后台 goroutine 触发重绘时，
// 请改用 NewApp 拿句柄——RunWith 返回时阻塞已结束，句柄无处可取。
func RunWith(view View, theme *material.Theme, cfg Config) error

// Invalidator 是状态变化后请求重新布局的入口（状态更新契约 §2）。
//
// 只请求重绘，不修改状态、不感知 ViewModel；
// 不承诺每次调用对应一个独立帧（Gio 可合并连续失效）。
type Invalidator interface {
	Invalidate()
}

// App 是生产形态的运行入口：先持有句柄，后阻塞驱动（ADR-0010）。
//
// 典型形态：
//
//	a, err := app.NewApp(view, th, cfg)
//	go func() {  // 后台工作线程
//	    vm.Set(...)          // 状态同步由调用方负责
//	    a.Invalidate()
//	}()
//	a.Run()                  // 主线程阻塞
//
// ⚠️ Invalidate 并发安全 ≠ ViewModel 字段读写并发安全。
func NewApp(view View, th *material.Theme, cfg Config) (*App, error)

// Run 阻塞驱动主循环；必须在主系统线程调用。
func (a *App) Run() error

// Invalidate 请求窗口产生下一帧；并发安全，任意 goroutine 可调。
//
// 实测语义（S3）：事件循环启动前调用安全——Gio mayInvalidate 零值
// false，driver 未创建时静默跳过，不 panic。
func (a *App) Invalidate()

// RunWindow 与 RunWith 相同，但**不调用 app.Main()**，只驱动事件循环。
//
// 存在的唯一理由：让测试进程能够可控退出。生产代码应使用 Run/RunWith/NewApp。
func RunWindow(view View, theme *material.Theme, cfg Config, stop <-chan struct{}) error

// RunWindowWithInvalidator 与 RunWindow 相同，另外把失效入口交给调用方
// （集成测试用；inv 为 nil 时等同 RunWindow）。
func RunWindowWithInvalidator(view View, theme *material.Theme, cfg Config,
	stop <-chan struct{}, inv func(Invalidator)) error
```

### 2.4 退出时调用根 View 的显式回调

调用方通过 `app.WithOnDestroy(view, callback)` 获得包装后的根 View。把该
View 直接传入现有窗口入口。包装保持原有 `Layout`，拒绝空 View、空回调和
对已包装根 View 重复注册。窗口配置和现有入口签名保持原样。

`App` 事件循环与 `RunWindowWithInvalidator` 使用的事件循环都在收到 Gio
`DestroyEvent` 时同步调用该回调一次，随后退出。回调在事件循环 goroutine
运行，须尽快返回。启动前的参数校验失败、只有关闭请求而没有销毁事件，以及
未显式包装的 View 均不触发回调。

Router 调用方可传入 `app.WithOnDestroy(r.View(), r.Shutdown)`。
`Shutdown` 可重复调用，与导航提交共享状态锁，取消 Router 和页面 Context，
清理待定工作且不需要下一帧。关闭先于导航结果提交时，该结果计一次丢弃，
当前页和最近错误保留。已经开始执行的回调仍须协作响应 Context 取消。

## 3. 为什么拆出 `RunWindow`

Gio 的 `app.Main()` 会接管主线程并且**没有退出机制**——它只能通过关闭窗口结束。

若 `Run` 只有一种形态，自动化测试就只能：
- 启动子进程后强杀（无法区分「正常运行」与「卡死」）；
- 或干脆不测。

`RunWindow` 接受一个 `stop` channel，收到信号后返回。测试可以：

```go
go app.RunWindow(view, theme, cfg, stop)
// ... 等待若干帧 ...
close(stop)   // 干净退出，可断言没有 panic
```

这样「启动 N 毫秒不崩溃」才是可验证的事实，而不是「进程还活着」。

**生产代码不得使用 `RunWindow`**——它不调用 `app.Main()`，平台窗口可能不显示。

## 4. 主线程约束（实测依据）

Gio v0.10.3 的 `app.Window` 用法是 `w := new(app.Window)`；
**不存在 `app.NewWindow` 导出函数**（只有包内 `newWindow`）。

- `app.Main()` 必须在主系统线程调用（Gio 的 `mainMain` 约束）；
- `w.Event()` 循环通常放在 goroutine 中，通过 `window.Invalidate()` 唤醒重绘。

因此 `Run`/`RunWith` 的结构是：启动事件循环 goroutine → 调用 `app.Main()` 阻塞。
`RunWindow` 则只跑事件循环，不调用 `app.Main()`。

## 5. 验收边界（诚实标注）

自动化测试**只能**验证到：

| 能自动验证 | 不能自动验证 |
|---|---|
| 生成代码编译通过 | 窗口是否真的弹出 |
| `RunWindow` 启动后不 panic、能正常退出 | 文字是否正确渲染 |
| 布局调用被实际执行（通过计数 View） | 布局结果是否符合预期 |

**物理窗口与渲染效果由人工本地确认**，不得在文档中声称已自动验证。
