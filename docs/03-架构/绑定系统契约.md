- 状态：**冻结（语义层）**
- 冻结日期：2026-10-19（提交 `04ae18f` 之后）
- 任务：`TASK-BINDING-CONTRACT-001` 第二阶段
- 依据：[`绑定系统现状核查.md`](绑定系统现状核查.md)

## 0. 本契约的边界

### 0.1 与 `TASK-STATE-001` 的职责划分

| 能力 | 本契约 | `TASK-STATE-001` |
|---|---|---|
| 从 ViewModel 读取当前绑定值 | **定义** | 遵守 |
| 绑定值的类型、安全性、读取失败行为 | **定义** | 遵守 |
| 判断当前值是否与上次缓存值相同 | **定义语义与责任边界** | 可提供实现机制 |
| 值变化后更新显示结果 | **定义可观察行为** | 实现更新流程 |
| 通知 UI 失效、触发重绘 | 不冻结具体接口 | **定义与实现** |
| 是否使用 AOT Diff | **不作决定** | 评估、设计与验证 |
| 多绑定的依赖收集与细粒度失效 | **不默认要求** | 根据性能需求决定 |
| 文本 shaping 的缓存与失效规则 | **定义结果要求与缓存边界** | 配合实现 |

### 0.2 一条关键区别：绑定值比较 ≠ AOT Diff

- **比较单个绑定值是否变化**：可在绑定节点附近完成，是 `INV-PERF-4` 的**直接需求**。
- **AOT Diff**：涉及新旧状态、依赖集合、节点更新与失效范围，是**可选架构方案**。

两者**不绑在一起冻结**。即使 `TASK-STATE-001` 最终不采用 AOT Diff，
本契约仍然成立。

## 01 表达式语法（冻结）

### 01.1 允许的形式

```text
{Path}     取值
{!Path}    取反（仅 bool）
Path := Identifier ("." Identifier)*
```

沿用规范 §4.1/§4.2，**不新增语法**。

### 01.2 路径语义

| 项 | 规则 |
|---|---|
| 分段 | 构造期完成（`BindingVal.Segments`），不在运行时切分 |
| 起点 | ViewModel 字段，或 `<For>` 循环变量（`RootForVar`） |
| 字段访问 | 逐段基于上一段的真实类型 |
| 零参单返回值方法 | 允许，隐式取值（不写 `()`） |
| 指针字段 | 自动解引用 |
| 嵌入字段 | 支持提升访问 |

### 01.3 与外部契约的关系

**不重复定义**类型校验、可访问性、诊断——这些已在
`Analyzer输入输出契约.md` §11 与 `诊断码目录.md` 冻结。本契约只引用。

### 01.4 不冻结

复杂表达式（算术、比较、拼接、三元）按规范 §4.2 **v1 禁止**。
将来若开放，属 v2 语义变更，需新 ADR。

## 02 类型系统（冻结）

### 02.1 唯一类型来源

绑定表达式的类型由 **Analyzer 产出并存入 `Facts`**：

```
ResolvedPath.Type / PathStep.Type : TypeInfo
ResolvedAttr.Target               : contracts.PropType
```

类型兼容与转换规则**唯一依据** `Analyzer输入输出契约.md` §11。

### 02.2 关于 `BindingVal` 是否增加类型字段

**决定：不增加。**

理由：

- `BindingVal` 是 **Parser 产物**，Parser 阶段没有类型信息；
- 类型已由 Analyzer 解析并集中存放在 `Facts` 中；
- 重复存储会造成**第二份事实**，违反单一事实来源原则；
- 消费需求（Codegen 生成读取代码）通过 `Facts` 满足即可。

**若将来实现中出现确凿的 Parser 侧需求，须先修改本条并说明理由，不得默认添加。**

### 02.3 类型传递路径

```text
ViewModel 字段类型
   → Analyzer 逐段解析 → TypeInfo（Kind/Named/Stringer）
   → checkCompat(实际类型, 目标 PropType) → 通过/拒绝（BIND-004）
   → Facts: ResolvedAttr{Path, Target}
   → Codegen 读取（当前未接通，见 04）
```

## 03 状态更新：语义冻结，机制留白

### 03.1 冻结的三层语义

| 层 | 职责 | 约束 |
|---|---|---|
| **绑定读取层** | 从 ViewModel 取得当前值，完成类型与显示值转换 | 不得每帧无条件重建字符串 |
| **绑定缓存层** | 记住上次有效的绑定值或显示结果；值未变化时复用 | 值未变化 → 不重复 shaping |
| **状态更新层** | ViewModel 变化时确保 UI 有机会重新读取 | 具体接口由 `TASK-STATE-001` 定义 |

### 03.2 可观察行为（本契约要求）

1. **值未变化**：连续多帧读取同一值 → 显示结果复用，**不重复整形**。
2. **值发生变化**：缓存正确失效 → 显示更新后的值。
3. **绝不为了零分配而错误复用旧文本**（正确性优先于性能）。
4. **读取失败**：不得留下部分生成结果，缓存不得进入不可恢复状态。

### 03.3 不冻结

- 通知 API 的具体签名
- 是否采用 AOT Diff
- 细粒度依赖收集的实现
- 失效范围的计算方式

### 03.4 当前状态与验证前提

核查确认：**当前不存在状态容器与变更通知**，ViewModel 变化到 UI 无路径。

因此本契约的 03 目前**只能通过可控测试驱动验证读取层与缓存层**，
**不能声称整条运行链路已满足要求**。完整链路验证需待 `TASK-STATE-001`。

## 04 代码生成与运行时读取（部分冻结）

### 04.1 冻结时基线与当前实现状态

本节最初冻结时，`codegen.go` 的 `staticAttr` 对绑定一律拒绝。该代码片段是
冻结时基线，不代表当前实现：

```go
if a.Value.IsBinding {
    return "", false
}
```

截至 2026-10-19，Codegen 已开始消费 `VerifiedDoc.Facts()`：直接调用 `Generate`
可为 `<Text Value="{字段路径}">` 生成 ViewModel 字段读取表达式。该切片有编译测试，
但默认 Pipeline 尚未传递 `Options.ModulePath`，故跨包 ViewModel 尚未从完整管线验收。

Analyzer Facts 已扩展 `ResolvedPath.PathStep.IsMethod`，Codegen 据此为零参方法段生成调用。
2026-10-19 的 `TestBindingRuntimePathKinds` 定向测试中，多段路径、指针访问和零参方法均通过。
这不改变绑定缓存和状态通知尚未实现、完整 Pipeline 尚未接线的状态。

### 04.2 冻结的生成契约

Codegen 应从 `VerifiedDoc` 读取 `Facts`，而非只读 `DocumentIR`：

| 信息 | 用途 |
|---|---|
| `ResolvedAttr.Name` | 属性名 |
| `ResolvedAttr.Target` | 目标 `PropType`，决定转换方式 |
| `ResolvedPath.Steps` | 生成取值表达式链 |
| `ResolvedPath.RootKind` | ViewModel 根 或 `<For>` 变量 |
| `ResolvedPath.Type.Kind` | 决定显示值转换 |

上述内容是生成器应消费的信息，并不表示当前每项都已完成。直接字段与零参方法读取已有
最小实现；`<For>` 变量绑定、其它控件/属性及自动刷新仍需独立实现和验收。

### 04.3 失败处理

- 绑定读取失败 → 报错，不得产出部分结果；
- 不得因读取失败污染缓存。

### 04.4 不冻结

具体生成模板。**未经验证的模板不得写入契约。**

## 05 缓存与性能边界

### 05.1 三层分离（对应你的要求）

| 层 | 内容 | 值未变化时 |
|---|---|---|
| 值读取 | 从 ViewModel 取当前值 | 仍需读取才能知道是否变化 |
| 显示值转换 | 值 → `material.Body1` 所需文本 | **不得重建字符串** |
| 文本 shaping | 生成/复用绘制操作 | **不得重复执行** |

### 05.2 动态节点成为缓存边界

- 含绑定的节点**不是**静态子树，不参与 `INV-PERF-1` 的整体固化；
- 静态父容器**包含**动态子节点时，父容器整体**不固化**（§16.7）；
- 绑定值变化 → 该绑定节点的显示结果与 shaping 缓存失效。

### 05.3 关于 shaping 的可观测性（重要事实）

**Gio 的 shaping 路径无法直接计数。**

核查确认：

- `text.Shaper` 的缓存字段（`layoutCache`/`pathCache`）**全部未导出**；
- shaping 由 `widget.Selectable.Layout` 内部驱动；
- 尝试注入自定义 `Shaper` 观测调用**未成功**（接口类型不匹配）。

因此：

- **不能只依赖 `allocs/op` 推断 shaping 是否被缓存**；
- 契约要求：实现阶段**先设计可替换的测试 seam**；
- 是否为观测引入生产接口，**待实现阶段核查后决定**，本契约不预设。

### 05.4 `INV-PERF-4` 的补充验收维度

现有「稳定帧 `allocs/op == 0`」不足以定位责任。补充：

| # | 场景 | 期望 |
|---|---|---|
| 1 | 绑定值稳定 | 不反复重建显示字符串，不重复整形 |
| 2 | 绑定值变化 | 缓存失效，显示更新（正确性优先） |
| 3 | 原始值变化但显示字符串不变 | 由契约明确是否允许复用 shaping |
| 4 | 字体/约束/主题等影响 shaping 的因素变化 | 不得错误复用旧结果 |
| 5 | 读取失败 | 不留部分结果，缓存可恢复 |

### 05.5 两个必须区分的性能指标

- **稳定帧零分配**：初始化完成后、绑定值不变时，文本路径 `allocs/op == 0`；
- **避免重复 shaping**：需通过**可观察的 shaping 调用计数**或等效证据验证，
  **不能只凭分配数推断**。
